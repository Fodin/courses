# Задание 5.3 — Проектирование пагинации: self-check

## Цель

Закрепить понимание того, когда использовать offset vs cursor-пагинацию, научиться обосновывать выбор исходя из требований продукта.

## Требования

1. Компонент содержит 3 сценария с разными требованиями к пагинации.
2. Каждый сценарий имеет:
   - Описание продукта и контекста
   - Список требований (минимум 4 пункта)
   - Два варианта ответа: «Offset (page/limit)» или «Cursor (after/first)»
   - Кнопку «Проверить» (активна после выбора варианта)
3. После проверки отображается:
   - Если ответ неверный: красный блок с объяснением почему выбранный вариант не подходит
   - Правильный ответ с примером URL запроса
   - Список обоснований (минимум 4 пункта)
   - Пример JSON-ответа
4. Выбранный вариант нельзя изменить после нажатия «Проверить».
5. Карточка раскрывается/скрывается по клику на заголовок.
6. После проверки — зелёная или красная рамка вокруг карточки.

## Чеклист

- [ ] Минимум 3 сценария
- [ ] Для каждого сценария — выбор между offset и cursor
- [ ] Блокировка выбора после проверки
- [ ] Отображение почему неверный вариант плохо подходит
- [ ] Обоснование правильного ответа (минимум 4 причины)
- [ ] Пример URL и пример ответа для правильного варианта
- [ ] Визуальный индикатор правильности (зелёный / красный)

## Как проверить себя

Пройдите все 3 сценария, не подглядывая в теорию. Для каждого сценария:
1. Прочитайте описание и требования.
2. Выберите тип пагинации.
3. Нажмите «Проверить» и прочитайте обоснование.
Цель — правильно ответить на все 3 сценария с первой попытки, опираясь только на требования.
