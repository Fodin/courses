# Задание 14.2: API Review — найди 15 проблем

## Цель

Провести полноценный API Review плохо спроектированного Shop API. Найти все 15 проблем в 9 категориях, понять почему каждая из них является проблемой и изучить правильное решение.

## Требования

1. Прочитать спецификацию «плохого» API внимательно
2. Самостоятельно найти как можно больше проблем до того, как смотреть подсказки
3. Для каждой найденной проблемы — отметить её как найденную (чекбокс)
4. Изучить исправление для каждой проблемы (кнопка «Показать исправление»)
5. Разобрать, почему каждое «исправление» правильнее исходного варианта

## Категории проблем

Найди по одной или нескольким проблемам в каждой категории:

- [ ] **URL Design** — как минимум 3 проблемы (глаголы, регистр, дублирование)
- [ ] **HTTP Methods** — как минимум 2 проблемы (POST для удаления, GET изменяет данные)
- [ ] **Status Codes** — 200 OK на ошибки
- [ ] **Data Model** — непоследовательное именование, неверные типы, неверный формат дат
- [ ] **Pagination** — нет пагинации на списочном endpoint
- [ ] **Search/Filter** — POST для поиска
- [ ] **Versioning** — нет версионирования
- [ ] **Errors** — нет машинного кода ошибки
- [ ] **Rate Limiting** — нет документации

## Как проверить себя

1. Сначала прочитай спецификацию, отметь проблемы которые заметил
2. Сравни количество найденных проблем с общим числом (15)
3. Нажми «Показать исправление» для проблем, которые не нашёл — изучи их
4. Задай себе вопрос: «Как бы я заметил эту проблему на реальном ревью?»
5. Финальная цель: 15/15 найдено + 15/15 изучено

## Подсказки

- Глаголы в URL — самая частая проблема на реальных проектах. Ищи слова типа get, create, update, delete, search, list
- 200 OK на ошибки — особенно коварная: API «работает», но клиентам трудно обрабатывать ошибки
- Обрати внимание на регистр полей в JSON-ответах — есть ли единый стандарт?
- Проверь: можно ли выполнить все необходимые операции через правильные HTTP-методы?
