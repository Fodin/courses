# Уровень 15: Тестирование

## Тесты — это инвестиция в уверенность

Строительная инспекция не строит здание за вас. Она не защищает от всех будущих проблем. Но она проверяет фундамент, несущие стены и проводку — те вещи, которые дорого исправлять потом. Тесты работают так же: не гарантируют отсутствие багов, но дают уверенность при изменении кода.

Главная ценность тестов — не поиск существующих багов, а **защита от будущих регрессий** и **уверенность при рефакторинге**.

---

## Пирамида тестирования

```
        /\
       /  \    E2E
      /----\   (мало, медленно, дорого)
     /      \
    /--------\  Integration
   /          \ (умеренно)
  /------------\
 /              \ Unit
/----------------\ (много, быстро, дёшево)
```

**Unit-тесты** — одна функция или модуль в изоляции, без реальных зависимостей. Выполняются за миллисекунды, их сотни.

**Integration-тесты** — взаимодействие нескольких модулей: сервис + репозиторий + база данных. Медленнее, но тестируют реальные сценарии.

**E2E-тесты** — полный пользовательский сценарий через интерфейс (Playwright, Cypress). Медленно, хрупко, но проверяет систему целиком.

## AAA паттерн

Каждый тест строится по трём фазам:

```typescript
it('should return discounted price for premium users', () => {
  // Arrange — подготовить данные и зависимости
  const user = { id: '1', tier: 'premium' }
  const product = { price: 100, id: 'p1' }

  // Act — выполнить тестируемое действие
  const result = calculatePrice(user, product)

  // Assert — проверить результат
  expect(result).toBe(80) // 20% скидка для premium
})
```

Один тест — одно поведение. Если `Act` требует нескольких вызовов — возможно, тест тестирует слишком много.

## Test doubles: подмена зависимостей

```typescript
// Stub: возвращает фиксированные данные
const userRepoStub = {
  findById: async () => ({ id: '1', name: 'Alice', tier: 'premium' }),
}

// Mock: проверяет, что метод был вызван
const emailServiceMock = {
  sendWelcome: jest.fn(),
}
await registerUser({ email: 'alice@example.com' }, emailServiceMock)
expect(emailServiceMock.sendWelcome).toHaveBeenCalledWith('alice@example.com')

// Spy: обёртка вокруг реального объекта
const spy = jest.spyOn(console, 'log')
doSomething()
expect(spy).toHaveBeenCalled()
spy.mockRestore()

// Fake: упрощённая реализация (in-memory вместо реальной БД)
class InMemoryUserRepository implements UserRepository {
  private users = new Map<string, User>()
  async findById(id: string) { return this.users.get(id) ?? null }
  async save(user: User) { this.users.set(user.id, user); return user }
}
```

💡 Правило: **не мокайте то, чем не владеете**. Мок на внешнюю библиотеку — вы тестируете своё предположение об API, а не реальное поведение.

## Coverage: метрика, но не цель

100% coverage не означает 0 багов:

```typescript
// ✅ Эта функция покрыта на 100%
function divide(a: number, b: number): number {
  return a / b
}

// ❌ Но этот тест ничего не проверяет
it('covers divide', () => {
  divide(4, 2) // вызвали, но не проверили результат
})
```

Coverage — нижняя граница. Цель: **качественные тесты**, которые ловят реальные ошибки.

---

## TDD: Red → Green → Refactor

```
1. Red   — написать тест, который падает (функции ещё нет)
2. Green — написать минимальный код, чтобы тест прошёл
3. Refactor — улучшить код, не ломая тесты
```

TDD полезен для сложной бизнес-логики и проектирования API. Менее полезен для UI и эксплоративного кода.

---

## Итог

- **Unit** — быстро, изолированно, много; **Integration** — реальные сценарии; **E2E** — полный путь пользователя
- **AAA** — Arrange, Act, Assert; один тест — одно поведение
- **Stub** — данные, **Mock** — проверка вызова, **Spy** — обёртка, **Fake** — реализация
- **Не мокайте внешние библиотеки** — тестируете предположение, а не реальность
- **Coverage** — метрика качества, не самоцель; 100% coverage ≠ 0 багов
- **TDD** — тест сначала, код потом; помогает при сложной логике и проектировании интерфейсов
