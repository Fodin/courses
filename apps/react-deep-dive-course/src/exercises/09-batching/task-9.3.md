# Задание 9.3: Batching vs Cascade

## Цель

Сравнить две противоположные стратегии обновления состояния: батчинг (3 setState в одном обработчике = 1 рендер) vs каскад (цепочка useEffect, где каждый триггерит следующий = 3+ рендера). Счётчик рендеров и таймер `performance.now()` докажут разницу производительности.

## Требования

1. Создать компонент `BatchingVsCascade` с двумя панелями рядом
2. **Левая панель "Batching" (1 рендер)**:
   - Три состояния: `step`, `progress`, `status` — начальные значения 0, 0, 'idle'
   - Кнопка "Запустить": в одном обработчике вызывает `setStep(1)`, `setProgress(100)`, `setStatus('done')` — React батчит их в 1 рендер
   - Счётчик рендеров через `useRef`, инкрементируется в теле компонента
   - Таймер: `performance.now()` до и после клика, отображает "Время обновления: X мс"
3. **Правая панель "Cascade" (3+ рендера)**:
   - Те же три состояния
   - Кнопка "Запустить": устанавливает только `setStep(1)`
   - `useEffect` на `step`: при `step === 1` вызывает `setProgress(100)`
   - `useEffect` на `progress`: при `progress === 100` вызывает `setStatus('done')`
   - Каждый useEffect — отдельный рендер, итого 3+ рендеров для той же конечной задачи
   - Счётчик рендеров и таймер аналогично левой панели
4. Кнопка "Сбросить" в обеих панелях: возвращает все состояния к начальным значениям
5. Добавить лог рендеров с временными метками (через `useRef` массив, максимум 10 последних записей) в каждой панели
6. Визуальная индикация финального состояния: прогресс-бар (ширина = `progress%`) и метка статуса

## Чеклист

- [ ] Левая панель: три `setState` в одном обработчике без useEffect-цепочки
- [ ] Правая панель: цепочка `useEffect` — каждый триггерит следующий setState
- [ ] `useRef` для счётчика рендеров в каждой панели, инкрементируется в теле компонента
- [ ] `performance.now()` измеряет время от клика до конца синхронного выполнения
- [ ] Лог рендеров с временными метками показывает 1 запись vs 3 записи
- [ ] Прогресс-бар визуально показывает финальное состояние
- [ ] Кнопка "Сбросить" корректно обнуляет всё состояние и логи
- [ ] Счётчик рендеров чётко показывает разницу: 1 vs 3+

## Как проверить себя

1. Нажмите "Запустить" в левой панели — счётчик рендеров вырастет на 1
2. Нажмите "Запустить" в правой панели — счётчик вырастет на 3
3. Сравните логи: в левом один timestamp, в правом три разных timestamp (разделены миллисекундами)
4. Нажмите "Запустить" быстро 5 раз подряд в обеих панелях — разница в счётчиках будет 5 vs 15+
5. Откройте DevTools → React Profiler → запишите нажатие обеих кнопок: левая = 1 коммит, правая = 3 коммита
6. Подумайте: когда каскад useEffect оправдан? (Подсказка: только когда следующее состояние вычисляется асинхронно или зависит от внешнего события, а не от предыдущего состояния)
