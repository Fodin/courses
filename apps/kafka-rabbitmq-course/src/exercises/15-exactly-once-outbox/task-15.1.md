# Задание 15.1: Проблема двойной записи

## Цель

Реализовать интерактивный визуализатор **Dual Write Problem** — ситуации, когда сервис последовательно делает запись в базу данных и публикует событие в брокер без атомарной гарантии. Нужно наглядно показать, что происходит при сбое брокера после успешной записи в БД.

## Требования

1. Объявить тип `WriteStep` с 8 значениями: `'idle' | 'db-writing' | 'db-success' | 'broker-writing' | 'broker-success' | 'broker-fail' | 'done-ok' | 'done-fail'`.
2. Объявить интерфейс `LogEntry` с полями `id: number`, `text: string`, `type: 'info' | 'success' | 'error' | 'warn'`.
3. Объявить состояния компонента: `step: WriteStep`, `logs: LogEntry[]`, `dbRecords` (массив объектов `{ id: string; status: string }`), `brokerMessages: string[]`, `failMode: boolean`, `logIdRef` через `useRef(0)`.
4. Реализовать вспомогательные функции `addLog(text, type)` и `delay(ms)`.
5. Реализовать функцию `runScenario`:
   - Генерирует уникальный `orderId` через `Date.now().toString().slice(-4)`.
   - Сбрасывает логи, переходит в `'db-writing'`, имитирует задержку 700 мс.
   - После записи в БД (`db-success`) добавляет запись в `dbRecords`, задержка 500 мс.
   - Если `failMode === true`: переходит в `'broker-fail'`, добавляет лог ошибки о рассинхронизации, завершается в `'done-fail'`.
   - Если `failMode === false`: переходит в `'broker-writing'` → `'broker-success'`, добавляет сообщение в `brokerMessages`, завершается в `'done-ok'`.
6. Реализовать функцию `reset`, сбрасывающую все состояния в начальные значения.
7. Объявить словари `logColors`, `logBg` (цвета для каждого типа лога) и `stepColors` (фоновый цвет контейнера в зависимости от текущего шага).
8. Отрисовать схему с двумя узлами (PostgreSQL и Kafka), визуально отражающую статус каждого узла (серый / синий / зелёный / красный) в зависимости от текущего `step`.
9. Добавить чекбокс "Симулировать сбой брокера" и кнопки "Создать заказ" / "Сбросить".
10. Отрисовать две панели с текущим состоянием хранилищ: PostgreSQL (orders) и Kafka (order-events).
11. Отрисовать лог событий в тёмном блоке с цветовым выделением строк по типу.
12. При `step === 'done-fail'` показать блок-предупреждение о проблеме несогласованности и отсылку к заданию 15.2.

## Чеклист

- [ ] Тип `WriteStep` с 8 значениями объявлен
- [ ] Интерфейс `LogEntry` с полями `id`, `text`, `type` объявлен
- [ ] Состояния `step`, `logs`, `dbRecords`, `brokerMessages`, `failMode`, `logIdRef` инициализированы
- [ ] `addLog` добавляет запись с автоинкрементным `id` через `logIdRef`
- [ ] `delay` возвращает промис через `setTimeout`
- [ ] `runScenario` последовательно проходит шаги с задержками
- [ ] При `failMode` функция завершается в `'done-fail'` без записи в `brokerMessages`
- [ ] При успехе функция завершается в `'done-ok'` с записью в оба хранилища
- [ ] `reset` сбрасывает все состояния, включая `dbRecords` и `brokerMessages`
- [ ] Схема визуально отражает текущий `step` (цвет PostgreSQL и Kafka меняется)
- [ ] Кнопка "Создать заказ" заблокирована (`disabled`) во время выполнения
- [ ] Панели PostgreSQL и Kafka показывают реальные данные или плейсхолдер
- [ ] Блок-предупреждение о рассинхронизации появляется только при `step === 'done-fail'`
- [ ] Строки лога выделяются цветом по типу (`success` — зелёный, `error` — красный, `warn` — жёлтый)

## Как проверить себя

1. Откройте задание — схема должна быть в нейтральных серых цветах, обе панели пустые.
2. Нажмите "Создать заказ" без включённого режима ошибки. Наблюдайте: сначала PostgreSQL становится синим (запись), затем зелёным. Затем Kafka — синей, потом зелёной. В обеих панелях появляются данные. Лог содержит `[DB] Запись сохранена успешно` и `[Broker] Событие опубликовано успешно`.
3. Нажмите "Сбросить", включите чекбокс "Симулировать сбой брокера".
4. Снова нажмите "Создать заказ". PostgreSQL зеленеет, но Kafka краснеет — в логе появляется `[Broker] ОШИБКА: Connection timeout!`. В панели PostgreSQL есть запись, в Kafka — нет. Появляется предупреждение о рассинхронизации.
5. Убедитесь, что кнопка "Создать заказ" заблокирована во время выполнения сценария.
