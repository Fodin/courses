# Уровень 10: Безопасность и npm audit

## Что такое npm audit

`npm audit` анализирует `package-lock.json` и сверяет установленные пакеты с базой известных уязвимостей (npm Advisory Database). Результат — отчёт с перечнем уязвимостей, их серьёзностью и путём в дереве зависимостей.

```bash
npm audit
```

## Уровни серьёзности (severity)

| Уровень      | Значение                                                                     |
| ------------ | ---------------------------------------------------------------------------- |
| **critical** | Немедленная угроза: удалённое выполнение кода, полный захват системы         |
| **high**     | Серьёзная уязвимость: утечка данных, эскалация привилегий                    |
| **moderate** | Умеренный риск: DoS, ограниченная утечка информации                          |
| **low**      | Минимальный риск: теоретическая уязвимость с ограниченной эксплуатируемостью |

## npm audit fix

Автоматически устанавливает исправленные версии в рамках semver-совместимости:

```bash
npm audit fix
```

Работает только для «совместимых» обновлений — minor и patch-версий согласно semver-диапазонам в `package.json`.

## npm audit fix --force

Обновляет зависимости даже если это нарушает semver — ставит breaking-версии:

```bash
npm audit fix --force
```

⚠️ Опасно: может обновить пакеты до мажорных версий с изменившимся API. После применения обязательно тестировать приложение.

## Исправление транзитивной уязвимости через overrides

Когда `npm audit fix` не может устранить уязвимость (maintainer прямой зависимости не выпустил обновление):

```json
{
  "overrides": {
    "vulnerable-package": "^2.0.1"
  }
}
```

```bash
npm install
npm audit
# 0 vulnerabilities
```

Это предпочтительнее `npm audit fix --force`.

## Полезные флаги

```bash
# Показать только уязвимости уровня high и выше
npm audit --audit-level=high

# Исключить dev-зависимости из отчёта
npm audit --omit=dev

# Вывести в формате JSON для CI-обработки
npm audit --json

# Проверить подписи пакетов (npm v8.5+)
npm audit signatures
```

## Audit в CI

В CI-пайплайне рекомендуется:

```bash
# Завершить pipeline с ненулевым кодом при critical/high
npm audit --audit-level=high

# Только production-зависимости
npm audit --omit=dev --audit-level=moderate
```

## Ложные срабатывания и контекст

Не все уязвимости критичны для конкретного проекта. Вопросы для оценки:

- Уязвимый код вообще вызывается в вашем приложении?
- Пакет используется только в devDependencies (тест-утилита, CLI-инструмент)?
- Вектор атаки реален в вашей инфраструктуре?

`--omit=dev` помогает сосредоточиться на production-рисках.

## ⚠️ Типичные ошибки

❌ Слепо запускать `npm audit fix --force` в production-ветке  
✅ Сначала попробовать `npm audit fix`, затем точечно использовать overrides

❌ Игнорировать audit-отчёт, потому что «всё равно ничего не сломалось»  
✅ Проверять severity и контекст использования; critical/high — приоритет

❌ Считать, что `npm audit` покрывает 100% уязвимостей  
✅ Дополнять audit другими инструментами (Snyk, socket.dev) для полного покрытия
