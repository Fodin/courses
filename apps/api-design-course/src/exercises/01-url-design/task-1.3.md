# Задание 1.3 — URL-схема блог-платформы

## Цель

Изучить полноценную REST-схему для реального приложения, разобрать паттерны: коллекции, вложенные ресурсы, RPC-исключения, query params для фильтрации.

## Требования

1. Компонент отображает эталонную URL-схему для блог-платформы.
2. Ресурсы сгруппированы (пользователи, посты, комментарии, теги).
3. Группы раскрываются по клику — показывается таблица endpoints.
4. Каждый endpoint: метод, URL, описание, пометка (если есть исключение или альтернатива).
5. В таблице наглядно выделены HTTP-методы цветом.
6. В конце — блок с вопросами для самопроверки (без ответов, для размышления).

## Чеклист

- [ ] Минимум 4 группы ресурсов
- [ ] Минимум 15 endpoints суммарно
- [ ] Присутствует пример RPC-исключения с пояснением
- [ ] Показана разница между вложенным ресурсом и query param фильтром
- [ ] Вопросы для самопроверки есть
- [ ] HTTP-методы выделены визуально

## Как проверить себя

После изучения схемы закройте компонент и попробуйте восстановить по памяти:
- Как получить посты конкретного автора?
- Как добавить комментарий к посту?
- Чем отличается PUT от PATCH для поста?
- Почему `/posts/:id/publish` — допустимый URL?
