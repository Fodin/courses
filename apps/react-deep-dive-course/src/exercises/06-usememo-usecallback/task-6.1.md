# Задание 6.1: useMemo vs useEffect — производный state

## Задание

В компоненте `Task6_1` реализована фильтрация todos через `useState + useEffect`.
Компонент содержит счётчик рендеров, который покажет, что при изменении `todos` или `filter`
происходит **два рендера** вместо одного.

Твоя задача — отрефакторить компонент: убрать `useState + useEffect` и заменить на `useMemo`.

## Цель

Понять, почему `useMemo` для вычисляемых данных всегда лучше, чем `useState + useEffect`.
Увидеть разницу в счётчике рендеров: 2 рендера → 1 рендер.

## Требования

1. Убери `visibleTodosState` и `useEffect`, который его обновлял
2. Вычисляй `visibleTodos` через `useMemo` с deps `[todos, filter]`
3. Счётчик рендеров (`renderCount`) должен показывать **1** при каждом изменении фильтра или добавлении todo (не 2)
4. Поле ввода `newTodo` НЕ должно вызывать пересчёт `visibleTodos` (тест мемоизации)
5. Кнопки: "Добавить todo", переключатель фильтра `all / active / done`
6. Добавь визуальный индикатор: текст "Последний пересчёт: [время]" рядом со списком — он должен обновляться только когда visibleTodos действительно пересчитывается

## Чеклист

- [ ] `visibleTodos` вычисляется через `useMemo`, не через `useState`
- [ ] `useEffect` для синхронизации `visibleTodos` удалён
- [ ] При добавлении todo счётчик рендеров увеличивается на **1**, не на 2
- [ ] При изменении фильтра счётчик рендеров увеличивается на **1**, не на 2
- [ ] При вводе текста в поле `newTodo` индикатор "Последний пересчёт" **не обновляется**
- [ ] Фильтрация работает корректно для всех трёх фильтров

## Как проверить себя

1. Запусти компонент и посмотри на начальное значение счётчика рендеров
2. Переключи фильтр — счётчик должен вырасти на 1 (не на 2)
3. Добавь новое todo — счётчик должен вырасти на 1
4. Напечатай что-то в поле "Новое todo" — текст "Последний пересчёт" не должен меняться
5. Сравни поведение с закомментированной плохой версией (useState + useEffect)
