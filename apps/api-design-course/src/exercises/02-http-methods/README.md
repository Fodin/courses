# HTTP-методы и идемпотентность

## Зачем нужны разные методы?

HTTP — не просто способ передавать данные. Это протокол с семантикой: каждый метод несёт смысл, который понимают серверы, браузеры, прокси и кэши. Использование правильного метода — это способ «говорить» с инфраструктурой на одном языке.

## Семь методов и их роли

| Метод | Роль | Типичный URL |
|---|---|---|
| **GET** | Получить ресурс | `GET /users/42` |
| **POST** | Создать ресурс | `POST /users` |
| **PUT** | Заменить целиком | `PUT /users/42` |
| **PATCH** | Частично обновить | `PATCH /users/42` |
| **DELETE** | Удалить | `DELETE /users/42` |
| **HEAD** | Метаданные без тела | `HEAD /files/report.pdf` |
| **OPTIONS** | Разрешённые методы | `OPTIONS /api/users` |

## Безопасные методы (safe)

**Безопасный метод** не изменяет состояние сервера. Можно вызывать сколько угодно раз — данные не изменятся.

Безопасные: **GET, HEAD, OPTIONS**

```
✅ GET /users          — просто читает, ничего не меняет
✅ HEAD /files/photo   — только заголовки, без тела
❌ GET /users/delete/5 — GET с мутацией — нарушение!
```

## Идемпотентность

**Идемпотентный метод** — повторный вызов с теми же данными даёт тот же результат.

```
PUT /tasks/1 { "title": "Купить молоко" }
PUT /tasks/1 { "title": "Купить молоко" }  ← тот же результат ✅

DELETE /tasks/1
DELETE /tasks/1  ← ресурс уже удалён, но ошибки нет ✅

POST /tasks { "title": "Новая задача" }
POST /tasks { "title": "Новая задача" }  ← создаст ВТОРУЮ задачу ❌
```

Идемпотентные: **GET, PUT, DELETE, HEAD, OPTIONS**
Не идемпотентный: **POST, PATCH** (в общем случае)

## PUT vs PATCH

Это самая частая точка путаницы:

- **PUT** — переклеить наклейку целиком. Отправляете весь объект, сервер заменяет всё.
- **PATCH** — дописать на наклейке. Отправляете только изменившиеся поля.

```
# PUT — заменяем весь объект:
PUT /users/42
{ "name": "Иван", "email": "ivan@new.com", "role": "admin" }

# PATCH — меняем только email:
PATCH /users/42
{ "email": "ivan@new.com" }
```

## HEAD и OPTIONS: зачем они нужны?

**HEAD** — проверить файл без скачивания. Браузер может узнать размер и тип файла до загрузки.

**OPTIONS** — CORS preflight. Перед «опасным» cross-origin запросом браузер автоматически отправляет OPTIONS, чтобы узнать: «разрешает ли сервер этот запрос?»
