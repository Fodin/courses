# Задание 6.3: Выбор стратегии версионирования

## Цель

Реализовать self-check компонент с 4 сценариями. В каждом сценарии студент выбирает стратегию
версионирования и получает объяснение правильного ответа с обоснованием.

## Требования

1. Показать 4 сценария: публичный API, внутренний микросервис, мобильное приложение, SaaS-платформа
2. Для каждого сценария отображать теги с характеристиками
3. Три варианта ответа: URL versioning, Header versioning, Query param versioning
4. После выбора — кнопка "Проверить" (активна только если выбран ответ)
5. После проверки: показать правильный/неправильный ответ с обоснованием
6. Навигация между сценариями (кнопки + прогресс-индикатор)
7. Итоговый счёт при прохождении всех сценариев

## Чеклист

- [ ] Прогресс-бар из 4 сегментов (зелёный = правильно, красный = неправильно, синий = текущий)
- [ ] Теги характеристик сценария (тип API, количество клиентов и т.д.)
- [ ] Три кнопки-варианта, кликабельные до проверки
- [ ] Выбранный вариант выделяется (синяя рамка до проверки)
- [ ] После проверки: правильный ответ — зелёный, неправильный — красный
- [ ] Блок с обоснованием появляется после нажатия "Проверить"
- [ ] Необязательное предупреждение для сложных сценариев
- [ ] Итоговый счёт X/4 после прохождения всех сценариев

## Как проверить себя

Сценарий 1 (Публичный API): правильный ответ — URL versioning
Сценарий 2 (Внутренний микросервис): правильный ответ — Header versioning
Сценарий 3 (Мобильное приложение): правильный ответ — URL versioning
Сценарий 4 (SaaS-платформа): правильный ответ — Header versioning

- Намеренно ответьте неверно — должен появиться красный блок с обоснованием
- После прохождения всех 4 сценариев должен появиться итоговый счёт
