# Задание 10.2: Сравнение алгоритмов Rate Limiting

## Цель

Построить интерактивную визуализацию, демонстрирующую поведение 4 алгоритмов rate limiting (Fixed Window, Sliding Window Counter, Token Bucket, Leaky Bucket) при одинаковом потоке запросов. Увидеть разницу в обработке burst-трафика и edge cases.

## Требования

1. **4 алгоритма параллельно** — каждый в своей колонке/секции:
   - Fixed Window Counter
   - Sliding Window Counter
   - Token Bucket
   - Leaky Bucket

2. **Настраиваемые параметры**:
   - Rate limit (запросов/мин) — default: 10
   - Window size (секунд) — default: 60
   - Burst size (для Token Bucket) — default: 5
   - Количество запросов за один клик — default: 5

3. **Кнопки управления**:
   - "Отправить N запросов" — генерирует пачку запросов одновременно
   - "Сбросить" — очищает все счётчики

4. **Визуализация для каждого алгоритма**:
   - Текущий счётчик / оставшиеся токены
   - Статус: принят / отклонён для каждого запроса (цветом)
   - Итого: принято / отклонено / всего

5. **Таблица сравнения** — итоговая статистика: % пропущенных, burst-поведение, среднее время ответа

## Чеклист

- [ ] Все 4 алгоритма работают одновременно при одном нажатии кнопки
- [ ] Параметры (rate, window, burst) настраиваемые
- [ ] Видна разница в burst-поведении между алгоритмами
- [ ] Fixed Window показывает boundary burst проблему
- [ ] Token Bucket правильно обрабатывает burst до лимита ведра
- [ ] Leaky Bucket показывает стабильный поток без burst
- [ ] Таблица сравнения показывает итоговую статистику
- [ ] UI обновляется в реальном времени

## Как проверить себя

1. Установите rate = 10 req/min и отправьте 15 запросов
2. Проверьте: Token Bucket с burst = 5 пропустит до 15 запросов (10 + 5 burst)
3. Проверьте: Leaky Bucket пропустит не более 10
4. Проверьте: Fixed Window пропустит 10 в текущем окне
5. Отправьте ещё 10 запросов — все алгоритмы должны отклонить большинство
6. Сбросьте и повторите — результаты должны быть воспроизводимы
7. Сравните свою визуализацию с эталонным решением (Solution)
