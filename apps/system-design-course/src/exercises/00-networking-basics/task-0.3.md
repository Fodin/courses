# Задание 0.3: Выбор протокола

## Цель

Научиться выбирать подходящий сетевой протокол для конкретного сценария, учитывая требования к латентности, надёжности, двунаправленности и масштабируемости.

## Требования

1. Для каждого из 5 сценариев выберите наиболее подходящий протокол
2. Обоснуйте свой выбор: почему именно этот протокол, а не альтернативы

### Сценарии

| # | Сценарий | Ключевые требования |
|---|----------|-------------------|
| 1 | Мессенджер (чат) в реальном времени | Мгновенная доставка, push от сервера, тысячи одновременных пользователей |
| 2 | Стриминг видео (YouTube-подобный сервис) | Большой объём данных, допустимы потери кадров, минимальная задержка |
| 3 | REST API для мобильного приложения магазина | CRUD операции, кэширование, совместимость с мобильными клиентами |
| 4 | Сбор данных с IoT-датчиков (температура, влажность) | Тысячи устройств, маленькие пакеты, нестабильная сеть, минимальный overhead |
| 5 | Взаимодействие микросервисов внутри дата-центра | Высокая скорость, строгая типизация, streaming, минимальный latency |

## Чеклист

- [ ] Для каждого сценария выбран протокол (из: HTTP/1.1, HTTP/2, HTTP/3, WebSocket, gRPC, MQTT, UDP)
- [ ] Для каждого выбора дано обоснование (1-2 предложения)
- [ ] Объяснено, почему альтернативные протоколы менее подходят
- [ ] Учтены требования каждого сценария: latency, throughput, надёжность, масштабируемость
- [ ] Ответы совпадают с решением или обоснованно отличаются

## Как проверить себя

1. Откройте задание и для каждого сценария выберите протокол
2. Сравните свои ответы с решением
3. Обратите внимание на обоснования — даже если вы выбрали тот же протокол, проверьте, совпадают ли причины
4. Если выбор отличается — это не обязательно ошибка: в реальной архитектуре бывает несколько допустимых решений
