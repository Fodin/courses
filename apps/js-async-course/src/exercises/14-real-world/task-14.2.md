# Задание 14.2: Async State Machine

## Цель

Реализовать визуальную конечную машину состояний (State Machine) для процесса оформления заказа. Каждый переход между состояниями — асинхронная операция с задержкой, вероятностью ошибки, автоматическим retry и возможностью отмены.

## Требования

1. **Состояния машины**: `idle` → `loading` → `confirmation` → `payment` → `processing` → `done`. При ошибке после исчерпания попыток — переход в `error`.

2. **Визуализация pipeline**: все состояния отображаются горизонтально в виде блоков, соединённых стрелками. Текущее состояние подсвечено своим цветом, пройденные — зелёным с галочкой.

3. **Async переходы**: каждый шаг занимает определённое время (loading: 1200ms, confirmation: 800ms, payment: 1500ms, processing: 1000ms). Реализовать через `setTimeout` с поддержкой `AbortSignal`.

4. **Retry при ошибке**: каждый шаг может случайно завершиться ошибкой (вероятность ~15–20%). При ошибке — автоматический повтор до 2 раз. После 3 неудачных попыток — переход в `error`.

5. **Отмена**: кнопка "Отменить" доступна на любом активном шаге. При нажатии — машина немедленно возвращается в `idle`.

6. **Индикатор выполнения**: анимированный спиннер или мигающий индикатор рядом с текущим состоянием.

7. **Лог переходов**: каждый переход записывается: время (HH:MM:SS), откуда → куда, длительность в ms. При retry — отметка `(retry #N)`. Лог прокручивается и отображает все переходы сессии.

## Как проверить себя

1. Нажмите "Оформить заказ" — машина начинает проходить через состояния автоматически
2. Наблюдайте как блоки подсвечиваются по очереди, пройденные становятся зелёными
3. В логе появляются переходы с таймингами
4. Нажмите "Отменить" в середине процесса — машина немедленно встаёт в `idle`, лог очищается
5. Запустите несколько раз — иногда будут появляться записи `(retry #1)` в логе
6. При трёх неудачных попытках подряд — переход в состояние `error` (красное)
