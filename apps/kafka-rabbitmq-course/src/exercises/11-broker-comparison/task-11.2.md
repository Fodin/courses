# Задание 11.2: Модели доставки

## Цель

Реализовать интерактивный компонент для визуального сравнения моделей доставки сообщений у пяти брокеров. Студент создаст анимированную схему с движущимися частицами-сообщениями, переключаемую между брокерами, и описательный блок с характеристиками каждой модели.

## Требования

1. Определить тип `BrokerModel` — union type из пяти значений: `'rabbitmq' | 'kafka' | 'nats' | 'redis' | 'pulsar'`.
2. Определить интерфейс `MessageParticle` с полями: `id: number`, `x: number`, `progress: number`, `active: boolean`.
3. Определить интерфейс `ModelConfig` с полями: `name: string`, `color: string`, `delivery: string`, `guarantee: string`, `brokerRole: string`, `consumerRole: string`, `description: string`, `flow: string[]`.
4. Заполнить объект `MODEL_CONFIGS: Record<BrokerModel, ModelConfig>` данными для всех 5 брокеров:
   - RabbitMQ: Push, at-least-once, Smart broker / Dumb consumer
   - Kafka: Pull, at-least-once / exactly-once, Dumb broker / Smart consumer
   - NATS: Push (Core) / Pull (JetStream), at-most-once (Core) / at-least-once (JetStream)
   - Redis Streams: Pull (XREADGROUP), at-least-once с ACK
   - Pulsar: Push + Pull hybrid, Stateless broker + BookKeeper
   - Каждый брокер должен иметь массив `flow` из 5 шагов (путь сообщения)
5. Реализовать состояния: `selected: BrokerModel` (выбранный брокер), `particles: MessageParticle[]` (движущиеся частицы), `running: boolean` (авто-режим), `msgCount: number`.
6. Реализовать функцию `sendMessage`: создаёт новую частицу и анимирует её по `progress` от 0 до 100 с шагом 5 каждые 40ms; при достижении 100 — удаляет через 600ms.
7. Реализовать функцию `startAuto`: при `running=false` запускает отправку 12 сообщений с интервалом 350ms; при `running=true` останавливает.
8. Отрисовать панель с кнопками переключения брокеров. Активная кнопка подчёркнута цветом брокера.
9. Отрисовать информационный блок с цветной рамкой: delivery, guarantee, brokerRole, consumerRole, description.
10. Отрисовать анимированную схему (SVG + абсолютное позиционирование): блоки "Producer", брокер (цветная рамка), "Consumer"; пунктирные линии между ними; частицы как цветные круги с glow-эффектом, исчезающие при `progress > 90`.
11. Кнопки "Отправить сообщение" и "Авто x12" / "Стоп"; счётчик "Отправлено: N".
12. Список шагов потока сообщений из `config.flow` с нумерацией.
13. При переключении брокера: очистить частицы, сбросить счётчик, остановить авто-режим.

## Чеклист

- [ ] Тип `BrokerModel` объявлен как union из 5 значений
- [ ] Интерфейсы `MessageParticle` и `ModelConfig` определены со всеми полями
- [ ] `MODEL_CONFIGS` содержит конфигурацию для всех 5 брокеров
- [ ] Каждый брокер имеет непустой массив `flow` из 5 шагов
- [ ] Переключение между брокерами сбрасывает частицы и счётчик
- [ ] Активная кнопка подчёркнута цветом текущего брокера
- [ ] Информационный блок обновляется при смене брокера
- [ ] Кнопка "Отправить сообщение" запускает одну частицу
- [ ] Частица движется слева направо и исчезает по достижении Consumer
- [ ] Цвет частицы соответствует цвету выбранного брокера
- [ ] Кнопка "Авто x12" отправляет 12 сообщений с интервалом
- [ ] Кнопка меняет текст на "Стоп" во время авто-режима
- [ ] Счётчик `msgCount` инкрементируется с каждым сообщением
- [ ] Список шагов `flow` отображается с цветными номерами

## Как проверить себя

1. При открытии должен быть выбран RabbitMQ. Нажмите "Отправить сообщение" — оранжевая точка должна проползти от Producer через RabbitMQ к Consumer.
2. Нажмите "Авто x12" — 12 сообщений должны отправиться автоматически. Кнопка становится "Стоп".
3. Нажмите "Стоп" до завершения — анимация должна остановиться (но текущая частица долетит).
4. Переключитесь на Kafka — кнопка подчёркивается красным, информационный блок меняется на "Pull (Kafka protocol)", роль брокера "Dumb broker".
5. Переключитесь на NATS — цвет зелёный, latency "★★★★★ (< 1ms)", delivery показывает оба режима.
6. Проверьте, что список шагов flow отображается для каждого брокера с нумерацией 1-5.
7. Убедитесь, что блок рамки меняет цвет при смене брокера.
