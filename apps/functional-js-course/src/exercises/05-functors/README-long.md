# Функторы — подробно

## Откуда термин

Термин пришёл из теории категорий — раздела математики, изучающего структуры и отображения между ними. Там функтор — это отображение между категориями, сохраняющее структуру.

Нам математическое определение не нужно. Практический смысл:

> Функтор — это тип-обёртка `F<T>`, который умеет применять функцию `T → U` к своему содержимому и возвращать `F<U>`.

Ключевое: тип контейнера не меняется, меняется только содержимое.

## Почему Array.map — это функтор

Массив удовлетворяет обоим законам:

```js
// Закон идентичности
[1, 2, 3].map(x => x)  // [1, 2, 3] — тот же массив по значению

// Закон композиции
[1, 2, 3].map(x => x + 1).map(x => x * 2)
// === [1, 2, 3].map(x => (x + 1) * 2)
// [4, 6, 8]  ===  [4, 6, 8]
```

Это позволяет транспайлерам и библиотекам (например, Lodash `chain`) объединять несколько `map` в один проход.

## Promise — «почти функтор»

Promise выглядит как функтор: у него есть `.then()`, который похож на `map`:

```js
Promise.resolve(42).then(x => x + 1)  // Promise<43>
```

Но Promise нарушает закон композиции из-за auto-unwrap:

```js
// f возвращает Promise — и Promise их автоматически «разворачивает»
const f = x => Promise.resolve(x * 2)
const g = x => x + 1

// Ожидаем: Promise<43> (Promise внутри Promise)
Promise.resolve(42).then(f).then(g)

// Получаем: Promise<85>
// Потому что Promise.then() автоматически unwrap-ит вложенный Promise!
// then(f) => Promise<84>, а не Promise<Promise<84>>
```

Поэтому Promise — это монада (умеет flatMap/then с авто-разворачиванием), но не строгий функтор.

## Практические функторы в JS/TS

### Box — Identity Functor

Простейший контейнер без дополнительной семантики. Полезен для построения цепочек:

```ts
const result = Box.of({ name: '  Alice ', age: '30' })
  .map(u => ({ ...u, name: u.name.trim() }))
  .map(u => ({ ...u, age: Number(u.age) }))
  .fold(u => u)
// { name: 'Alice', age: 30 }
```

### Lazy — функтор отложенных вычислений

Оборачивает `() => T` вместо `T`. map цепляет трансформации, run() запускает:

```ts
class Lazy<T> {
  constructor(private thunk: () => T) {}
  static of<T>(thunk: () => T) { return new Lazy(thunk) }
  map<U>(fn: (x: T) => U): Lazy<U> { return new Lazy(() => fn(this.thunk())) }
  run(): T { return this.thunk() }
}

// Вычисление описывается, но не запускается
const computation = Lazy.of(() => heavyCalculation())
  .map(result => result.filter(isValid))
  .map(result => result.map(transform))

// Выполняется только здесь
computation.run()
```

Полезно для ленивой инициализации, отложенного рендера, описания вычислений как данных.

### Validated — функтор с накоплением ошибок

map пропускается, если значение невалидно:

```ts
Validated.of(userInput)
  .validate(s => s.length > 0, 'Поле не может быть пустым')
  .map(s => s.trim())
  .validate(s => s.includes('@'), 'Нет символа @')
  .map(s => s.toLowerCase())
```

Если любая `validate` вернёт false — все последующие `map` будут пропущены. Ошибки накапливаются.

### EventMapper — функтор трансформации событий

```ts
EventMapper.of(rawEvent)
  .map(e => ({ ...e, x: e.x - viewport.width / 2 }))   // центрировать
  .map(e => ({ ...e, normalized: e.x / viewport.width })) // нормализовать
  .map(e => pick(e, ['x', 'y', 'normalized']))           // выбрать нужные поля
```

Позволяет описывать трансформации событий декларативно, не мутируя оригинальный объект.

## Связь с Maybe и Either

Box, Lazy, Validated — это упрощённые варианты. На практике нужны функторы с семантикой ошибок:

- **Maybe / Option** — функтор с двумя состояниями: `Some(value)` и `None`. map пропускается для `None`. Решает проблему null.
- **Either / Result** — функтор с двумя ветками: `Right(value)` (успех) и `Left(error)` (ошибка). map применяется только к Right.

```ts
// Maybe: безопасная работа с null/undefined
Maybe.of(user)
  .map(u => u.address)     // None если user = null
  .map(a => a.city)        // None если address = null
  .fold(() => 'Unknown', city => city)

// Either: обработка ошибок без try/catch
parseJSON(rawString)         // Right(data) или Left(SyntaxError)
  .map(data => data.users)
  .map(users => users.filter(isActive))
  .fold(
    err => renderError(err),
    users => renderList(users)
  )
```

Это тема следующего уровня — Level 6.

## Зачем нужны законы

Законы — это контракт. Если `map` соблюдает оба закона:

1. Код можно рефакторить безопасно: два `map` всегда можно объединить в один
2. Библиотеки (fp-ts, ramda) могут оптимизировать pipeline автоматически
3. Тесты становятся проще: достаточно проверить законы, а не каждый сценарий

Нарушение законов — как нарушение контракта интерфейса. Код компилируется, но ведёт себя непредсказуемо.

## Аналогия: подарочная коробка

Представьте функтор как подарочную коробку:

- `Box.of(gift)` — положить подарок в коробку
- `.map(fn)` — преобразовать содержимое, не открывая коробку (как рентген + манипулятор)
- `.fold(fn)` — открыть коробку и достать содержимое

`map` гарантирует, что коробка останется коробкой — вы не получите случайно пакет или мешок вместо коробки. Это и есть «сохранение структуры».

## Функторы в TypeScript

TypeScript не имеет встроенного типа для функтора, но интерфейс легко описывается:

```ts
interface Functor<T> {
  map<U>(fn: (value: T) => U): Functor<U>
}
```

На практике каждый функтор определяет свой тип возврата точнее:

```ts
class Box<T> implements Functor<T> {
  map<U>(fn: (value: T) => U): Box<U> {  // возвращает Box<U>, а не Functor<U>
    return new Box(fn(this.value))
  }
}
```

Это позволяет сохранять полную типовую информацию в цепочках.
