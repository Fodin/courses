# Уровень 0: Введение — менеджеры пакетов и npm-экосистема

## Зачем нужны менеджеры пакетов

Современный JavaScript-проект редко существует в изоляции. Он опирается на десятки, а то и сотни готовых библиотек: для тестирования, сборки, работы с датами, HTTP-запросов и так далее. Копировать эти библиотеки вручную, следить за их обновлениями и разрешать конфликты версий вручную — задача, которая быстро становится неуправляемой.

**Менеджер пакетов** решает эту задачу автоматически:

- находит нужный пакет в реестре (registry)
- скачивает его вместе со всеми его собственными зависимостями
- записывает точные версии в lockfile, чтобы другой разработчик получил ровно то же дерево

## npm registry

**registry.npmjs.org** — центральный публичный реестр пакетов для JavaScript. Когда вы выполняете `npm install lodash`, npm:

1. Обращается к `https://registry.npmjs.org/lodash` и получает метаданные: список версий, их зависимости, URL tarball-архивов.
2. Выбирает версию, удовлетворяющую указанному диапазону.
3. Скачивает tarball (`.tgz`-архив), распаковывает его в `node_modules`.

Реестр — это просто HTTP-сервер с JSON-API. Можно использовать собственный реестр (Verdaccio, Artifactory) или проксировать публичный.

## Что такое «пакет»

Пакет — это директория с файлом `package.json` внутри, упакованная в tarball. `package.json` содержит:

- `name` и `version` — идентификатор пакета в реестре
- `main` / `exports` — точки входа
- `dependencies` — список того, что нужно пакету для работы

Когда вы публикуете пакет командой `npm publish`, npm упаковывает директорию в `.tgz` и загружает в реестр.

## Локальная vs глобальная установка

**Локальная установка** (`npm install <pkg>`) — пакет попадает в `./node_modules` текущего проекта. Это стандартный способ: каждый проект имеет свои версии зависимостей.

**Глобальная установка** (`npm install -g <pkg>`) — пакет устанавливается в системный каталог (`~/.npm-global` или `/usr/local/lib/node_modules`). Используется для CLI-инструментов, которые нужны вне конкретного проекта (например, `npm install -g typescript`). Однако глобальные установки усложняют воспроизводимость: на другой машине может стоять другая версия.

Современная альтернатива глобальной установке — `npx`, который запускает пакет без постоянной установки.

## Транзитивные зависимости

Если ваш проект зависит от пакета A, а A зависит от B и C — то B и C являются **транзитивными зависимостями** вашего проекта. npm устанавливает их автоматически. Именно из-за транзитивных зависимостей `node_modules` может содержать сотни пакетов при нескольких прямых зависимостях.

## npm CLI и реестр — разные вещи

Важно различать:

- **npm CLI** — утилита командной строки, которую вы устанавливаете на компьютер (`npm`, `npx`)
- **npm registry** — облачный сервис на `registry.npmjs.org`
- **npm, Inc.** — компания, поддерживающая оба

CLI можно использовать с альтернативными реестрами. Реестром можно пользоваться через другие CLI (pnpm, yarn).

## Обзор экосистемы

| Инструмент | Особенность                                                   |
| ---------- | ------------------------------------------------------------- |
| **npm**    | Стандартный менеджер, поставляется с Node.js                  |
| **pnpm**   | Жёсткие ссылки (hardlinks) — экономит место, строгая изоляция |
| **yarn**   | Альтернативный CLI от Meta, Plug'n'Play режим                 |

Все три работают с тем же npm-реестром. Детали рассмотрим в уровнях 15–17.
