# Задание 4.4: Схема репликации и шардирования для соцсети

## Цель

Спроектировать архитектуру хранения данных для социальной сети: выбрать тип БД, стратегию шардирования и репликации для каждой сущности (профили, посты, лайки, комментарии).

## Требования

1. Создайте интерактивную таблицу с 4 сущностями:
   - **Profiles** — профили пользователей (имя, аватар, био)
   - **Posts** — посты (текст, медиа, автор, дата)
   - **Likes** — лайки (кто, что, когда)
   - **Comments** — комментарии (текст, автор, пост, дата)
2. Для каждой сущности предоставьте выбор (dropdown / кнопки):
   - **Тип БД** — PostgreSQL, MongoDB, Cassandra, Redis
   - **Sharding key** — user_id, post_id, date, region, none
   - **Replication** — Master-Slave, Master-Master, None
3. При нажатии «Проверить» покажите оценку решения:
   - Для каждой сущности: правильно / частично / неправильно
   - Объяснение, почему эталонный вариант лучше
4. Покажите эталонное решение с развёрнутым пояснением

## Чеклист

- [ ] 4 сущности отображены в таблице
- [ ] Для каждой — выбор типа БД, sharding key, replication
- [ ] Кнопка «Проверить» с оценкой
- [ ] Объяснение для каждого выбора
- [ ] Эталонное решение с пояснением
- [ ] Оценка отличает полностью правильные, частично правильные и неправильные ответы

## Как проверить себя

Эталонное решение (упрощённое):
1. **Profiles**: PostgreSQL, shard by user_id, Master-Slave (read-heavy, ACID для обновлений)
2. **Posts**: Cassandra, shard by user_id, Master-Slave (write-heavy, хронологический доступ)
3. **Likes**: Redis/Cassandra, shard by post_id, Master-Slave (счётчики, высокая скорость записи)
4. **Comments**: Cassandra, shard by post_id, Master-Slave (write-heavy, чтение по посту)
