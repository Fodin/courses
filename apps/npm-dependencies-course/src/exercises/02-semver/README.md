# Уровень 2: Семантическое версионирование (semver)

## Структура версии: MAJOR.MINOR.PATCH

```
1.2.3
│ │ └── PATCH: исправление бага, обратно совместимо
│ └──── MINOR: новая функциональность, обратно совместимо
└────── MAJOR: ломающие изменения (breaking changes)
```

Правило: если обновление ломает существующий API — меняется MAJOR. Если добавляет новое без ломки — MINOR. Если только исправляет ошибки — PATCH.

## Основные операторы в package.json

### Caret (^) — разрешает MINOR и PATCH обновления

```
^1.2.3  →  >=1.2.3 <2.0.0
^0.2.3  →  >=0.2.3 <0.3.0   (!)
^0.0.3  →  >=0.0.3 <0.0.4   (!!)
```

Важное исключение: для версий `0.x.x` `^` ведёт себя как `~`, а для `0.0.x` — как точная версия. Это сделано намеренно: `0.x` означает нестабильный API, и даже MINOR-изменение может быть ломающим.

### Tilde (~) — разрешает только PATCH обновления

```
~1.2.3  →  >=1.2.3 <1.3.0
~1.2    →  >=1.2.0 <1.3.0
~1      →  >=1.0.0 <2.0.0
```

### Точная версия — только эта версия

```
1.2.3   →  ровно 1.2.3
```

### Диапазоны и x-ranges

```
>=1.2.3           любая версия от 1.2.3 и выше
>=1.2.3 <2.0.0    диапазон
1.2.x             любой PATCH для 1.2
1.x               любой MINOR.PATCH для 1
*                 любая версия
```

### Логическое ИЛИ

```
^1.2.3 || ^2.0.0   версия из первой ИЛИ второй ветки
```

## Pre-release версии

```
1.0.0-alpha.1
1.0.0-beta.2
1.0.0-rc.1
```

Pre-release теги **не попадают** в обычные диапазоны. `^1.0.0` никогда не выберет `1.1.0-beta.1`, даже если числово она больше `1.0.0`. Установить pre-release можно только явно:

```bash
npm install some-pkg@1.1.0-beta.1
```

## Как npm выбирает версию

При `npm install` npm:

1. Получает список всех версий пакета из реестра
2. Фильтрует pre-release (если диапазон не включает pre-release тег)
3. Выбирает **максимальную** версию, удовлетворяющую диапазону

```bash
# Проверить, что выберет npm для диапазона
npm view lodash@'^4.17.0' version

# Все доступные версии
npm view lodash versions --json

# Версия, которая будет установлена
npm install lodash --dry-run
```

## Утилита semver для проверки

```bash
# Установить CLI для тестирования
npx semver '1.2.3' -r '^1.2.0'   # → 1.2.3 (удовлетворяет)
npx semver '2.0.0' -r '^1.2.0'   # → (пусто, не удовлетворяет)
npx semver '0.2.3' -r '^0.2.0'   # → 0.2.3
npx semver '0.3.0' -r '^0.2.0'   # → (не удовлетворяет!)
```
