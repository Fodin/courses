# Задание 9.1: Стратегии партиционирования

## Цель

Реализовать интерактивный визуализатор стратегий партиционирования Kafka. Студент наглядно поймёт, как round-robin, key-based и кастомный партиционер распределяют сообщения по партициям, и почему выбор стратегии влияет на порядок доставки и балансировку нагрузки.

## Требования

1. Определить тип `PartitionStrategy` — union type из трёх значений: `'round-robin' | 'key-based' | 'custom'`.
2. Определить интерфейс `KafkaMessage` с полями: `id: number`, `key: string | null`, `value: string`, `partition: number`, `strategy: PartitionStrategy`, `color: string`.
3. Реализовать три функции партиционирования:
   - `getPartitionRoundRobin(msgId, total)` — возвращает `msgId % total`
   - `getPartitionByKey(key, total)` — hash-функция от ключа: `hash = (hash * 31 + charCode) % total`, при `key === null` возвращает `0`
   - `getPartitionCustom(value, total)` — CRITICAL/HIGH → партиция 0, ERROR/WARN → партиция 1, остальное → последняя партиция
4. Создать массив `SAMPLE_MESSAGES` из 10 сообщений с разными ключами и значениями, включающими метки CRITICAL, HIGH, ERROR, WARN и null-ключи.
5. Реализовать кнопки переключения стратегии: при смене стратегии сбрасывать список сообщений.
6. Реализовать кнопку "Отправить N сообщений": вычислять партицию для каждого сообщения согласно выбранной стратегии и сохранять результат в состоянии.
7. Отобразить три колонки-партиции (Partition 0, 1, 2): в каждой показывать попавшие туда сообщения с ключом и значением. Цвет границы и счётчик соответствуют партиции.
8. Показывать блок с текстовым описанием текущей стратегии.
9. После отправки с key-based стратегией: показывать подсказку о том, что одинаковые ключи всегда попадают в одну партицию.

## Чеклист

- [ ] Тип `PartitionStrategy` объявлен как union type из 3 значений
- [ ] Интерфейс `KafkaMessage` содержит все 6 полей
- [ ] Функция `getPartitionRoundRobin` возвращает `msgId % total`
- [ ] Функция `getPartitionByKey` корректно вычисляет хеш и обрабатывает `null`
- [ ] Функция `getPartitionCustom` маршрутизирует по содержимому значения
- [ ] Массив `SAMPLE_MESSAGES` содержит 10 сообщений с разными ключами
- [ ] При смене стратегии список сообщений сбрасывается
- [ ] Кнопка отправки распределяет все сообщения по партициям
- [ ] Три партиции отображаются визуально с цветными границами и счётчиком
- [ ] Каждое сообщение в партиции показывает ключ и значение
- [ ] Блок описания стратегии обновляется при переключении
- [ ] Подсказка про порядок ключей появляется только для key-based стратегии

## Как проверить себя

1. Выберите стратегию "round-robin" и нажмите "Отправить". Убедитесь, что сообщения распределены примерно равномерно: ~3-4 на каждую партицию.
2. Переключитесь на "key-based". Нажмите "Отправить" дважды — результат должен быть идентичным (детерминированность). Проверьте, что user-101 всегда попадает в одну и ту же партицию.
3. Выберите "custom". Убедитесь, что сообщения с "CRITICAL" и "HIGH" идут в Partition 0, "ERROR" и "WARN" — в Partition 1, остальные — в Partition 2.
4. После key-based отправки должна появиться подсказка о гарантии порядка для одного пользователя.
5. Смена стратегии должна сбрасывать колонки партиций.
