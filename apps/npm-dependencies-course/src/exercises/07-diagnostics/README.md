# Уровень 7: Диагностика дерева зависимостей

## npm ls — просмотр дерева

`npm ls` (или `npm list`) выводит дерево зависимостей:

```bash
npm ls                  # только прямые зависимости
npm ls --all            # полное дерево со всеми транзитивными
npm ls lodash           # найти конкретный пакет в дереве
npm ls --depth=2        # ограничить глубину вывода
npm ls --json           # вывод в JSON
```

### Маркеры в выводе

- `INVALID` — установленная версия не удовлетворяет требованию родителя
- `extraneous` — пакет установлен, но отсутствует в `package.json`
- `missing` — пакет требуется, но не установлен
- `deduped` — пакет не установлен в данном месте, используется дедуплицированная копия выше

## npm explain / npm why

`npm explain <pkg>` (алиас `npm why <pkg>`) — отвечает на вопрос «почему этот пакет в дереве и кто его туда потащил?»:

```bash
npm explain lodash
npm explain lodash@4.17.21
npm why lodash          # синоним
```

Вывод показывает цепочку зависимостей: кто и почему требует данный пакет.

## npm doctor

`npm doctor` — проверка окружения: Node.js, npm, доступность реестра, права доступа к кешу и `node_modules`:

```bash
npm doctor
```

Проверяет: версии Node/npm, доступность registry, права на кеш, наличие git, актуальность npm.

## npm fund

`npm fund` — показывает пакеты, которые ищут финансирование. Чисто информационная команда, не влияет на зависимости.

## npm outdated

Уже знакомая команда (уровень 6), но в контексте диагностики: быстрый способ узнать, насколько устарело дерево.

## Маркеры проблем: разбор

| Маркер       | Значение                           | Что делать                          |
| ------------ | ---------------------------------- | ----------------------------------- |
| `INVALID`    | Версия не совпадает с требованием  | `npm install` для пересборки дерева |
| `extraneous` | Лишний пакет в node_modules        | `npm prune`                         |
| `missing`    | Пакет требуется, но не установлен  | `npm install`                       |
| `deduped`    | Переиспользуется копия из родителя | Норма, не проблема                  |

## ⚠️ Типичные ошибки

❌ Игнорировать INVALID и extraneous в выводе `npm ls`  
✅ INVALID — запустить `npm install`; extraneous — запустить `npm prune`

❌ Думать, что `npm doctor` починит проблемы сам  
✅ `npm doctor` только диагностирует, не исправляет автоматически

❌ Не знать, зачем нужен пакет — удалять наугад  
✅ Сначала `npm explain <pkg>` — понять, кто требует этот пакет
