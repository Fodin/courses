# Задание 3.2: Симулятор кэша (LRU / LFU / FIFO)

## Цель

Построить интерактивный симулятор кэша фиксированного размера, который наглядно показывает, как разные eviction-стратегии решают, какой элемент вытеснить при заполнении кэша.

## Требования

1. Создайте кэш фиксированного размера (по умолчанию 4 элемента)
2. Реализуйте ввод ключа (текстовое поле + кнопка «Запросить»), а также предустановленные кнопки для быстрых запросов (A, B, C, D, E, F)
3. Реализуйте три стратегии вытеснения с переключением:
   - **LRU** — вытесняет элемент, к которому дольше всего не обращались
   - **LFU** — вытесняет элемент с наименьшим числом обращений
   - **FIFO** — вытесняет элемент, добавленный раньше всех
4. Визуализируйте текущее содержимое кэша:
   - Ключ элемента
   - Частота обращений (для LFU)
   - Время последнего доступа (для LRU)
   - Порядок добавления (для FIFO)
5. Отображайте счётчик: hits, misses, hit ratio (%)
6. Ведите лог последних операций: «HIT: key A» или «MISS: key E → evicted key B»
7. Кнопка «Сброс» для начала нового эксперимента

## Чеклист

- [ ] Кэш фиксированного размера (4 слота) отображается визуально
- [ ] Ввод ключа и предустановленные кнопки работают
- [ ] Реализованы 3 стратегии (LRU, LFU, FIFO)
- [ ] При переполнении кэша вытесняется правильный элемент по текущей стратегии
- [ ] Отображается hit/miss/ratio
- [ ] Лог операций показывает историю запросов
- [ ] Видна разница в поведении между стратегиями
- [ ] Переключение стратегии сбрасывает кэш

## Как проверить себя

1. Выберите LRU, запросите A, B, C, D, E — должен вытесниться A (самый давний)
2. Выберите LFU, запросите A, A, A, B, C, D, E — должен вытесниться один из B/C/D (частота 1), но не A (частота 3)
3. Выберите FIFO, запросите A, B, C, D. Обратитесь к A повторно. Запросите E — должен вытесниться A (первый добавленный), несмотря на недавний доступ
4. Сравните hit ratio при последовательности A, B, C, D, A, B, E, A, B, C для разных стратегий
