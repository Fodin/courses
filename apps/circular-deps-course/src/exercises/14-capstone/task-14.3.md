# Задание 14.3 — Распутать модульный граф: два переплетённых цикла (сложное)

## Цель

На графе из 6 модулей найти ДВА переплетённых через общий узел цикла и починить каждый своим приёмом — комбинация техник курса.

## Что дано

- `order.ts` — тип `Order`, зовёт `invoiceStatus` из `invoice.ts` (🔒 только чтение).
- `customer.ts` — потребляет `order.ts` и `invoice.ts`, в циклах не участвует (🔒 только чтение).
- `constants.ts` — вспомогательная константа (🔒 только чтение).
- `format.ts` — пустая заготовка третьего модуля.
- `invoice.ts` — узел, через который переплетены оба цикла:
  - импортирует `Order` из `order.ts` обычным (не типовым) импортом, хотя использует его только как тип — цикл 1: `order.ts` ⇄ `invoice.ts`;
  - содержит `formatMoney`, продублированный с `payment.ts`, оба модуля обмениваются импортами этой функции — цикл 2: `invoice.ts` ⇄ `payment.ts`.
- `payment.ts` — импортирует `formatMoney` из `invoice.ts`.

## Требования

1. Диагностируйте оба цикла отдельно: цикл 1 — типовой, цикл 2 — рантайм между равноправными модулями.
2. Для цикла 1: сделайте импорт `Order` в `invoice.ts` типовым (`import type`).
3. Для цикла 2: перенесите `formatMoney` в `format.ts` (третий модуль); `invoice.ts` перестаёт содержать эту функцию, `payment.ts` берёт её из `format.ts`, а не из `invoice.ts`.
4. Нажмите «Проверить» — оба цикла должны исчезнуть одновременно.

## Чеклист

- [ ] Импорт `Order` в `invoice.ts` — `import type`
- [ ] `formatMoney` вынесен в `format.ts`
- [ ] `invoice.ts` больше не содержит `formatMoney`
- [ ] `payment.ts` берёт `formatMoney` из `./format`, а не из `./invoice`
- [ ] Проверка `noRuntimeCycles()` — зелёная
- [ ] Пройти квиз уровня ≥ 80%

## Как проверить себя

Разберите каждый цикл отдельно, прежде чем чинить оба сразу: если исправить только цикл 1, `noRuntimeCycles()` всё равно останется красной из-за цикла 2, и наоборот. Это тот самый шаг «классификация» из теории уровня — на переплетённом графе он особенно важен.
