# Задание 2.2: Point-to-Point очередь — симулятор

## Цель

Реализовать интерактивный симулятор Point-to-Point очереди с поддержкой Competing Consumers. Пользователь должен видеть, как сообщения от producers попадают в общую очередь и разбираются несколькими consumers — каждое сообщение достаётся ровно одному consumer.

---

## Требования

1. Отображайте очередь сообщений с текущим количеством ожидающих сообщений
2. Реализуйте кнопку "Отправить сообщение" для ручного добавления сообщений в очередь
3. Реализуйте режим "Авто-поток" — автоматическая публикация сообщений раз в 800мс. Кнопка переключает режим on/off
4. Отображайте минимум 2 consumers с состояниями "свободен" / "занят"
5. Свободный consumer автоматически забирает первое сообщение из очереди и обрабатывает его ~1500мс
6. Когда consumer занят, он НЕ берёт новые сообщения — сообщения копятся в очереди
7. Добавьте кнопки "+ Consumer" и "- Consumer" для динамического изменения числа consumers (макс. 4, мин. 1)
8. Нельзя удалить consumer, который сейчас занят
9. Отображайте лог событий в виде консоли с временными метками: кто отправил, кто забрал, кто завершил
10. Показывайте счётчик "Обработано" для каждого consumer
11. Ни одно сообщение НЕ должно попасть к двум consumers одновременно

---

## Чеклист

- [ ] Массив сообщений в state с полями `id`, `text`, `status: 'in-queue' | 'processing' | 'done'`, `consumerId`
- [ ] Массив consumers в state с полями `id`, `name`, `busy`, `processedCount`
- [ ] Polling-механизм (setInterval) для назначения сообщений свободным consumers
- [ ] При назначении сообщения consumer: consumer.busy = true, message.status = 'processing'
- [ ] По истечении таймера обработки: consumer.busy = false, processedCount++, сообщение удаляется из очереди
- [ ] Auto-produce режим управляется через ref и clearInterval для корректной очистки
- [ ] Лог обновляется при каждом событии: отправка, назначение, завершение
- [ ] Видно количество сообщений в очереди в реальном времени
- [ ] При добавлении нового consumer он начинает разбирать очередь немедленно
- [ ] Компонент корректно очищает все intervals при unmount (useEffect cleanup)

---

## Как проверить себя

1. Нажмите "+ Отправить сообщение" 5 раз подряд — все 5 появятся в очереди
2. Первые 2 сообщения (по числу свободных consumers) сразу уйдут в обработку
3. Оставшиеся 3 ждут в очереди, пока consumers освобождаются
4. Включите "Авто-поток" и наблюдайте накопление очереди при 2 consumers
5. Нажмите "+ Consumer" — очередь начнёт разбираться быстрее
6. Нажмите "- Consumer" на занятом consumer — ничего не должно произойти
7. В логе должны быть строки вида:
   ```
   [10:23:15] Producer -> Queue: "Order #5"
   [10:23:15] Consumer A <- Queue: "Order #5"
   [10:23:16] Consumer A DONE: "Order #5"
   ```

### Ожидаемый результат

```
Очередь: [Order #3] [Order #4] [Order #5]  (3 ждут)
Consumer A: [обрабатывает Order #1] — занят
Consumer B: [обрабатывает Order #2] — занят
```
