# Задание 12.3: Dynamic child pipelines

## Цель

Создать интерактивную визуализацию процесса генерации и запуска dynamic child pipeline. Показать двухэтапный процесс: сначала generate-джоб создаёт YAML, затем trigger-джоб его запускает.

## Требования

1. Отобразить список сервисов в директории `services/` — пользователь может добавлять и удалять сервисы
2. Показать generate-джоб, который "генерирует" YAML на основе списка сервисов
3. Отображать сгенерированный YAML — он должен содержать по одному джобу на каждый сервис
4. Показать trigger-джоб, ссылающийся на `artifact: generated-pipeline.yml`
5. Визуализировать итоговый dynamic child pipeline с джобами для каждого сервиса
6. При добавлении или удалении сервиса — пересчитывать и обновлять сгенерированный YAML

## Чеклист

- [ ] Список сервисов с возможностью добавления (поле ввода + кнопка) и удаления (кнопка у каждого сервиса)
- [ ] Блок "generate-pipeline" с иконкой генерации
- [ ] Текстовое поле (readonly) с сгенерированным YAML — обновляется при изменении списка сервисов
- [ ] Блок "trigger-dynamic" с конфигом include:artifact
- [ ] Визуализация child pipeline: отдельный блок со списком джобов
- [ ] YAML для generate-джоба (artifacts:paths) и trigger-джоба (trigger:include:artifact)
- [ ] При пустом списке сервисов показывать предупреждение

## Как проверить себя

1. Добавь сервис `payments` — убедись, что в сгенерированном YAML появился джоб `test-payments`
2. Удали сервис `frontend` — джоб `test-frontend` должен исчезнуть из YAML
3. Добавь 5+ сервисов — YAML должен корректно содержать все джобы
4. Очисти список сервисов — должно появиться предупреждение "Нет сервисов для генерации"
5. Проверь, что конфиг trigger-джоба не меняется при изменении списка сервисов (он всегда ссылается на артефакт)

## Подсказки

- Используй `useState` для: `services` (массив строк), `newServiceName` (строка для поля ввода)
- Генерацию YAML реализуй как функцию `generateYaml(services: string[]): string`, которая строит template literal
- Для каждого сервиса генерируй джоб вида `test-{service}: { stage: test, script: ["cd services/{service} && npm test"] }`
- Минимальный валидный YAML для child: `stages: [test]` + по джобу на сервис
- Для предупреждения при пустом списке используй условный рендеринг
