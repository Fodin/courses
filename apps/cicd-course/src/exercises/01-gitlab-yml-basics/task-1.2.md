# Задание 1.2: Stages и порядок выполнения

## Цель

Понять, как stages управляют порядком выполнения job'ов в пайплайне, и научиться правильно распределять задачи по стадиям.

---

## Что нужно сделать

Создай компонент `Task1_2`, который визуально демонстрирует порядок выполнения пайплайна. Студент добавляет стадии и job'ы, компонент показывает, как они выполнятся.

### Требования

1. Определи TypeScript-интерфейс `PipelineJob`:
   - `id` — уникальный id
   - `name` — имя job'а
   - `stage` — имя стадии
   - `status` — `'pending' | 'running' | 'success' | 'failed'`
   - `duration` — длительность в секундах (для симуляции)

2. Определи TypeScript-интерфейс `PipelineStage`:
   - `name` — имя стадии
   - `jobs` — массив job'ов в этой стадии

3. Реализуй начальный набор данных: стадии `build`, `test`, `deploy` с 2-3 job'ами в каждой

4. Визуализируй пайплайн горизонтально (стадии слева направо):
   - Каждая стадия — колонка
   - Job'ы внутри стадии — карточки в колонке
   - Стрелка между стадиями показывает последовательность

5. Реализуй кнопку "Запустить пайплайн" с симуляцией выполнения:
   - Job'ы одной стадии "запускаются" одновременно (меняют статус на `running`)
   - После "завершения" стадии запускается следующая
   - Финальный статус — `success` или `failed` (можно рандомизировать)

6. Добавь форму для добавления нового job'а с полями: имя job'а и выбор стадии

---

## Ожидаемый результат

- Горизонтальная визуализация стадий с job'ами
- Анимация прохождения пайплайна по стадиям
- Различные цвета для разных статусов (серый, синий, зелёный, красный)
- Форма добавления job'а обновляет визуализацию

---

## Как проверить себя

1. Видишь три колонки (build, test, deploy) с job'ами?
2. Нажми "Запустить пайплайн" — job'ы build стали синими одновременно?
3. После завершения build стартовали job'ы test?
4. Добавь новый job в стадию `test` — он появился в колонке test?
5. Если job упал (красный) — следующая стадия не запустилась?
