# Задание 13.2: Dynamic child pipelines для монорепо

## Цель

Визуализировать процесс генерации динамических child pipelines в монорепо. Пользователь "запускает" анализ изменений, видит какие child pipelines сгенерировались, и может симулировать их выполнение.

## Требования

1. Отобразить два этапа: **генерация** (родительский пайплайн) и **выполнение** (child pipelines)
2. Реализовать кнопку "Запустить анализ изменений" — после нажатия симулировать работу generate-джоба (2-3 секунды с индикатором прогресса или сменой статуса)
3. После генерации показать, какие child pipeline файлы были созданы (только для изменённых сервисов)
4. Дать возможность "запустить" сгенерированные child pipelines — для каждого показать его стадии: `build → test → deploy`
5. Показать сгенерированный YAML для выбранного child pipeline
6. Визуально показать `strategy: depend` — родительский пайплайн должен быть "в ожидании" пока child pipelines не завершились

## Чеклист

- [ ] Переключатели для выбора изменённых сервисов (как в задании 13.1)
- [ ] Кнопка запуска с индикацией процесса генерации
- [ ] Список сгенерированных .yml файлов (только для изменённых сервисов)
- [ ] Блок с YAML содержимым выбранного child pipeline
- [ ] Статусы стадий child pipeline: pending → running → success/failed
- [ ] Визуализация ожидания родительского пайплайна (strategy: depend)
- [ ] Кнопка "сбросить" для повторной симуляции

## Как проверить себя

1. Выбери только payments → должен сгенерироваться только `pipeline-payments.yml`
2. Выбери auth и notifications → два child pipeline файла
3. Нажми "Запустить" → джобы проходят стадии build → test → deploy
4. Родительский пайплайн должен показывать статус "ожидание" пока child pipelines не завершились
5. Кликни по сгенерированному файлу → увидь его YAML содержимое

## Подсказки

- Состояние симуляции хранить в объекте: `{ phase: 'idle' | 'generating' | 'running' | 'done', pipelines: {...} }`
- Для имитации async операций использовать `setTimeout` внутри обработчиков событий
- Стадии child pipeline: `{ stage: 'build' | 'test' | 'deploy', status: 'pending' | 'running' | 'success' }`
- Для последовательного запуска стадий запускать каждую через `setTimeout` с нарастающей задержкой
- Индикатор ожидания родительского пайплайна: пульсирующий цвет или spinner через CSS animation
