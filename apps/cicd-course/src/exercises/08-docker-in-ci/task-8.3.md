# Задание 8.3: Multi-stage builds — оптимизация Dockerfile

## Цель

Создать интерактивный симулятор, который показывает разницу между наивным Dockerfile и оптимизированным multi-stage вариантом: размер итогового образа, скорость повторной сборки при изменении кода и при изменении зависимостей.

## Требования

1. Показать два варианта Dockerfile: **"Простой"** и **"Multi-stage + оптимизированный"** — переключение вкладками
2. Для каждого варианта отображать код Dockerfile с подсветкой (моноширинный шрифт)
3. Симулятор сценариев изменений: три кнопки — **"Изменили код"**, **"Изменили зависимости"**, **"Первая сборка"**
4. Для каждого сценария показывать: список пересобираемых слоёв (с цветовой разметкой: серый = из кэша, оранжевый = пересобирается), время сборки в секундах (числа для наглядности)
5. Блок сравнения размеров образа: простой ~600MB vs multi-stage ~30MB
6. Итоговая таблица: Простой vs Multi-stage по трём параметрам для выбранного сценария

## Чеклист

- [ ] Две вкладки с кодом Dockerfile (Simple / Multi-stage)
- [ ] Три кнопки сценариев — меняют симуляцию
- [ ] Список слоёв с индикацией: из кэша (серый) / пересобирается (оранжевый/красный)
- [ ] Числовое время сборки для обоих вариантов
- [ ] Блок с размерами итоговых образов (визуально: прогрессбар или большие числа)
- [ ] Таблица сравнения для текущего сценария
- [ ] Активный сценарий подсвечен кнопкой в pressed-состоянии

## Как проверить себя

1. Нажми "Изменили код" — в Multi-stage перестраивается только 1-2 слоя, в Simple — все
2. Нажми "Изменили зависимости" — в Multi-stage перестраивается npm ci слой; в Simple — тоже, но разница в финальном образе
3. Нажми "Первая сборка" — оба варианта пересобирают всё, разница только в итоговом размере
4. Переключи вкладки Dockerfile — убедись, что видна разница между простым и multi-stage
5. Проверь, что размеры образов отображаются корректно: Simple ~600MB, Multi-stage ~30MB

## Подсказки

- Используй `useState` для: `activeTab` ('simple' | 'multistage'), `scenario` ('first' | 'code-change' | 'deps-change')
- Данные о слоях и временах захардкодь как константы — это симулятор, не реальная сборка
- Для слоёв используй массив объектов: `{ name: 'FROM node:20', cached: true }`
- Прогрессбар размера: `width: (size / maxSize * 100) + '%'` в inline-стилях
- Для таблицы сравнения достаточно 3-4 строки: время, слои из кэша, финальный размер, что включено в образ
