# Задание 13.4: Mutex на Atomics

## Цель

Реализовать Spinlock Mutex через `Atomics.compareExchange` и показать его влияние на корректность счётчика. Два Worker'а соревнуются за критическую секцию. Без mutex — race condition, счётчик меньше 16. С mutex — ровно 16.

## Требования

1. **Два SharedArrayBuffer**:
   - `lockBuf` — 1 ячейка `Int32Array`: `0 = UNLOCKED`, `1 = LOCKED`
   - `counterBuf` — 1 ячейка `Int32Array`: общий счётчик

2. **Mutex через compareExchange**:
   - `acquireLock`: spinloop — `Atomics.compareExchange(lock, 0, UNLOCKED, LOCKED)` пока не вернёт `UNLOCKED`
   - `releaseLock`: `Atomics.store(lock, 0, UNLOCKED)` + `Atomics.notify(lock, 0, 1)`

3. **Критическая секция** — каждый Worker выполняет 8 итераций:
   - Читает `counter[0]`, ждёт ~2мс (busy wait), пишет `val + 1`
   - Без mutex: часть инкрементов теряется
   - С mutex: все 16 инкрементов сохраняются

4. **Timeline визуализация**:
   - Две горизонтальные полосы (по одной на Worker)
   - Каждый прямоугольник = время в критической секции
   - Без mutex: красные прямоугольники там, где есть временное пересечение
   - С mutex: полосы не пересекаются — чёткое чередование

5. **Переключатель** — вкладки "С Mutex / Без Mutex".

6. **Итоговый счётчик** — зелёный если 16, красный если меньше.

## Как проверить себя

1. Запустите "С Mutex" 5 раз — счётчик всегда 16, полосы не пересекаются
2. Переключитесь на "Без Mutex", запустите 5 раз — счётчик меньше 16, красные пересечения в timeline
3. Добавьте `console.log` в Worker — убедитесь, что `acquireLock` действительно крутится в цикле пока лок занят
4. Попробуйте увеличить задержку в критической секции с 2мс до 10мс — число потерянных инкрементов возрастёт без mutex
