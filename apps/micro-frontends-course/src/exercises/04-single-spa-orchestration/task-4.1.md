# Задание 4.1 — Визуализатор lifecycle Single-SPA

## Цель

Создать интерактивный симулятор, который показывает, как Single-SPA управляет жизненным циклом приложений при переходах между маршрутами: какие приложения монтируются, какие размонтируются, и в каком порядке это происходит.

## Требования

1. Навигационная панель с 4-5 маршрутами (/, /catalog, /cart, /profile, /admin).
   Каждый маршрут имеет заранее заданный набор приложений, которые должны быть активны (MOUNTED).

2. Сетка состояний приложений: минимум 5-6 приложений (например: shell, navbar, catalog, cart, profile, admin).
   Каждое приложение отображается карточкой с:
   - Именем и фреймворком
   - Текущим состоянием из списка: NOT_LOADED, LOADING, NOT_BOOTSTRAPPED, BOOTSTRAPPING, NOT_MOUNTED, MOUNTING, MOUNTED, UNMOUNTING
   - Цветовой индикацией: серый/зелёный/синий/оранжевый/красный — по смыслу состояния

3. При клике на маршрут — анимированный переход:
   - Приложения, которые были MOUNTED, но не нужны на новом маршруте: UNMOUNTING → NOT_MOUNTED
   - Приложения, которые нужны, но NOT_LOADED: LOADING → NOT_BOOTSTRAPPED → BOOTSTRAPPING → NOT_MOUNTED → MOUNTING → MOUNTED
   - Приложения, которые NOT_MOUNTED (уже bootstrapped): MOUNTING → MOUNTED
   - Каждый шаг имеет задержку 200-400мс для наглядности
   - Кнопки навигации заблокированы во время перехода

4. Лог событий внизу (тёмный фон, monospace):
   - Формат: `HH:MM:SS  имя-приложения  событие`
   - Последние ~40 событий, автопрокрутка к новым

5. Временная шкала последнего перехода:
   - Горизонтальные бары для каждой фазы (load, bootstrap, mount, unmount)
   - Масштаб: ширина бара пропорциональна длительности фазы
   - Подпись с длительностью в мс

## Checklist

- [ ] Минимум 5 маршрутов и 6 приложений
- [ ] Все 8 состояний (NOT_LOADED, LOADING, NOT_BOOTSTRAPPED, BOOTSTRAPPING, NOT_MOUNTED, MOUNTING, MOUNTED, UNMOUNTING) отображаются и используются
- [ ] При переходе старые приложения unmount, новые — проходят полный lifecycle
- [ ] Повторное посещение маршрута: приложения переходят NOT_MOUNTED → MOUNTED (без повторного bootstrap)
- [ ] Кнопки навигации заблокированы во время перехода
- [ ] Лог событий обновляется в реальном времени
- [ ] Временная шкала строится после каждого перехода

## Как проверить себя

- Перейдите на /catalog — должны смонтироваться catalog-приложение через все фазы
- Перейдите с /catalog на /cart — catalog должен пройти UNMOUNTING, cart — полный цикл загрузки
- Вернитесь на /catalog — catalog должен сразу перейти NOT_MOUNTED → MOUNTED (bootstrap уже сделан)
- Во время перехода попробуйте кликнуть другой маршрут — не должно работать

## Подсказка

Используйте `async/await` с `setTimeout` (обёрнутым в Promise) для симуляции задержек. Храните состояния всех приложений в массиве объектов в `useState`. Для временной шкалы запоминайте `Date.now()` в начале каждой фазы.
