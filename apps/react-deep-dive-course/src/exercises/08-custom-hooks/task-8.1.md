# Задание 8.1: useDebounce

## Задание

Реализуйте кастомный хук `useDebounce<T>(value: T, delay: number): T`, который откладывает обновление значения до тех пор, пока пользователь не перестанет его изменять в течение `delay` миллисекунд.

## Цель

Понять, как работает cleanup в `useEffect`, почему без него debounce не работает, и научиться строить хуки, в которых `useEffect` управляет браузерными API через корректный lifecycle.

## Требования

1. Реализовать `useDebounce<T>(value: T, delay: number): T`
2. Внутри — `useState` для хранения debounced-значения и `useEffect` с `setTimeout`
3. `useEffect` должен возвращать `() => clearTimeout(timer)` — cleanup, отменяющий предыдущий таймер
4. Хук должен корректно обрабатывать изменение `delay` (новый таймер с новым delay)
5. Создать компонент-демо: поле поиска, которое показывает исходное и debounced-значение
6. Показать счётчик setState-вызовов — он должен увеличиваться только после паузы, не при каждом keystroke
7. Добавить визуальный индикатор: "ожидание..." пока значения различаются

## Чеклист

- [ ] `useDebounce` принимает generic тип `T`
- [ ] Внутри есть `useState(value)` для debounced-значения
- [ ] `useEffect` запускает `setTimeout` при каждом изменении `value`
- [ ] Cleanup возвращает `() => clearTimeout(timer)` — без этого debounce не работает
- [ ] Deps массив содержит `[value, delay]`
- [ ] Демо показывает разницу между "live" значением и debounced
- [ ] При быстром вводе счётчик setState не растёт
- [ ] После паузы (delay ms) debounced-значение обновляется

## Как проверить себя

1. Введите "react hooks" быстро — счётчик setState не должен расти при каждой букве
2. Остановите ввод — через 300ms debounced-значение должно обновиться
3. Измените значение `delay` (слайдер или кнопки) — новый таймаут должен применяться
4. Откройте DevTools → Performance → запишите быстрый ввод: должен быть один render после паузы, не N renders при N нажатиях
5. Закомментируйте строку с `clearTimeout` и снова введите быстро — увидите, что setState вызывается для каждой буквы
