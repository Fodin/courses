# Уровень 4: Barrel-файлы как «фабрика циклов»

## Аналогия: единая стойка регистрации

Представь большой офис, где у каждого отдела есть своя дверь, но по правилам все посетители обязаны сначала зайти на общую стойку регистрации на первом этаже, и уже оттуда их направляют куда нужно. Это удобно для внешних гостей — один вход, один список контактов. Но что, если сотрудник отдела бухгалтерии, чтобы дойти до соседнего стола в своём же отделе, тоже обязан каждый раз спускаться на первый этаж, регистрироваться и подниматься обратно? Абсурд — а именно так часто и работает barrel-файл, когда через него ходят «свои».

## Что такое barrel

**Barrel** — это файл (обычно `index.ts`) в папке модуля, который просто реэкспортирует всё, что в этой папке есть:

```ts
// features/auth/index.ts — barrel
export { login } from './login'
export { logout } from './logout'
export { AuthForm } from './AuthForm'
```

Идея хорошая: внешний код импортирует одну точку — `from 'features/auth'`, а не лезет во внутренности папки.

## Как barrel создаёт цикл, которого «не должно быть»

```mermaid
graph LR
  Login["login.ts"] -->|"import { AuthForm } from '../index'"| Index["index.ts (barrel)"]
  Index -->|"export { login } from './login'"| Login
```

Файл `login.ts` лежит **внутри** той же папки, что и barrel. Если он вдруг импортирует что-то через `../index` (собственный barrel) вместо прямого пути к соседнему файлу — barrel, который реэкспортирует сам `login.ts`, оказывается зависим от него же. Получается self-import цикл, который легко просмотреть: снаружи кажется, что всё чисто, просто «модуль что-то импортировал из своего же public API».

Второй сценарий ещё коварнее: два соседних слайса импортируют друг друга **через barrel**, а barrel реэкспортирует вообще всё содержимое папки — в граф зависимостей затягиваются десятки не связанных с задачей файлов, и цикл возникает там, где по логике задачи его быть не должно (это называют **barrel hell**).

📌 Запомнить: barrel — это граница для **внешних** потребителей. Внутри своей же папки/слайса импортируй файлы напрямую, по относительному пути, а не через `./index`.
