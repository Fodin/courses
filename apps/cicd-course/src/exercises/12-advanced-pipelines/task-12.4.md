# Задание 12.4: DAG с needs

## Цель

Создать интерактивную визуализацию DAG-пайплайна с `needs`. Показать разницу между линейным stage-пайплайном и DAG, рассчитать реальное время выполнения в обоих режимах.

## Требования

1. Отобразить набор джобов с настраиваемой длительностью: `build-frontend` (2 мин), `build-backend` (8 мин), `test-frontend` (3 мин), `test-backend` (4 мин), `deploy` (2 мин)
2. Реализовать переключатель "Линейный режим / DAG с needs"
3. В линейном режиме — показывать выполнение с барьерами stage (каждая stage ждёт все джобы предыдущей)
4. В DAG-режиме — показывать, что `test-frontend` стартует сразу после `build-frontend`, не ожидая `build-backend`
5. Рассчитывать и отображать общее время выполнения пайплайна в обоих режимах
6. Генерировать YAML с `needs:` для DAG-режима

## Чеклист

- [ ] 5 блоков джобов с иконками и временем выполнения
- [ ] Поля или слайдеры для изменения длительности каждого джоба
- [ ] Переключатель "Линейный / DAG"
- [ ] Визуализация графа зависимостей (стрелки needs между джобами)
- [ ] Расчёт и отображение общего времени: "Линейный: X мин | DAG: Y мин | Экономия: Z мин"
- [ ] YAML с `needs:` для DAG-режима (обновляется при изменении зависимостей)
- [ ] Подсветка "критического пути" — самой длинной цепочки зависимостей

## Как проверить себя

1. В линейном режиме увеличь `build-backend` до 20 мин — все test-джобы должны ждать его, суммарное время вырастет
2. Переключись в DAG — `test-frontend` должен стартовать через 2 мин, а не через 20
3. Измени длительность `test-backend` так, чтобы он стал критическим путём — проверь, что расчёт обновился
4. Убедись, что YAML в DAG-режиме содержит `needs:` у test-джобов
5. Проверь, что `deploy` в YAML содержит needs на оба test-джоба

## Подсказки

- Используй `useState` для: `dagMode` (boolean), `durations` (объект `{[job]: number}`)
- Время линейного пайплайна: `max(build-jobs) + max(test-jobs) + deploy`
- Время DAG-пайплайна: `max(build-frontend + test-frontend, build-backend + test-backend) + deploy`
- Для визуализации стрелок между блоками используй CSS `position: absolute` или SVG-линии
- Критический путь подсвечивай другим цветом бордера (например, оранжевый вместо синего)
- Для слайдеров используй `<input type="range" min={1} max={20} />`
