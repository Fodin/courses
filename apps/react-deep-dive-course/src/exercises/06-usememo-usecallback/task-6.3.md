# Задание 6.3: Memoization Cost-Benefit

## Задание

Компонент `Task6_3` содержит бенчмарк трёх вариантов вычисления:

1. **Без мемоизации** — дорогое вычисление (sort + filter по 10 000 элементов) напрямую
2. **useMemo на дешёвом** — `items.length` обёрнут в `useMemo`
3. **useMemo на дорогом** — sort + filter обёрнуты в `useMemo`

Кнопка "Trigger Re-render" вызывает setState, который **не меняет данные** — только вызывает рендер.
`performance.now()` замеряет время каждого варианта.

Твоя задача — реализовать все три варианта и сделать вывод о том, когда мемоизация оправдана.

## Цель

Измерить реальную стоимость мемоизации vs. стоимость вычисления.
Понять: мемоизировать дешёвые операции = платить overhead без пользы.

## Требования

1. Массив `items` — 10 000 объектов `{ id, value, active }`, создаётся один раз через `useMemo([], [])`
2. **Вариант 1 (без мемо)**: `expensiveResult` вычисляется напрямую при каждом рендере:
   ```ts
   const start = performance.now()
   const expensiveResult = items
     .filter(i => i.active)
     .sort((a, b) => b.value - a.value)
     .slice(0, 5)
   const time1 = performance.now() - start
   ```
3. **Вариант 2 (useMemo на дешёвом)**: `items.length` обёрнут в `useMemo([items])`
   - Замеряй время через `performance.now()` внутри factory
4. **Вариант 3 (useMemo на дорогом)**: sort + filter обёрнуты в `useMemo([items])`
   - Deps `[items]` — массив не меняется при trigger re-render, только `tick` меняется
5. Кнопка "Trigger Re-render": увеличивает `tick` (не меняет `items`)
6. Отображение: три карточки с результатом и временем выполнения (мс)
7. При нажатии кнопки: вариант 1 пересчитывается (время > 0), варианты 2 и 3 возвращают кэш

## Чеклист

- [ ] `items` создаётся один раз через `useMemo([], [])` с 10 000 элементов
- [ ] Вариант 1 показывает время > 0 при каждом рендере
- [ ] Вариант 2 показывает время ≈ 0 при trigger re-render (кэш), но overhead deps
- [ ] Вариант 3 показывает время ≈ 0 при trigger re-render (кэш)
- [ ] Вариант 2 при первом рендере показывает минимальное время (< 0.01ms) — length это O(1)
- [ ] Вариант 3 при первом рендере показывает значительное время (> 1ms) — sort это O(n log n)
- [ ] Вывод в UI: "useMemo на дешёвом = overhead, useMemo на дорогом = выгода"

## Как проверить себя

1. Открой компонент — посмотри время первого рендера для каждого варианта
2. Нажми "Trigger Re-render" несколько раз
3. Убедись: Вариант 1 каждый раз тратит время, Варианты 2 и 3 — нет
4. Сравни первый рендер: Вариант 2 (length) должен быть на порядки быстрее Варианта 3 (sort)
5. Сделай вывод: мемоизировать length — платить overhead useMemo без пользы
