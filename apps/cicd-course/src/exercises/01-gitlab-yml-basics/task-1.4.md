# Задание 1.4: Ключевое слово image

## Цель

Научиться выбирать подходящий Docker-образ для разных типов CI задач: понять компромиссы между размером образа, наличием инструментов и скоростью пайплайна.

---

## Что нужно сделать

Создай компонент `Task1_4`, который представляет интерактивный каталог Docker-образов для CI. Студент видит характеристики каждого образа и может "назначить" образ для разных типов проектов.

### Требования

1. Определи TypeScript-интерфейс `DockerImage`:
   - `name` — имя образа (например, `'node:20-alpine'`)
   - `category` — категория (`'javascript' | 'python' | 'go' | 'ruby' | 'generic'`)
   - `sizeMb` — приблизительный размер в МБ
   - `tools` — массив предустановленных инструментов (строки)
   - `useCases` — для каких задач подходит (массив строк)
   - `pros` — преимущества (массив строк)
   - `cons` — недостатки (массив строк)

2. Создай данные для 6 образов:
   - `node:20-alpine` (JS/TS проекты, ~170 МБ)
   - `python:3.11-slim` (Python проекты, ~130 МБ)
   - `golang:1.21-alpine` (Go проекты, ~270 МБ)
   - `ruby:3.2-alpine` (Ruby/Rails, ~80 МБ)
   - `alpine:3.18` (Shell-скрипты, утилиты, ~5 МБ)
   - `ubuntu:22.04` (Сложные сборки, ~70 МБ)

3. Отобрази карточки образов в сетке (2-3 в ряд):
   - Имя образа
   - Размер с цветовой индикацией (зелёный — до 100 МБ, жёлтый — до 300 МБ, красный — больше)
   - Список инструментов
   - Клик раскрывает детали (pros/cons, use cases)

4. Реализуй задание на сопоставление "Проект → Образ":
   - Список из 4 типов проектов (React-приложение, Python-скрипт, Go-микросервис, Shell CI-утилита)
   - Для каждого — выпадающий список или кнопки выбора образа
   - Кнопка "Проверить выбор" сравнивает с правильными ответами

5. Покажи рекомендации после проверки: какой образ выбран правильно, какой нет и почему

---

## Ожидаемый результат

- Сетка карточек с Docker-образами
- Клик на карточку раскрывает детали с pros/cons
- Задание на сопоставление с проверкой
- Объяснение правильных ответов

## Как проверить себя

1. Видишь сетку из 6 карточек с размерами?
2. Карточка `alpine:3.18` имеет зелёный индикатор размера (5 МБ), а `golang:1.21-alpine` — жёлтый (270 МБ)?
3. Кликни на любую карточку — раскрылись детали с pros/cons?
4. В задании на сопоставление выбери `ubuntu:22.04` для React-приложения и нажми "Проверить" — видишь объяснение, почему это не оптимально?
5. Выбери правильные образы для всех проектов — видишь зелёный результат?
