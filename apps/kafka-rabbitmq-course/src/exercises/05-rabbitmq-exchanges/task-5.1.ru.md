# Задание 5.1: Direct Exchange

## Цель

Реализовать интерактивный симулятор Direct Exchange, который демонстрирует точную маршрутизацию сообщений по routing key.

## Требования

1. Определи интерфейс `DirectBinding` со свойствами: `queue` (string), `routingKey` (string), `color` (string), `bgColor` (string), `messages` (string[]).
2. Определи интерфейс `DirectMessage` со свойствами: `id` (number), `routingKey` (string), `payload` (string), `timestamp` (string).
3. Создай начальный массив `initialDirectBindings` с 4 привязками:
   - `orders.new` → routing key `order.created`
   - `orders.paid` → routing key `order.paid`
   - `orders.cancelled` → routing key `order.cancelled`
   - `notifications` → routing key `order.created` (демонстрирует, что один ключ может связывать несколько очередей)
4. Реализуй состояния: `bindings`, `selectedKey`, `customKey`, `animating` (string[]), `log`, `messageCount`.
5. Реализуй функцию `publish()`: при публикации находит все очереди с совпадающим routing key, добавляет сообщения в них, обновляет лог, запускает анимацию (список имён очередей) на 900 мс.
6. Реализуй функцию `clearQueues()`: очищает сообщения во всех очередях и лог.
7. Отобрази схему архитектуры: Producer → стрелка → Direct Exchange → набор очередей с binding keys.
   - Binding key подсвечивается, если совпадает с текущим routing key
   - Очередь подсвечивается при анимации (isAnimating)
   - Внутри очереди: название, счётчик сообщений, последнее сообщение
8. Предоставь панель управления: список из 5 predefined routing keys для выбора + поле для ввода своего ключа.
9. Отобрази блок публикации в виде псевдокода AMQP (`channel.basicPublish(...)`) с текущим exchange, routing key и телом сообщения.
10. Отобрази лог маршрутизации: для каждого сообщения показывает routing key и в какие очереди оно попало (или "UNROUTABLE").
11. Добавь информационный блок с описанием принципов работы Direct Exchange.

## Чеклист

- [ ] Интерфейсы `DirectBinding` и `DirectMessage` объявлены с корректными типами
- [ ] Инициализирован массив из 4 привязок с двумя очередями на один ключ `order.created`
- [ ] Функция `publish` корректно выбирает очереди по exact match
- [ ] Анимация срабатывает только для очередей с совпадающим ключом
- [ ] Очередь `notifications` и `orders.new` оба получают сообщение при ключе `order.created`
- [ ] При неизвестном ключе лог показывает "UNROUTABLE"
- [ ] Поле ввода своего ключа работает и имеет приоритет над выбором из списка
- [ ] Кнопка "Очистить" сбрасывает сообщения и лог
- [ ] Отображается псевдокод AMQP с актуальными значениями
- [ ] Информационный блок присутствует

## Как проверить себя

1. Выберите routing key `order.created` и нажмите "Опубликовать" — сообщение должно попасть в очереди `orders.new` и `notifications` (обе имеют этот ключ).
2. Выберите `order.paid` — сообщение попадает только в `orders.paid`.
3. Введите несуществующий ключ, например `foo.bar` — лог должен показать "UNROUTABLE".
4. Нажмите "Очистить" — все очереди и лог должны сброситься.
