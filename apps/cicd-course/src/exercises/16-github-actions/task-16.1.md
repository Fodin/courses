# Задание 16.1: Основы Workflow — events, jobs, steps, runs-on

## Цель

Создать интерактивный конструктор GitHub Actions workflow. Студент выбирает триггеры, Runner и структуру джобов — и видит итоговый YAML в реальном времени. Параллельно отображается сравнение с эквивалентной конфигурацией GitLab CI.

## Требования

1. Отобразить секцию выбора **триггеров** (`on:`):
   - Чекбоксы: `push`, `pull_request`, `schedule`, `workflow_dispatch`
   - При включении `schedule` — поле ввода cron-выражения (по умолчанию `'0 2 * * *'`)
   - При включении `workflow_dispatch` — подсказка "Ручной запуск через UI"
2. Отобразить выбор **Runner** (`runs-on`): кнопки `ubuntu-latest`, `windows-latest`, `macos-latest`
3. Отобразить **три джоба**: `lint`, `test`, `build` с чекбоксами включения/отключения
4. Показать `needs:` зависимости: `test` зависит от `lint`, `build` зависит от `test`
5. Показывать **два YAML-блока**: итоговый GitHub Actions workflow и эквивалентный GitLab CI пайплайн
6. Добавить аннотацию-подсказку для ключевого отличия: "В GitLab код клонируется автоматически. В GitHub нужен `actions/checkout`"

## Чеклист

- [ ] Чекбоксы для 4 триггеров с корректным отображением в YAML
- [ ] Поле cron появляется только при включённом `schedule`
- [ ] Выбор `runs-on` из 3 вариантов
- [ ] Включение/отключение джобов влияет на YAML и `needs:` зависимости
- [ ] При отключённом `lint` — `test` не имеет `needs: lint`
- [ ] Два YAML-блока: GitHub Actions и GitLab CI (для сравнения)
- [ ] Блок с аннотацией о `actions/checkout`
- [ ] YAML обновляется при каждом изменении

## Как проверить себя

1. Включи только `push` триггер — в YAML должен быть `on: push:`
2. Включи `schedule` — появится поле cron, в YAML — `schedule:` с cron-строкой
3. Смени Runner на `macos-latest` — в обоих джобах поменяется `runs-on`
4. Отключи джоб `lint` — `needs: lint` должен исчезнуть из джоба `test`
5. Сравни два YAML-блока — найди отличие с `actions/checkout`

## Подсказки

- Используй `useState` для: массива включённых триггеров, cron-строки, выбранного Runner, массива включённых джобов
- Функция `buildGitHubYaml(config)` генерирует GitHub Actions YAML
- Функция `buildGitLabYaml(config)` генерирует GitLab CI YAML для сравнения
- В блоке `needs:` джоба убирай ссылки на отключённые джобы
- В каждый активный джоб добавляй `uses: actions/checkout@v4` как первый шаг
