# Задание 9.2: Capacity калькулятор — Paste Service

## Цель

Построить интерактивный калькулятор ёмкости для Paste Service. Ввести параметры нагрузки и получить расчёт storage, bandwidth, количества серверов и стоимости. Визуализировать рост данных по месяцам и годам.

## Требования

1. **Input-параметры** (с дефолтными значениями):
   - Pastes/day — количество новых pastes в день (default: 5M)
   - Average paste size — средний размер paste в KB (default: 10 KB)
   - Retention — срок хранения в годах (default: 5)
   - Read:Write ratio — соотношение чтений к записям (default: 5:1)

2. **Расчёт и вывод**:
   - **QPS**: write QPS, read QPS (средний), peak read QPS (x3)
   - **Storage**: контент (S3) на полный период, метаданные (SQL) на полный период
   - **Bandwidth**: incoming (upload), outgoing (download), peak outgoing
   - **Стоимость**: примерная стоимость S3 storage ($0.023/GB/мес), bandwidth ($0.09/GB)
   - **Серверы**: примерное количество API-серверов (при 1000 QPS на сервер)

3. **Таблица роста**: помесячный/погодовой рост storage (content + metadata) с нарастающим итогом

4. Все расчёты обновляются при изменении любого input

## Чеклист

- [ ] Реализованы все 4 input-параметра с возможностью изменения
- [ ] QPS рассчитывается корректно (write = pastes/86400, read = write * ratio)
- [ ] Storage рассчитывается для content (S3) и metadata (SQL) отдельно
- [ ] Bandwidth рассчитывается с учётом peak (x3)
- [ ] Стоимость S3 рассчитывается с актуальными тарифами
- [ ] Таблица роста показывает нарастающий итог по периодам
- [ ] Интерфейс обновляется в реальном времени при изменении параметров

## Как проверить себя

1. Введите дефолтные значения (5M pastes/day, 10 KB, 5 лет, 5:1)
2. Проверьте: write QPS ~ 58, read QPS ~ 290, peak ~ 870
3. Проверьте: content storage ~ 91 TB за 5 лет
4. Измените параметры и убедитесь, что расчёты обновляются
5. Сравните свой калькулятор с эталонным решением (Solution)
