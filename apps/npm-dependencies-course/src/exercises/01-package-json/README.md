# Уровень 1: Виды зависимостей в package.json

## Пять полей для зависимостей

В `package.json` есть пять полей, каждое с чётким назначением:

| Поле                   | Когда ставить                                                |
| ---------------------- | ------------------------------------------------------------ |
| `dependencies`         | Нужно в продакшне: react, express, lodash                    |
| `devDependencies`      | Только для разработки: jest, eslint, webpack                 |
| `peerDependencies`     | Пакет-плагин объявляет, что нужен «хост» определённой версии |
| `optionalDependencies` | Может не установиться — программа продолжит работу           |
| `bundledDependencies`  | Включается в tarball при npm publish                         |

## dependencies

Всё, что нужно коду во время выполнения. Если вы пишете Express-приложение и используете `axios` для HTTP-запросов — `axios` должен быть здесь.

```bash
npm install axios          # → dependencies
```

## devDependencies

Инструменты, которые нужны только разработчику или CI-пайплайну, но не в готовом приложении. Тесты, линтеры, сборщики, TypeScript, генераторы типов.

```bash
npm install --save-dev jest typescript eslint   # → devDependencies
```

При установке в продакшне или на сервере их можно пропустить:

```bash
npm install --omit=dev
# Старый синтаксис, эквивалентен:
npm install --production
```

## peerDependencies

Механизм для плагинов и расширений. Пакет сам **не устанавливает** зависимость, а объявляет: «чтобы я работал, в проекте хоста уже должна быть эта библиотека».

Пример: `eslint-plugin-react` требует `eslint` как peer.

**npm v7+:** peerDependencies устанавливаются автоматически. Если версия конфликтует — npm выдаёт ошибку `ERESOLVE`. Разрешить принудительно: `npm install --legacy-peer-deps`.

## optionalDependencies

Пакет попробует установить зависимость, но при ошибке (отсутствие нативного модуля, сетевая проблема) продолжит установку без неё. Ваш код должен проверять наличие модуля перед использованием.

```bash
npm install --save-optional fsevents   # только для macOS
```

## bundledDependencies

Массив имён пакетов (не объект версий), которые будут включены в tarball при `npm publish`. Редкий случай: когда нужно гарантировать наличие зависимости даже без доступа к реестру. Не путайте с `bundleDependencies` (оба написания принимаются npm).

## Поле engines

Не зависимость, но связано: объявляет, с какими версиями Node.js и npm пакет совместим.

```json
{
  "engines": {
    "node": ">=18.0.0",
    "npm": ">=9.0.0"
  }
}
```

npm проверяет это поле при установке и выдаёт предупреждение (не ошибку по умолчанию).

## Что куда класть: практическое правило

Задайте вопрос: «нужен ли этот пакет в runtime?»

- **Да** → `dependencies`
- **Нет (только для разработки)** → `devDependencies`
- **Я пишу плагин/расширение** → `peerDependencies`
- **Пакет необязателен** → `optionalDependencies`
