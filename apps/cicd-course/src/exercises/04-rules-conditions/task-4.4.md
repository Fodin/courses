# Задание 4.4: Комбинирование правил

## Цель

Создать конструктор сложных `rules` — интерфейс для добавления правил с условиями `if`, `changes`, `exists`, визуализацией AND/OR логики и предпросмотром итогового YAML.

## Требования

1. Интерфейс добавления правил: форма с полями for if, changes (список паттернов), when
2. Список добавленных правил с возможностью удаления
3. Визуализация логики: rules — OR между правилами, внутри правила — AND между условиями
4. Симулятор: выбор тестового события → подсветка первого сработавшего правила
5. YAML-предпросмотр — генерация rules-конфигурации из добавленных правил
6. Кнопки "Загрузить пример" с 3 готовыми конфигурациями

## Поля формы нового правила

| Поле | Тип | Описание |
|---|---|---|
| if (условие) | select + text | Выбор переменной + оператор + значение |
| changes паттерны | textarea | Один паттерн на строку |
| when | select | on_success / never / manual / always |

## Готовые примеры конфигураций

**Пример 1: MR + изменения**
```yaml
rules:
  - if: $CI_PIPELINE_SOURCE == "merge_request_event"
    changes: [src/**/*]
    when: on_success
  - if: $CI_COMMIT_BRANCH == "main"
    when: on_success
  - when: never
```

**Пример 2: Деплой на прод**
```yaml
rules:
  - if: $CI_COMMIT_TAG =~ /^v\d+\.\d+\.\d+$/
    when: on_success
  - if: $CI_COMMIT_BRANCH == "main"
    when: manual
  - when: never
```

**Пример 3: Нагрузочные тесты**
```yaml
rules:
  - if: $CI_PIPELINE_SOURCE == "schedule"
    when: always
  - if: $CI_COMMIT_BRANCH == "main" && $CI_PIPELINE_SOURCE == "push"
    when: manual
  - when: never
```

## Чеклист

- [ ] Форма добавления правила с тремя полями (if / changes / when)
- [ ] Кнопка "Добавить правило" — добавляет в список
- [ ] Список правил с кнопкой удаления каждого
- [ ] Блок "AND/OR логика" — схема: прямоугольники правил (OR) → кружки условий внутри правила (AND)
- [ ] Тестовый симулятор: выпадающий список событий, кнопка "Проверить"
- [ ] Подсветка первого сработавшего правила при симуляции
- [ ] Блок YAML-предпросмотра, обновляемый реактивно
- [ ] 3 кнопки "Загрузить пример" с готовыми конфигурациями

## Как проверить себя

- Загрузи "Пример 1" → выбери событие "MR + изменения в src/" → должно подсветиться первое правило
- Загрузи "Пример 1" → выбери "Push в main" → должно подсветиться второе правило
- Загрузи "Пример 1" → выбери "Push в feature" → ни одно правило кроме fallback (never) не сработает
- Добавь своё правило → оно должно появиться в YAML-предпросмотре
- Удали правило → YAML обновится без него
