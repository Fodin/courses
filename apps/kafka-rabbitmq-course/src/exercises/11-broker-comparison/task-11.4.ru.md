# Задание 11.4: Benchmark Dashboard

## Цель

Реализовать интерактивный дашборд с бенчмарк-данными пяти брокеров. Студент создаст bar-chart визуализацию throughput и latency по разным сценариям тестирования, а также график влияния размера сообщения на производительность. Задание закрепляет понимание производительностных характеристик брокеров.

## Требования

1. Определить интерфейс `BenchScenario` с полями: `id: string`, `name: string`, `description: string`.
2. Определить интерфейс `BrokerBenchmark` с полями: `broker: string`, `color: string`, `throughput: Record<string, number>`, `p99Latency: Record<string, number>`, `msgSizeImpact: { size: string; throughput: number; latency: number }[]`.
3. Заполнить массив `BENCH_SCENARIOS` из 4 сценариев: "Small + Persistent" (1KB, 3x replication, fsync), "Small + Fast" (1KB, in-memory), "Large + Persistent" (100KB, 3x replication), "Fan-out 10 consumers".
4. Заполнить массив `BENCH_DATA` из 5 объектов (по брокеру). Для каждого брокера — значения throughput и p99Latency для всех 4 сценариев, и массив `msgSizeImpact` из 5 точек (100B, 1KB, 10KB, 100KB, 1MB).
5. Реализовать вспомогательную функцию `formatNum(n: number): string` — форматирует число: `≥ 1M → "1.2M"`, `≥ 1K → "500K"`, иначе строка числа.
6. Определить тип `BenchView = 'throughput' | 'latency' | 'msgsize'`.
7. Реализовать состояния: `scenario: string` (выбранный сценарий, начально `'small_persist'`), `view: BenchView` (начально `'throughput'`), `selectedBrokers: Set<string>` (все 5 выбраны по умолчанию), `msgSizeBroker: string` (начально `'Apache Kafka'`).
8. Реализовать функцию `toggleBroker`: добавляет/удаляет брокер из `selectedBrokers`. Нельзя снять галочку если остался последний выбранный.
9. Вычислить `visibleData` — только выбранные брокеры. `maxThroughput` и `maxLatency` для нормализации баров.
10. Отрисовать панель фильтров: кнопки по каждому брокеру (затемнение `opacity: 0.4` если не выбран, цветное подчёркивание если выбран).
11. Отрисовать вкладки: Throughput, P99 Latency, Msg Size Impact.
12. Для вкладок Throughput/Latency: кнопки сценариев, блок описания сценария, bar-chart. В баре: для throughput — чем больше тем лучше (зелёный если > 60%). Для latency — чем меньше тем лучше (красный если > 60% от максимума). Анимация ширины бара `transition: 'width 0.4s ease'`.
13. Для вкладки Msg Size Impact: переключатель брокеров, bar-chart для throughput по размерам сообщений (100B → 1MB), значения throughput и latency рядом.
14. Блок с примечанием по методологии бенчмарков (откуда данные, что влияет на результат).

## Чеклист

- [ ] Интерфейсы `BenchScenario` и `BrokerBenchmark` определены
- [ ] `BENCH_SCENARIOS` содержит 4 сценария с описаниями
- [ ] `BENCH_DATA` содержит данные для всех 5 брокеров
- [ ] Каждый брокер имеет `msgSizeImpact` из 5 точек
- [ ] `formatNum` корректно форматирует 2000000 → "2.0M", 500000 → "500K"
- [ ] Переключение `selectedBrokers` работает, нельзя убрать последний
- [ ] Фильтры брокеров: затемнение неактивных, цветное подчёркивание активных
- [ ] Вкладка Throughput: bar-chart обновляется при смене сценария
- [ ] Вкладка Latency: бар красный если высокое значение
- [ ] Bar анимируется при переключении сценария
- [ ] Описание сценария отображается под кнопками сценариев
- [ ] Вкладка Msg Size Impact: bar-chart для выбранного брокера по 5 размерам
- [ ] Блок методологии присутствует внизу
- [ ] При смене view='msgsize' кнопки сценариев скрываются

## Как проверить себя

1. При открытии выбрана вкладка Throughput, сценарий "Small + Persistent". Kafka должна иметь самый длинный бар (800K msg/s).
2. Нажмите на сценарий "Small + Fast" — NATS должна выйти в явные лидеры (8M msg/s).
3. Переключитесь на вкладку "P99 Latency" — Redis Streams и NATS должны показывать маленькие значения (зелёные бары), RabbitMQ — немного выше.
4. Снимите галочку с "RabbitMQ" — его бар исчезает, максимум пересчитывается.
5. Попробуйте снять все галочки — последний брокер не должен сниматься.
6. Переключитесь на "Msg Size Impact". Выберите "NATS". Бар для 100B должен быть максимальным, для 1MB — минимальным.
7. Переключитесь на Apache Kafka в Msg Size Impact — сравните падение throughput с ростом размера.
8. Убедитесь, что блок примечания по методологии отображается внизу.
