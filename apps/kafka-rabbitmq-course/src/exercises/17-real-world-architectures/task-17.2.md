# Задание 17.2: Централизованное логирование

## Цель

Реализовать интерактивную симуляцию пайплайна централизованного логирования на основе стека ELK + Kafka. Несколько микросервисов пишут логи в отдельные Kafka-топики, Logstash читает их и передаёт в Elasticsearch. Пользователь видит поток логов в Kibana-style интерфейсе с фильтрацией по уровню, сервису и тексту сообщения.

## Требования

1. Объявить интерфейс `LogEntry` с полями: `id: number`, `service: string`, `level: 'INFO' | 'WARN' | 'ERROR'`, `message: string`, `topic: string`, `partition: number`, `timestamp: string`.
2. Объявить константный массив `SERVICES_LOG` из 5 сервисов: `'api-gateway'`, `'order-service'`, `'payment-service'`, `'inventory-service'`, `'notification-service'`.
3. Объявить словарь `SERVICE_COLORS` — каждому сервису свой цвет.
4. Объявить массив `LOG_TEMPLATES` из 12 шаблонов с полями `service`, `level`, `message`. Шаблоны должны включать реалистичные сообщения: HTTP-запросы, создание заказов, ошибки оплаты, предупреждения о низком складском остатке и т.д.
5. Объявить словарь `LEVEL_COLORS` (INFO → зелёный, WARN → жёлтый, ERROR → красный).
6. Реализовать вспомогательную функцию `getPartition(service): number` — возвращает партицию через `indexOf(service) % 3`.
7. Реализовать функцию `genTimestamp(): string` — возвращает текущее время в формате `HH:MM:SS.mmm` (12 символов из ISO-строки).
8. Объявить состояния компонента: `logs: LogEntry[]`, `streaming: boolean`, `searchTerm: string`, `filterLevel: 'ALL' | 'INFO' | 'WARN' | 'ERROR'`, `filterService: string`, `totalConsumed: number`, `counterRef` и `timerRef` через `useRef`.
9. Реализовать `startStreaming`: запускает `setInterval` с интервалом 700 мс. На каждом тике берёт шаблон из `LOG_TEMPLATES` по кругу (через `counterRef`), создаёт `LogEntry` с топиком `logs.{service}` и партицией через `getPartition`, добавляет запись в начало `logs` (ограничение 60), увеличивает `totalConsumed`.
10. Реализовать `stopStreaming`: останавливает интервал, устанавливает `streaming: false`.
11. Реализовать `clearLogs`: вызывает `stopStreaming`, сбрасывает `logs`, `totalConsumed` и `counterRef.current`.
12. Добавить `useEffect` для очистки интервала при размонтировании.
13. Реализовать фильтрацию `filteredLogs` по `filterLevel`, `filterService` и `searchTerm` (поиск в `message`, нечувствительный к регистру).
14. Вычислять `topicCounts: Record<string, number>` — количество записей в каждом топике.
15. Вычислять `levelCounts: { INFO: number; WARN: number; ERROR: number }`.
16. Отрисовать визуализацию пайплайна: цветные плашки сервисов → Kafka (logs.*) → Logstash → Elasticsearch → Kibana UI.
17. При наличии логов отображать блок Kafka-топиков с количеством сообщений и номером партиции для каждого топика.
18. Отображать статистику уровней (INFO / WARN / ERROR / Всего в Elasticsearch) в цветных плашках.
19. Отрисовать Kibana-style панель фильтров (тёмный фон): текстовый поиск, селектор уровня, селектор сервиса.
20. Отрисовать поток логов в тёмном терминальном блоке. Первая строка выделяется более тёмным фоном. Каждая строка: timestamp → уровень (цветной) → [сервис] (цветной) → текст сообщения. При пустом результате фильтрации показывать сообщение-заглушку.
21. Добавить кнопки "Запустить поток логов" / "Остановить поток" (переключаемые) и "Очистить".

## Чеклист

- [ ] Интерфейс `LogEntry` объявлен с 7 полями
- [ ] Массив `SERVICES_LOG` содержит ровно 5 сервисов
- [ ] Словарь `SERVICE_COLORS` задан для всех 5 сервисов
- [ ] Массив `LOG_TEMPLATES` содержит 12 шаблонов с реалистичными сообщениями
- [ ] `LEVEL_COLORS` задан для INFO, WARN, ERROR
- [ ] `getPartition` возвращает `indexOf % 3`
- [ ] `genTimestamp` возвращает строку формата `HH:MM:SS.mmm`
- [ ] Состояния `logs`, `streaming`, `searchTerm`, `filterLevel`, `filterService`, `totalConsumed` объявлены
- [ ] `counterRef` и `timerRef` объявлены через `useRef`
- [ ] `startStreaming` запускает интервал 700 мс, создаёт `LogEntry` с топиком и партицией
- [ ] Новые логи добавляются в начало массива, хранится не более 60 записей
- [ ] `stopStreaming` корректно останавливает `setInterval`
- [ ] `clearLogs` сбрасывает логи, счётчик и `counterRef.current = 0`
- [ ] `useEffect` очищает интервал при размонтировании компонента
- [ ] `filteredLogs` фильтруется одновременно по трём критериям
- [ ] `topicCounts` подсчитывается из текущих `logs`
- [ ] `levelCounts` подсчитывается из текущих `logs`
- [ ] Пайплайн (сервисы → Kafka → Logstash → Elasticsearch → Kibana) отрисован
- [ ] Блок Kafka-топиков появляется только при наличии логов
- [ ] Блок статистики показывает актуальные счётчики INFO / WARN / ERROR / всего
- [ ] Панель фильтров стилизована в тёмных тонах
- [ ] Лог-стрим тёмный, первая строка подсвечена, цвета уровней корректны
- [ ] Кнопка переключает текст "Запустить" / "Остановить" в зависимости от состояния

## Как проверить себя

1. Откройте задание — пайплайн отображён, лог пустой, кнопка "Запустить поток логов" активна.
2. Нажмите кнопку. Логи начинают поступать примерно каждые 0.7 секунды. Первая строка всегда выделена.
3. Появляется блок Kafka-топиков — видны топики `logs.api-gateway`, `logs.payment-service` и т.д. с номерами партиций (0, 1, 2).
4. Счётчики INFO / WARN / ERROR обновляются по мере поступления логов.
5. Введите в поле поиска `order` — отображаются только строки с "order" в тексте.
6. Выберите уровень ERROR — видны только красные строки. Переключитесь на конкретный сервис — остаются только его логи.
7. Нажмите "Остановить поток" — поступление логов прекращается, фильтры продолжают работать.
8. Нажмите "Очистить" — все логи удаляются, счётчики обнуляются.
