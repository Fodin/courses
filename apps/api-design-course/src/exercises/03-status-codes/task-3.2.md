# Задание 3.2 — Конструктор error response по RFC 7807

## Цель

Научиться составлять структурированные ответы об ошибках по стандарту RFC 7807 Problem Details. Понять назначение каждого поля и их взаимосвязь с HTTP-кодом.

## Требования

1. Компонент предлагает несколько сценариев ошибок: ошибка валидации, ресурс не найден, конфликт, rate limit, доступ запрещён.
2. При выборе сценария поля формы заполняются шаблонными значениями.
3. Пользователь может редактировать все поля RFC 7807: type, title, status, detail, instance.
4. Для сценария с ошибками валидации — чекбокс для добавления массива errors по полям.
5. Результирующий JSON обновляется в реальном времени и отображается с подсветкой.

## Чеклист

- [ ] Минимум 4 сценария ошибок
- [ ] Редактируемые поля: type, title, status, detail, instance
- [ ] Живой preview результирующего JSON
- [ ] Поддержка массива errors для ошибок валидации
- [ ] Отображение Content-Type: application/problem+json
- [ ] Смена сценария перезаполняет форму

## Как проверить себя

Составьте error response для случая, когда пользователь пытается обновить чужую запись. Правильный статус — 403. В поле detail опишите конкретную причину. Убедитесь, что type — это URI, а не просто строка. Покажите коллеге — понятно ли из ответа, что произошло?
