# Задание 4.3: Virtual Hosts и права доступа

## Цель

Создать интерактивный редактор Virtual Hosts и permissions RabbitMQ. Студент поймёт модель изоляции vhost'ов, трёхуровневую систему прав (configure/write/read) на основе regex-паттернов и как эти права применяются к реальным ресурсам.

## Требования

1. Определить интерфейсы `VHost`, `RmqUser` и `Permission`:
   - `VHost`: `name`, `description`, `tags: string[]`, `created`
   - `RmqUser`: `username`, `tags: string[]`, `color`
   - `Permission`: `user`, `vhost`, `configure`, `write`, `read`
2. Создать начальные данные: минимум 3 vhost'а (включая `/`), 3 пользователя с разными тегами (`administrator`, `none`, `monitoring`) и 4 записи permissions с разными уровнями доступа.
3. Реализовать левую панель с двумя секциями:
   - **Virtual Hosts**: список с выделением активного vhost. Клик — выбирает vhost. Кнопка удаления для всех vhost'ов кроме `/`. Форма добавления нового vhost (input + кнопка "+", работает по Enter и по клику).
   - **Пользователи**: список с цветными точками и тегами. Клик — выбирает/снимает выделение пользователя.
4. Реализовать основную часть с двумя вкладками (`matrix`, `editor`):
   - **Вкладка "matrix"**: таблица permissions для выбранного vhost. Строки — пользователи, ячейки — права (configure/write/read в виде `code`). Кнопка редактирования в каждой строке переходит во вкладку "editor". Цветная подсветка: полный доступ `.*` — зелёный, пустой паттерн — красный.
   - **Вкладка "editor"**: форма редактирования прав конкретного пользователя в конкретном vhost. Три поля ввода (configure, write, read) с подсказками. Живой preview: список из `RESOURCE_NAMES` с зелёными/красными индикаторами совпадения regex-паттерна. Кнопки "Сохранить" и "Отмена".
5. Реализовать функцию `matchesRegex(pattern: string, name: string): boolean` — проверяет, совпадает ли имя ресурса с паттерном (`^pattern$`), обрабатывает пустую строку как false и ловит исключения невалидного regex.
6. При удалении vhost — автоматически удалять все связанные permissions.
7. При сохранении permissions — обновлять существующую запись или добавлять новую.

## Чеклист

- [ ] Интерфейсы `VHost`, `RmqUser`, `Permission` строго типизированы
- [ ] Начальные данные: 3 vhost, 3 пользователя, 4 permissions с разными паттернами
- [ ] Список vhosts: выделение, удаление (кроме `/`), добавление через форму
- [ ] Форма добавления vhost работает по Enter и по клику на "+"
- [ ] Список пользователей: цветные точки, теги, выделение кликом
- [ ] Матрица permissions для выбранного vhost отображает все 3 поля
- [ ] Паттерн `.*` подсвечен зелёным, пустой — красным
- [ ] Кнопка редактирования открывает editor-вкладку с заполненными полями
- [ ] Live preview в editor показывает, к каким ресурсам применяется паттерн
- [ ] Функция `matchesRegex` корректно обрабатывает пустую строку и невалидный regex
- [ ] Сохранение обновляет существующую или добавляет новую запись
- [ ] Удаление vhost удаляет связанные permissions

## Как проверить себя

1. Выберите vhost `/production` — в матрице отображаются права для `admin`, `app_user`, `monitor`.
2. У `app_user` поля configure и write/read содержат `orders\..*|payments\..*` — это ограниченный доступ.
3. Нажмите кнопку редактирования для `app_user` — открывается editor.
4. В поле write введите `audit\..*` — в preview напротив `audit.events` появляется зелёный индикатор.
5. В поле write очистите значение — все индикаторы становятся красными.
6. Сохраните — возвращаетесь в matrix, видны обновлённые права.
7. Добавьте новый vhost `/dev` через форму — он появляется в списке.
8. Нажмите "✕" рядом с `/dev` — vhost удаляется, из матрицы исчезают его permissions.
9. Попытайтесь удалить `/` — ничего не происходит (дефолтный vhost защищён).
