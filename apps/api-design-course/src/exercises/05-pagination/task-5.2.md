# Задание 5.2 — Конструктор query-параметров

## Цель

Научиться правильно компоновать query-параметры для фильтрации, сортировки и пагинации, понять структуру мета-данных в ответе.

## Требования

1. Компонент содержит форму с элементами управления:
   - Фильтр по статусу (select: active / draft / archived / любой)
   - Диапазон цен: поля «от» и «до» (операторы `price[gte]` и `price[lte]`)
   - Дата создания от (оператор `createdAt[gte]`)
   - Сортировка (select): по имени A→Z, Z→A, по дате новые/старые, по цене ↑↓
   - Страница и лимит (5 / 10 / 20 / 50)
2. URL запроса обновляется в реальном времени при изменении любого фильтра.
3. В URL для диапазонов используется нотация `price[gte]`, `price[lte]`, `createdAt[gte]`.
4. Для сортировки по убыванию используется минус: `sort=-createdAt`.
5. При изменении фильтров (кроме страницы) страница сбрасывается на 1.
6. Отображается блок с примером мета-данных ответа: totalCount, page, limit, totalPages, hasNextPage, hasPrevPage.
7. Разные части URL выделены разными цветами (фильтры, операторы, сортировка, пагинация).

## Чеклист

- [ ] Фильтр по статусу
- [ ] Диапазон цен с операторами `[gte]` / `[lte]`
- [ ] Фильтр по дате с оператором `[gte]`
- [ ] Сортировка с конвенцией минус = DESC
- [ ] Выбор лимита из preset-значений
- [ ] URL обновляется при каждом изменении
- [ ] Сброс страницы на 1 при смене фильтров
- [ ] Мета-данные ответа (totalCount, totalPages, hasNextPage, hasPrevPage)
- [ ] Цветовое выделение частей URL

## Как проверить себя

Настройте фильтры: статус = active, цена 500–3000, сортировка по дате (новые), страница 2, лимит 10.
Ожидаемый URL должен содержать: `status=active`, `price[gte]=500`, `price[lte]=3000`, `sort=-createdAt`, `page=2`, `limit=10`.
Убедитесь, что при смене сортировки страница сбрасывается на 1.
