# Задание 0.1: Хороший vs плохой API

## Цель

Научиться распознавать признаки плохо спроектированного API и аргументированно объяснять, что именно нарушено и как это исправить.

## Требования

1. Создайте компонент `Task0_1`, который отображает минимум **3 пары** сравнений "плохой API vs хороший API"
2. Каждая пара должна покрывать **отдельный аспект**: URL-дизайн, формат ответа, именование полей (или любые другие на ваш выбор)
3. Каждая пара содержит:
   - Блок с плохим примером (код/HTTP-запрос)
   - Блок с хорошим примером (код/HTTP-запрос)
   - Список конкретных проблем в плохом варианте
4. Добавьте кнопку "Показать разбор" для каждой пары — разбор скрыт по умолчанию
5. Добавьте кнопку "Показать все разборы"
6. Реализуйте с помощью `useState`

## Чеклист

- [ ] Минимум 3 пары сравнений
- [ ] Каждый аспект — отдельный (нет дублирования тем)
- [ ] Кнопка "Показать разбор" для каждой пары
- [ ] Кнопка "Показать все разборы"
- [ ] Состояние (показать/скрыть) работает независимо для каждой пары
- [ ] Визуально плохой и хороший варианты различаются (цвет, иконки)
- [ ] Компонент обёрнут в `<div className="exercise-container">`

## Как проверить себя

1. Откройте задание в браузере — разборы должны быть скрыты
2. Нажмите "Показать разбор" на первой паре — должен открыться только этот разбор
3. Нажмите "Показать все разборы" — все разборы открываются одновременно
4. Прочитайте список проблем для каждого плохого примера и убедитесь, что каждая проблема конкретна и объяснима
5. Попробуйте придумать четвёртую пару самостоятельно и добавить её
