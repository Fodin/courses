# Задание 6.3: Durable vs Transient — тест на отказоустойчивость

## Цель

Симулировать перезапуск брокера RabbitMQ и наблюдать, какие очереди и сообщения выживают в зависимости от конфигурации. Понять разницу между durable/transient очередями и persistent/transient сообщениями.

## Требования

1. Кнопка "Объявить очередь" с чекбоксом `durable` (true/false)
2. Публикация сообщений с чекбоксом `persistent` (deliveryMode 1 или 2)
3. Кнопка "Перезапустить брокер" — симулирует остановку и запуск
4. После перезапуска:
   - Non-durable очереди исчезают полностью
   - В durable очередях остаются только persistent сообщения
5. Визуализация очередей: каждая очередь — блок с бейджем durable/transient
6. Сообщения в очередях: цветные ячейки (синие — persistent, розовые — transient, зелёные с галочкой — выжили)
7. Матрица выживания в конце (таблица 2x2)
8. Лог операций: declare, publish, broker restart

## Чеклист

- [ ] Можно объявить durable и non-durable очереди одновременно
- [ ] Persistent и transient сообщения визуально различаются
- [ ] Кнопка перезапуска активна только при наличии сообщений
- [ ] После перезапуска non-durable очереди исчезают из списка
- [ ] В durable очереди transient сообщения удаляются, persistent — остаются со значком ✓
- [ ] Матрица 2x2 корректно отражает все 4 комбинации
- [ ] Лог содержит все операции с правильными параметрами
- [ ] Broker status (Online/Restarting) отображается корректно

## Как проверить себя

**Сценарий 1 — всё выживает**:
1. Объяви durable очередь
2. Публикуй persistent сообщения
3. Нажми "Перезапустить брокер"
4. Результат: очередь и все сообщения на месте (зелёные, с ✓)

**Сценарий 2 — частичная потеря**:
1. Объяви durable очередь
2. Публикуй 3 persistent + 3 transient сообщения
3. Нажми "Перезапустить брокер"
4. Результат: 3 persistent выжили, 3 transient потеряны

**Сценарий 3 — полная потеря**:
1. Объяви non-durable очередь
2. Публикуй любые сообщения
3. Нажми "Перезапустить брокер"
4. Результат: очередь исчезла вместе со всеми сообщениями

## Подсказки

- После "перезапуска" используй `.filter()` для удаления non-durable очередей
- Анимируй перезапуск: показывай "STOPPING..." → задержка → "ONLINE"
- Лог: `[declare] queue="name" durable=true`, `[publish] "msg" deliveryMode=2`
- Матрицу выживания показывай всегда (не только после перезапуска) — это образовательный элемент
