# Задание 0.2: Архитектура — брокер, клиенты, топики

## Цель

Освоить структуру топиков и механизм wildcards в MQTT. Реализовать интерактивное дерево топиков и тестер паттернов подписки.

---

## Требования

1. Определи рекурсивный интерфейс `TopicNode` с полями: `name` (только сегмент), `full` (полный путь), `type: 'file' | 'dir'`, опционально `children`, `hasMessage`, `retained`

2. Создай дерево топиков минимум из 3 уровней вложенности и 8+ листьев (например: `home/sensor/temperature`, `home/light/living_room/status`, `home/door/status`)

3. Отобрази дерево топиков с иконками (`📁` для узлов, `📄` для листьев). Листья с сообщениями помечаются бейджем, retained — особым бейджем

4. Клик по узлу дерева выделяет его и показывает полный путь

5. Реализуй "Тестер подписки": поле ввода паттерна (с поддержкой `+` и `#`) и кнопка "Тест". Функция `matchWildcard(pattern, topic)` должна корректно обрабатывать оба wildcard.

6. Отобрази параметры MQTT-подключения (host, port, keepalive, clientId, protocolVersion) в виде таблицы

---

## Требования к логике matchWildcard

- `home/+/temperature` совпадает с `home/bedroom/temperature`, но не с `home/floor1/bedroom/temperature`
- `home/#` совпадает с `home/`, `home/a`, `home/a/b/c`
- `+/+` совпадает только с двухуровневыми топиками
- `#` совпадает со всем

## Как проверить себя

1. Видишь дерево топиков с иерархией?
2. Клик по листу показывает полный путь?
3. Введи `home/sensor/+` → нажми Тест → совпало только `home/sensor/temperature` и `home/sensor/humidity`?
4. Введи `home/#` → совпали ВСЕ топики внутри `home/`?
5. Введи `home/+/+` → совпали только двухуровневые пути под `home/`?
6. Введи `office/#` → 0 совпадений?
