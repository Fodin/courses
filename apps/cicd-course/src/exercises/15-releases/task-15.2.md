# Задание 15.2: GitLab Release и changelog

## Цель

Создать конструктор GitLab Release: пользователь вводит параметры релиза (тег, название, changelog-записи, ссылки на assets), а компонент генерирует корректный `.gitlab-ci.yml` с блоком `release:` и визуализирует итоговую страницу релиза.

## Требования

1. Реализовать поле ввода версии тега (например, `v1.3.0`) с валидацией формата `v#.#.#`
2. Реализовать поле названия релиза (например, `Release v1.3.0: OAuth и оптимизации`)
3. Добавить секцию `Changelog entries` — список строк с кнопкой "Добавить запись". Каждая запись выбирает тип (feat/fix/chore) и текст
4. Добавить секцию `Assets` — список ссылок с полями: name, url, link_type (other/image/package/runbook)
5. Показывать предпросмотр "GitLab Release page" — как будет выглядеть страница релиза
6. Генерировать YAML-конфиг с блоком `release:` в реальном времени на основе всех полей

## Чеклист

- [ ] Поле тега с валидацией — при неверном формате показывать ошибку
- [ ] Поле названия релиза
- [ ] Добавление/удаление changelog-записей (минимум 3 записи в начале)
- [ ] Changelog группируется по типу: Features / Bug Fixes / Chores
- [ ] Добавление/удаление assets-ссылок
- [ ] Визуальный предпросмотр страницы релиза (имитация GitLab UI)
- [ ] YAML-конфиг с image: release-cli, rules по тегу, блоком release:
- [ ] YAML обновляется при каждом изменении

## Как проверить себя

1. Введи тег `v2.0.0` — YAML обновится, в rules появится v2.0.0 в regex
2. Добавь changelog-запись типа `feat` с текстом "новый API" — в предпросмотре появится в разделе Features
3. Добавь changelog-запись типа `fix` — появится в разделе Bug Fixes
4. Добавь asset с link_type: `image` и url на Docker Hub — появится в YAML в блоке assets:links
5. Введи невалидный тег `1.2.3` (без v) — должна появиться ошибка валидации

## Подсказки

- Changelog-записи: `{ id, type: 'feat'|'fix'|'chore', text }` в массиве `useState`
- Assets: `{ id, name, url, link_type }` в массиве `useState`
- Для предпросмотра используй имитацию GitLab-стиля: тёмная шапка, тег как бейдж, разделы markdown
- Валидацию тега делай через regex `/^v\d+\.\d+\.\d+$/`
- YAML блока `release:` генерируй отдельной функцией `buildReleaseYaml(tag, name, assets)`
