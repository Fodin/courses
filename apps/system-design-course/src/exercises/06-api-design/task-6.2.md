# Задание 6.2: Rate Limiter симулятор

## Цель

Построить интерактивный симулятор алгоритмов rate limiting: визуализировать как Token Bucket, Fixed Window и Sliding Window обрабатывают поток запросов.

## Требования

1. Реализуйте переключение между тремя алгоритмами:
   - **Token Bucket** — жетоны пополняются с постоянной скоростью (rate), максимум = burst
   - **Fixed Window** — счётчик сбрасывается каждые N секунд
   - **Sliding Window** — считает запросы в скользящем окне
2. Настройка параметров через кнопки:
   - **Rate** — допустимая скорость запросов (requests/sec)
   - **Burst** — максимальный всплеск (для Token Bucket)
   - **Window** — размер окна в секундах (для Fixed/Sliding Window)
3. Кнопка «Отправить запрос» — отправляет один запрос к rate limiter
4. Визуализация:
   - Текущее состояние алгоритма (токены в ведре / счётчик в окне)
   - Лог запросов: принятые (зелёный) и отклонённые (красный)
   - Счётчики: всего запросов, принятых, отклонённых
5. Кнопка «Burst 10» — отправить 10 запросов сразу (демонстрация всплеска)
6. Reset — сброс состояния

## Чеклист

- [ ] Переключение между 3 алгоритмами (Token Bucket, Fixed Window, Sliding Window)
- [ ] Настраиваемые параметры (rate, burst, window)
- [ ] Кнопка «Send Request» — один запрос
- [ ] Кнопка «Burst 10» — 10 запросов сразу
- [ ] Визуализация состояния алгоритма
- [ ] Лог принятых/отклонённых запросов
- [ ] Счётчики (total, allowed, rejected)
- [ ] Reset

## Как проверить себя

1. Token Bucket: burst запросов проходит, затем — только с заданным rate
2. Fixed Window: на границе двух окон можно отправить 2x лимита
3. Sliding Window: на границе окон 2x лимита невозможен
4. Burst 10 при rate=5, burst=5 (Token Bucket): первые 5 проходят, остальные 5 — 429
5. Reset сбрасывает все счётчики и состояние
