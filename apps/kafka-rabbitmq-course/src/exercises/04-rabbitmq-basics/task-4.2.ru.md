# Задание 4.2: Management UI — дашборд

## Цель

Реализовать симулятор RabbitMQ Management UI с живыми анимированными метриками. Студент научится читать данные дашборда, понимать метрики очередей и соединений, различать типы очередей и состояния.

## Требования

1. Определить интерфейсы `QueueStats` и `ConnectionInfo` со всеми необходимыми полями:
   - `QueueStats`: `name`, `vhost`, `type` (`'classic' | 'quorum' | 'stream'`), `state` (`'running' | 'idle' | 'flow'`), `messages`, `messagesReady`, `messagesUnacked`, `publishRate`, `deliverRate`, `consumers`, `memory`
   - `ConnectionInfo`: `name`, `user`, `vhost`, `state`, `channels`, `sendRate`, `recvRate`
2. Создать начальные данные: минимум 5 очередей (включая хотя бы одну quorum, одну stream и одну с 0 consumers) и минимум 3 соединения.
3. Реализовать анимацию метрик через `setInterval` (1500 мс): publish/deliver rate незначительно меняются, количество сообщений пересчитывается исходя из дельты между publish и deliver. Idle-очереди не анимировать.
4. Реализовать три вкладки (`overview`, `queues`, `connections`) с переключением:
   - **Overview**: 4 сводных карточки (Queues, Messages, Publish/s, Deliver/s), блок с информацией о ноде (Disk free, Memory used, FD used, Erlang processes, Uptime и т.д.), анимированные rate-бары для активных очередей.
   - **Queues**: таблица со всеми очередями, цветные бейджи типа, иконка состояния. Клик на строку — показывает детальную панель с дополнительными полями. Очереди с 0 consumers подсвечены предупреждением.
   - **Connections**: таблица соединений с пользователем, vhost, состоянием, каналами и скоростями.
5. Хедер дашборда: имя ноды, версия RabbitMQ, версия Erlang, текущее время.
6. Футер: версия Management Plugin, счётчик обновлений (tick).
7. Компонент должен корректно очищать интервал при размонтировании (`useEffect` с cleanup).

## Чеклист

- [ ] Интерфейсы `QueueStats` и `ConnectionInfo` строго типизированы
- [ ] Начальные данные содержат разнообразные очереди (quorum, stream, classic, idle, без consumers)
- [ ] Анимация работает через `setInterval` с cleanup в `useEffect`
- [ ] Вкладка Overview: 4 карточки с агрегированными метриками
- [ ] Вкладка Overview: блок Node info с 6+ параметрами
- [ ] Вкладка Overview: animated rate-bars для активных очередей
- [ ] Вкладка Queues: таблица с цветными бейджами типа и статуса
- [ ] Клик на строку таблицы открывает детальную панель
- [ ] Очередь без consumers выделяется предупреждением (⚠️ 0)
- [ ] Вкладка Connections: таблица с пользователями и vhosts
- [ ] Хедер имитирует Management UI (оранжевый фон, имя ноды, версии)

## Как проверить себя

1. Дашборд открывается на вкладке Overview — видны 4 карточки с суммарными метриками.
2. Значения Publish/s и Deliver/s в карточках меняются каждые 1-2 секунды (анимация).
3. На вкладке Queues в колонке Тип видны цветные бейджи: синий "quorum", фиолетовый "stream", серый "classic".
4. Очередь dead.letter (0 consumers) показывает "⚠️ 0" красным цветом в колонке Consumers.
5. Клик на строку очереди открывает панель с деталями (Virtual Host, Memory и т.д.).
6. Повторный клик на ту же строку скрывает панель.
7. На вкладке Connections видны все подключённые сервисы с их vhost и каналами.
8. После размонтирования компонента (переключение уровня) интервал не продолжает работать.
