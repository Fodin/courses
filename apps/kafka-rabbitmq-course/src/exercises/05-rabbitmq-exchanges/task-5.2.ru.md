# Задание 5.2: Fanout Exchange

## Цель

Реализовать интерактивный симулятор Fanout Exchange, который демонстрирует широковещательную рассылку сообщений во все привязанные очереди независимо от routing key.

## Требования

1. Определи интерфейс `FanoutQueue` со свойствами: `id` (string), `name` (string), `color` (string), `bgColor` (string), `messages` (string[]), `active` (boolean).
2. Инициализируй 3 очереди по умолчанию: `email-notifications`, `push-notifications`, `analytics-events`.
3. Реализуй состояния: `queues`, `animating` (boolean), `routingKey`, `messageCount`, `log`, `newQueueName`.
4. Реализуй функцию `publish()`:
   - Берёт только активные очереди (`active: true`)
   - Устанавливает `animating = true`
   - Через 600 мс добавляет сообщение в каждую активную очередь и сбрасывает `animating`
   - Записывает в лог строку с количеством очередей и их именами
5. Реализуй функцию `toggleQueue(id)`: переключает свойство `active` очереди.
6. Реализуй функцию `addQueue()`: добавляет новую очередь с именем из `newQueueName`, назначает цвет по циклу из 3 вариантов, очищает поле ввода.
7. Реализуй функцию `removeQueue(id)`: удаляет очередь по идентификатору.
8. Реализуй функцию `clearAll()`: очищает сообщения во всех очередях и лог.
9. Отобрази схему: Producer → Exchange → список очередей с анимированными стрелками.
   - Отключённые очереди (active: false) отображаются с opacity 0.35
   - Exchange подсвечивается при анимации
   - Каждая очередь имеет кнопки "unbind"/"bind" и "✕" (удалить)
10. Предоставь поле для ввода routing key (он принимается, но игнорируется при маршрутизации) с подписью "(игнорируется)".
11. Предоставь поле ввода + кнопку "+ Bind" для добавления новой очереди.
12. Отобрази лог рассылок с временными метками.
13. Добавь блок с 4 сценариями использования Fanout Exchange.

## Чеклист

- [ ] Интерфейс `FanoutQueue` с полем `active` для управления привязкой
- [ ] Функция `publish` рассылает только в активные очереди
- [ ] Анимация задержана через `setTimeout` на 600 мс
- [ ] `toggleQueue` работает — отключённая очередь перестаёт получать сообщения
- [ ] `addQueue` с циклической сменой цветов
- [ ] `removeQueue` удаляет очередь из списка
- [ ] Поле routing key принимает ввод, но не влияет на маршрутизацию
- [ ] Enter в поле добавления очереди вызывает `addQueue`
- [ ] Лог показывает количество очередей-получателей
- [ ] Присутствует блок сценариев использования

## Как проверить себя

1. Нажмите "Broadcast" — все 3 очереди получают сообщение.
2. Нажмите "unbind" у одной очереди и снова "Broadcast" — она не получает новые сообщения.
3. Измените routing key на любое значение и нажмите "Broadcast" — результат не меняется (все активные очереди получают сообщение).
4. Добавьте новую очередь через поле ввода — она появляется в списке и сразу получает следующее сообщение.
5. Удалите очередь кнопкой "✕" — она исчезает из схемы.
