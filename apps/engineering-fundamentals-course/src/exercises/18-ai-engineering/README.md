# Уровень 18: AI-assisted инженерия

## AI как инструмент, не как замена инженера

Появление мощных языковых моделей изменило повседневную работу разработчика. Но не так, как ожидали многие: AI не заменил инженерное мышление — он изменил то, куда это мышление направляется.

Аналогия: калькулятор не убил математиков. Он освободил их от рутинных вычислений, дав больше времени на доказательства теорем и построение моделей. AI делает то же с кодом.

---

## Что AI делает хорошо

```typescript
// AI отлично справляется с boilerplate
// Промпт: "Generate a TypeScript Zod schema for a user registration form"

import { z } from 'zod'

const registrationSchema = z.object({
  email: z.string().email('Invalid email format'),
  password: z.string().min(8, 'At least 8 characters').max(100),
  name: z.string().min(2).max(100),
  acceptTerms: z.literal(true, {
    errorMap: () => ({ message: 'You must accept terms' }),
  }),
})
```

AI хорош при: генерации boilerplate, написании тестов по существующему коду, объяснении незнакомого кода, рефакторинге с чётким критерием, написании документации, переводе между языками.

---

## Что AI делает плохо

- **Архитектурные решения**: AI не знает контекст вашего бизнеса, ваши ограничения, технический долг
- **Безопасность**: AI уверенно генерирует уязвимый код — SQL-инъекции, XSS, небезопасная сериализация
- **Галлюцинации**: API изменился три месяца назад, AI помнит старую версию и называет несуществующие методы
- **Novel algorithms**: задачи, где нет публичных примеров в интернете
- **Бизнес-контекст**: почему именно это правило скидки, кто принял это архитектурное решение

## Prompt engineering для кода

Плохой промпт получает плохой код. Хороший промпт — спецификация:

```
❌ Плохо:
"напиши функцию для работы с пользователями"

✅ Хорошо:
"Напиши TypeScript функцию createUser(dto: CreateUserDto): Promise<User>.
Условия:
- email должен быть уникальным (бросай DuplicateEmailError)
- password нужно хэшировать через bcrypt с salt 12
- возвращай User без поля passwordHash
- не используй any, не добавляй комментарии
Пример DTO: { email: string, password: string, name: string }"
```

Чем точнее описание — тем меньше итераций.

## Copilot-driven development

**TDD + AI**: пишешь тест → просишь AI написать реализацию, которая его проходит. Тест — это спецификация, AI — исполнитель.

**Spec-driven**: пишешь TypeScript-интерфейсы и типы → AI реализует функции. Типы — это машиночитаемая документация.

**Review-driven**: AI пишет первую версию → инженер делает code review → итерация. Экономит время на написание, не на понимание.

⚠️ Главное правило: **AI-generated code = ваша ответственность**. Вы подписываетесь под каждой строкой, которую принимаете в кодовую базу.

---

## Ограничения и риски

| Риск | Симптом | Решение |
|------|---------|---------|
| Галлюцинации | Уверенный неправильный код | Проверять вывод, запускать тесты |
| Устаревшие знания | Несуществующие методы API | Смотреть документацию, не принимать слепо |
| Безопасность | SQL-инъекции, XSS в сгенерированном коде | Code review с фокусом на безопасность |
| Over-reliance | Потеря навыков без AI | Периодически решать задачи самостоятельно |
| Context window | AI не видит всю кодовую базу | Давать релевантный контекст явно |

## Как AI меняет инженерные практики

Кодирование ускорилось. Но *thinking time* не уменьшился — он стал важнее.

Навыки, которые стали **важнее**: code review, архитектура, понимание проблемы, specification writing, debugging AI-ошибок.

Навыки, которые стали **менее критичны**: запоминание синтаксиса, написание boilerplate, ручное переименование переменных.

AI-native проекты добавляют: `.cursorrules`, `CLAUDE.md` — файлы, которые объясняют AI контекст проекта, соглашения, запрещённые паттерны.

---

## Итог

- AI — это мощный инструмент с чёткими ограничениями, не оракул и не замена мышления
- Хороший промпт = спецификация: задача + ограничения + формат + примеры
- Всегда проверяй сгенерированный код: тесты, security review, понимание каждой строки
- Ценность инженера сместилась: от написания кода к пониманию проблемы и проверке решений
- AI-generated code — ваша ответственность, не ответственность AI
