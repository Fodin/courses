# Задание 3.2 — Конструктор динамического реестра remote

## Цель

Создать визуальный конструктор, который позволяет описать реестр dynamic remotes и генерирует готовый TypeScript-код для загрузчика с поддержкой fallback, health-check и retry.

## Требования

1. Таблица remote-модулей с возможностью добавлять и удалять строки. Каждая строка содержит:
   - Имя (text) — идентификатор remote, используется в коде
   - Primary URL (text) — основной URL `remoteEntry.js`
   - Fallback URL (text, опционально) — резервный URL при недоступности основного
   - Health-check endpoint (text, опционально) — URL для проверки доступности
   - Timeout ms (number, default 5000) — таймаут загрузки
   - Priority (number 1–10) — приоритет remote

2. Валидация полей в реальном времени:
   - Имя: обязательное, только буквы/цифры/_ (начинается с буквы), уникальное среди всех записей
   - Primary URL: обязательный, формат `http://` или `https://`
   - Fallback URL: если заполнен — должен быть валидным URL
   - Timeout: от 1000 до 30000 мс
   - Priority: от 1 до 10
   - Ошибки показываются прямо под полем

3. Генерация TypeScript-кода:
   - Интерфейс `RemoteConfig` с типами всех полей
   - Объект `remoteRegistry` со всеми записанными remote
   - Функция `loadRemote(name: string)` с retry, fallback, health-check
   - Функция `checkHealth(endpoint, timeout)`

4. Live-preview кода:
   - Обновляется при каждом изменении таблицы
   - При наличии ошибок код отображается с пониженной прозрачностью
   - Кнопка скрыть/показать код

## Checklist

- [ ] Таблица поддерживает добавление и удаление строк
- [ ] Все поля валидируются с сообщениями об ошибках
- [ ] Дублирующиеся имена подсвечиваются ошибкой в обоих полях
- [ ] Код генерируется корректно для всех заполненных remote
- [ ] При ошибках валидации код полупрозрачен
- [ ] Кнопка скрыть/показать код работает
- [ ] Предустановлены примеры данных

## Как проверить себя

- Добавьте remote с именем `my-app` → код содержит `myApp:` ... нет, имя используется как есть
- Укажите `primaryUrl: "not-a-url"` → ошибка под полем
- Укажите `timeout: 500` → ошибка (меньше 1000)
- Добавьте две строки с одинаковым именем → ошибка в обеих
- Удалите все строки → код показывает комментарий-подсказку
- Заполните все поля корректно → сгенерированный код содержит функцию loadRemote с fallback и retry

## Подсказка

Обратите внимание, что `checkHealth` использует `AbortController` для таймаута. В функции `loadRemote` перебор URLs происходит последовательно: сначала проверяется `primaryUrl`, при неудаче — `fallbackUrl`.
