# Задание 10.3 — Ревью: два независимых цикла (сложное)

## Цель

Провести полноценное ревью модуля, в котором спрятаны **два независимых** рантайм-цикла в разных слайсах, и устранить оба — каждый своим приёмом.

## Что дано

- Цикл 1: `src/features/checkout/model/cart.ts` (только для чтения) ↔ `src/features/checkout/model/pricing.ts` (редактируется). `pricing.ts` импортирует `CartItem` обычным импортом, хотя использует его только как тип.
- Цикл 2: `src/entities/product/model/catalog.ts` (только для чтения) ↔ `src/entities/product/model/product.ts` (редактируется). `product.ts` импортирует `CATALOG_VERSION` статически, хотя значение нужно только внутри тела функции.

Эти два цикла никак не связаны друг с другом — они в разных слайсах и разных слоях.

## Требования

1. Не редактируйте `cart.ts` и `catalog.ts` — они уже корректны.
2. В `pricing.ts` разорвите цикл, сделав импорт `CartItem` типовым (`import type`).
3. В `product.ts` разорвите цикл иначе: замените статический импорт `CATALOG_VERSION` на динамический `import()` внутри функции `describeProduct` (значение нужно только в момент вызова, а не при загрузке модуля).
4. После правок в проекте не должно быть ни одного рантайм-цикла импортов.

## Чеклист

- [ ] `pricing.ts` использует `import type { CartItem }`
- [ ] `product.ts` использует динамический `import('./catalog')` вместо статического импорта
- [ ] Проверка «нет рантайм-цикла» — зелёная
- [ ] Пройти квиз уровня ≥ 80%

## Как проверить себя

1. Нажмите «Проверить» — проверка должна стать зелёной.
2. Откройте «Показать эталон», если не получается.
3. Объясните себе, почему для одного цикла подошёл `import type`, а для другого — только динамический `import()` (подсказка: посмотрите, действительно ли значение используется только как тип).
