# Задание 5.2: Cache — ускорение сборки

## Цель

Создать симулятор сборки, наглядно показывающий разницу во времени выполнения пайплайна с кэшем и без. Добавить настройку `cache:key` и `cache:paths`.

## Требования

1. Отобразить два варианта пайплайна рядом: "Без кэша" и "С кэшем"
2. В каждом варианте показать шаги: `Установка зависимостей → Компиляция → Запуск тестов`
3. Реализовать кнопку "Запустить симуляцию" — анимировать выполнение шагов с задержкой
4. "Без кэша" — установка зависимостей занимает ~3 секунды (симуляция)
5. "С кэшем" — установка зависимостей занимает ~0.5 секунды (кэш hit)
6. Показывать итоговое время для каждого варианта и экономию от кэша
7. Добавить секцию настройки `cache:key` — выпадающий список или кнопки: статический ключ, `$CI_COMMIT_REF_SLUG`, `files: [package-lock.json]`
8. Добавить чекбоксы для `cache:paths` (минимум: `node_modules/`, `.npm/`, `.cache/`)
9. Показывать сгенерированный YAML кэш-конфига

## Чеклист

- [ ] Два визуальных блока "Без кэша" и "С кэшем" рядом (flex-layout)
- [ ] Минимум 3 шага в каждом пайплайне с индикатором выполнения (pending/running/done)
- [ ] Кнопка "Запустить" активирует пошаговую анимацию
- [ ] Разное время шага "Установка зависимостей" в зависимости от наличия кэша
- [ ] Итоговое время после завершения симуляции
- [ ] Блок настройки cache:key с тремя вариантами
- [ ] Чекбоксы cache:paths
- [ ] Сгенерированный YAML обновляется при изменении настроек
- [ ] После симуляции — сравнение: "Сэкономлено X секунд (Y%)"

## Как проверить себя

1. Нажми "Запустить" — оба пайплайна должны запускаться одновременно
2. "С кэшем" должен завершиться быстрее из-за шага установки зависимостей
3. Итоговые числа должны отражать реальную разницу во времени
4. Выбери `files: [package-lock.json]` в настройке key — YAML должен обновиться
5. Включи дополнительные paths — они должны появиться в YAML

## Подсказки

- Для симуляции используй `setTimeout` внутри `async` функции или цепочку через `useEffect`
- Шаги хранятся как массив объектов: `{ name, withCacheDuration, withoutCacheDuration, status }`
- `status` может быть: `'pending' | 'running' | 'done'`
- Для индикатора используй цветные точки: серая (pending), жёлтая (running), зелёная (done)
- Итоговое время считай суммой `duration` завершённых шагов
