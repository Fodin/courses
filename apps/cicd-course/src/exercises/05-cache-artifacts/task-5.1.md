# Задание 5.1: Artifacts — передача данных между джобами

## Цель

Создать интерактивную визуализацию pipeline с артефактами. Показать, как данные "текут" между джобами, и дать возможность настраивать параметры артефактов.

## Требования

1. Отобразить три джоба в виде блоков: `build` → `test` → `deploy`
2. Визуально показать, что артефакты передаются между джобами (стрелки или поток)
3. Реализовать настройку `artifacts:paths` — поле ввода или список чекбоксов с путями (`dist/`, `reports/`, `public/`)
4. Реализовать выбор `artifacts:expire_in` через кнопки: `1 hour`, `1 day`, `1 week`, `never`
5. Реализовать выбор `artifacts:when` через кнопки: `on_success`, `on_failure`, `always`
6. Показывать сгенерированный YAML-конфиг, обновляющийся в реальном времени при изменении настроек
7. При выборе `when: on_failure` визуально подсветить, что артефакт сохраняется только при падении джоба

## Чеклист

- [ ] Три блока джобов с названиями и иконками или цветовым кодированием
- [ ] Стрелки или индикаторы передачи артефактов между джобами
- [ ] Чекбоксы или кнопки для выбора paths (минимум 3 варианта)
- [ ] Кнопки выбора expire_in (4 варианта)
- [ ] Кнопки выбора when (3 варианта)
- [ ] YAML-блок с подсветкой синтаксиса (моноширинный шрифт, тёмный фон)
- [ ] YAML обновляется при каждом изменении настройки
- [ ] Подсказка или описание для каждого значения when

## Как проверить себя

1. Включи `dist/` и `reports/` в paths — убедись, что оба отображаются в YAML
2. Выбери `expire_in: never` — в YAML должно появиться `expire_in: never`
3. Выбери `when: on_failure` — визуально должно измениться отображение джоба
4. Сними все чекбоксы paths — YAML должен корректно обработать пустой список
5. Выбери разные комбинации и проверь корректность итогового YAML

## Подсказки

- Используй `useState` для хранения: `selectedPaths` (массив), `expireIn` (строка), `when` (строка)
- YAML можно собирать через template literal или функцию `buildYaml(config)`
- Для стрелок между джобами используй символы `→` или CSS `border-right` с `content`
- Для визуального отличия `on_failure` — измени цвет рамки или добавь предупреждающую иконку
