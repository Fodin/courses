# Задание 3.4 — Вынести общий тип в отдельный файл (простое)

## Цель

Освоить второй приём разрыва типового цикла — не точечный `import type`, а
физический вынос общего типа в отдельный модуль, когда тип и значение одного
модуля тянут за собой не только тип соседа.

## Что дано

- `order.ts` (редактируется) — экспортирует и тип `Order`, и значение
  `formatOrder`; реально зависит от значения `userName` из `user.ts`.
- `user.ts` (редактируется) — импортирует `Order` из `order.ts` обычным
  импортом, хотя использует его только как тип параметра.
- `types.ts` (редактируется) — пустая заготовка с `TODO`.

Импорт `order.ts` целиком в `user.ts` (пусть и ради типа) замыкает цикл, ведь
`order.ts` сам зависит от `user.ts`.

## Требования

1. Перенесите `interface Order` из `order.ts` в `types.ts`.
2. В `order.ts` подключите `Order` из `./types` через `import type`, оставив
   импорт `userName` из `./user` как значение — это реальная зависимость.
3. В `user.ts` подключите `Order` из `./types` через `import type` вместо
   импорта из `./order`.
4. Нажмите «Проверить».

## Чеклист

- [ ] `types.ts` содержит `interface Order`
- [ ] `order.ts` импортирует `Order` из `types.ts` как тип
- [ ] `user.ts` импортирует `Order` из `types.ts` как тип
- [ ] `order.ts` по-прежнему импортирует `userName` как значение
- [ ] Ни одного рантайм-цикла в графе не осталось
- [ ] Пройти квиз уровня ≥ 80%

## Как проверить себя

После переноса ни `order.ts`, ни `user.ts` не должны импортировать друг
друга напрямую — только `userName` идёт из `user.ts` в `order.ts` как
значение, а тип `Order` оба берут из общего `types.ts`.
