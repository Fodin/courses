# Задание 6.1 — ESLint import/no-cycle

## Цель

Научиться подключать и настраивать ESLint-правило `import-x/no-cycle` (или классическое `import/no-cycle`), читать его сообщения об ошибках и понимать, как чинить найденные циклы прямо по тексту предупреждения.

## Требования

1. Пройти теорию (README.md, README-long.md) уровня.
2. Понимать, как подключить правило в flat config ESLint.
3. Уметь по сообщению `Dependency cycle detected` / `Dependency cycle via ./b:3` восстановить путь цикла и найти строку, с которой он начинается.
4. Знать назначение опций `maxDepth`, `ignoreExternal`, `allowUnsafeDynamicCyclicDependency`, `disableScc`.
5. Понимать компромисс между `maxDepth` и производительностью линта на больших проектах.
6. Понимать, что правило срабатывает на этапе линта/CI, до рантайма — и почему это ценно.
7. Знать минимум два способа исправить найденный цикл по подсказке линта (import type, вынос общего, dynamic import).
8. Пройти квиз (quiz.json) уровня — не менее 80% правильных ответов.

## Чеклист

- [ ] Знаю, как включить `import-x/no-cycle` в flat config
- [ ] Умею прочитать сообщение об ошибке и найти в нём путь цикла
- [ ] Знаю назначение опций maxDepth, ignoreExternal, allowUnsafeDynamicCyclicDependency, disableScc
- [ ] Понимаю компромисс скорость/полнота при настройке maxDepth
- [ ] Знаю минимум два способа исправить цикл по сообщению линта
- [ ] Понимаю разницу между линт-проверкой и проверкой madge/dependency-cruiser (когда каждая срабатывает)
- [ ] Прошёл квиз уровня

## Как проверить себя

1. Открой Solution — там разбор реального сообщения ESLint по частям и таблица опций правила.
2. Попробуй мысленно восстановить путь цикла по примеру сообщения `Dependency cycle via ./b:3`.
3. Пройди квиз — если не набрал 80%, вернись к README-long.md.
