# Задание 0.2: Render ≠ DOM update

## Цель

Наглядно показать, что вызов функции компонента (Render) и обновление DOM (Commit) — это разные вещи. Ты построишь компонент с двумя счётчиками: один считает вызовы функции компонента, другой — реальные обновления DOM.

## Требования

1. Создать переменную `renderCount` с помощью `useRef` — она инкрементируется при каждом вызове функции компонента (просто `renderCount.current++` в теле функции).
2. Создать состояние `commitCount` — инкрементируется в `useEffect` без зависимостей (то есть при каждом Commit).
3. Отображать оба счётчика на экране.
4. Добавить кнопку **"Force re-render"** — вызывает `setState` с новым значением (например, инкрементирует вспомогательный счётчик), что всегда приводит к рендеру и коммиту.
5. Добавить кнопку **"Same value setState"** — вызывает `setState(0)` когда значение уже `0`. Студент должен увидеть, что `renderCount` может вырасти, а `commitCount` — нет.
6. Под кнопками вывести объяснение наблюдаемого поведения.

## Чеклист

- [ ] `renderCount` используется через `useRef` и инкрементируется в теле компонента
- [ ] `commitCount` инкрементируется в `useEffect(() => {...})` без массива зависимостей
- [ ] Кнопка "Force re-render" всегда увеличивает оба счётчика
- [ ] Кнопка "Same value setState" может увеличить `renderCount` без изменения `commitCount`
- [ ] Оба счётчика отображаются на экране с понятными подписями
- [ ] Есть пояснительный текст под кнопками

## Как проверить себя

1. При первой загрузке: `renderCount = 1`, `commitCount = 1`.
2. Кликни "Force re-render" несколько раз — оба счётчика растут.
3. Кликни "Same value setState" — `renderCount` может вырасти на 1, а `commitCount` останется прежним.
4. Обрати внимание: в Strict Mode React вызывает функцию компонента дважды при первом рендере — `renderCount` может быть 2 при старте. Это нормально.

> 💡 Подсказка: чтобы `renderCount` обновлялся синхронно без лишних ре-рендеров, используй `useRef`, а не `useState`. `useRef` не вызывает повторный рендер при изменении.
