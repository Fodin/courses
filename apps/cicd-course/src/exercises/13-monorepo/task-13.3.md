# Задание 13.3: Стратегии кэширования в монорепо

## Цель

Создать конструктор стратегии кэширования для монорепо. Пользователь настраивает параметры кэша для каждого сервиса и видит итоговый YAML, а также оценку эффективности кэширования.

## Требования

1. Отобразить три сервиса с разными технологическими стеками: `auth` (Node.js), `payments` (Go), `notifications` (Python)
2. Для каждого сервиса реализовать настройку:
   - **Lock-файл** (package-lock.json / go.sum / requirements.txt) — влияет на ключ кэша
   - **Политика** (pull-push / pull / push) с описанием каждой
   - **Изоляция по ветке** (добавить `$CI_COMMIT_REF_SLUG` в prefix или нет)
3. Показывать итоговый cache key для каждого сервиса
4. Показывать YAML-конфигурацию кэша для выбранных настроек
5. Добавить индикатор "конфликт ключей" — если два сервиса имеют одинаковый ключ кэша (без prefix)
6. Показывать оценку: "оптимально" / "есть проблемы" с пояснением

## Чеклист

- [ ] Три карточки сервисов с иконками технологий (N = Node, G = Go, P = Python)
- [ ] Переключатели политики кэша для каждого сервиса (pull-push / pull / push)
- [ ] Чекбокс "изолировать по ветке" для каждого сервиса
- [ ] Отображение итогового ключа кэша в виде строки
- [ ] YAML блок с полной конфигурацией cache: для всех сервисов
- [ ] Детектор конфликтов: подсветить красным если ключи совпадают
- [ ] Итоговая оценка конфигурации с пояснением

## Как проверить себя

1. Сними prefix у двух сервисов и оставь одинаковые lock-файлы → должен появиться индикатор конфликта
2. Для build-джоба выбери `pull-push`, для test-джоба выбери `pull` → оценка "оптимально"
3. Включи "изолировать по ветке" → в ключе кэша появится `$CI_COMMIT_REF_SLUG`
4. Выбери `push` без `pull-push` ни для одного сервиса → должно появиться предупреждение (кто создаст кэш?)
5. Проверь, что YAML корректно отражает все настройки

## Подсказки

- Ключ кэша формируется как `{prefix}-{hash(lockFile)}`. В симуляторе можно показать схему: `"auth-$HASH(package-lock.json)"`
- Конфликт ключей: сравниваем `prefix` сервисов — если prefix не задан (пустой), то ключи могут совпасть
- Для оценки конфигурации проверяй: есть ли хотя бы один `pull-push` (иначе кэш никто не создаёт), нет ли конфликтов prefix
- Три состояния политики можно переключать по кругу: `pull-push → pull → push → pull-push`
- Для наглядности показывай описание политики под переключателем: "Читает и обновляет кэш" / "Только читает" / "Только пишет"
