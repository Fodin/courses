# Задание 9.2 — Слайсы тянут друг друга через public API (среднее)

## Цель

Разобраться со случаем, когда каждый отдельный импорт легален (идёт через public API), но вместе два таких импорта образуют горизонтальный цикл между слайсами одного слоя.

## Что дано

- `entities/user/model/user.ts` — тип `User` и `getUserLastOrder`, которая ищет заказ через `Order`, импортированный из `entities/order` (🔒 только чтение).
- `entities/order/model/order.ts` — тип `Order`, который хранит **вложенный объект `User`**, импортированный из `entities/user`. Именно этот импорт нужно поправить.

## Требования

1. Уберите импорт `User` из `entities/order/model/order.ts`.
2. Замените поле `owner: User` на `ownerId: string`.
3. `findOrder` должна продолжать работать без изменений сигнатуры.
4. Нажмите «Проверить» — обе проверки должны стать зелёными.

## Чеклист

- [ ] `Order` хранит `ownerId: string`, а не вложенный `User`
- [ ] `entities/order/model/order.ts` больше не импортирует `entities/user`
- [ ] Проверка `noRuntimeCycles` — зелёная
- [ ] Пройти квиз уровня ≥ 80%

## Как проверить себя

Оба импорта (`order → user` и `user → order`) сами по себе шли через public API — то есть формально всё «по правилам». Но именно наличие СВЯЗИ В ОБЕ СТОРОНЫ между слайсами одного слоя и создаёт цикл. Достаточно убрать одно направление — и порядок восстановлен.
