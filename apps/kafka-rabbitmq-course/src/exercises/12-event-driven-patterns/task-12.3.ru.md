# Задание 12.3: Хореография vs Оркестрация

## Цель

Реализовать интерактивную визуализацию двух подходов к координации распределённых операций в микросервисной архитектуре: **хореографии** (сервисы реагируют на события самостоятельно) и **оркестрации** (центральный координатор управляет потоком). Студент должен анимировать оба потока параллельно и сравнить их характеристики.

## Требования

1. Определить тип `FlowStep` = объединение строковых литералов: `'order-service' | 'payment-service' | 'inventory-service' | 'shipping-service' | 'notification-service'`.
2. Определить интерфейс `ServiceNode` с полями `id: FlowStep`, `label: string`, `x: number`, `y: number`, `color: string`. Объявить константу `SERVICES_LAYOUT` из 5 узлов с координатами для SVG-диаграммы.
3. Определить интерфейс `ChoreographyStep` с полями `from: FlowStep`, `event: string`, `to: FlowStep`, `produces: string`, `delay: number`. Объявить массив `CHOREOGRAPHY_STEPS` из 4 шагов: `OrderPlaced → PaymentProcessed → StockReserved → ShipmentCreated → NotificationSent` (delay 600 мс каждый).
4. Определить интерфейс `OrchestrationStep` с полями `service: FlowStep`, `command: string`, `response: string`, `delay: number`. Объявить массив `ORCHESTRATION_STEPS` из 4 шагов: оркестратор по очереди вызывает Payment, Inventory, Shipping, Notification.
5. Реализовать состояния: `choreoStep: number` (−1 = не запущено), `orchStep: number` (−1), `choreoRunning: boolean`, `orchRunning: boolean`, `choreoLog: string[]`, `orchLog: string[]`.
6. Реализовать async-функцию `runChoreography`: сбрасывает состояние, добавляет начальную запись в лог, в цикле ждёт `step.delay` мс через `setTimeout` в Promise, обновляет `choreoStep` и добавляет строку лога для каждого шага. Отключает running по завершении.
7. Реализовать async-функцию `runOrchestration`: аналогично, но лог включает две строки на шаг — команду оркестратора к сервису и ответ сервиса. В конце добавляет «Saga завершена успешно».
8. Реализовать функцию `resetAll`, сбрасывающую все 4 состояния шагов и логи.
9. Отрисовать блок хореографии: заголовок + кнопка «Запустить» (недоступна пока идёт анимация) + SVG-диаграмма + прокручиваемый лог.
10. SVG хореографии: рисует линии между сервисами из `CHOREOGRAPHY_STEPS`; активная линия — сплошная цветная с названием события, неактивная — пунктирная серая. Узлы сервисов: активные — заливка цветом, неактивные — белые с цветной рамкой. Заголовок `ORCHESTRATOR` не нужен.
11. Отрисовать блок оркестрации: заголовок + кнопка «Запустить» + SVG-диаграмма + прокручиваемый лог.
12. SVG оркестрации: центральный прямоугольник «ORCHESTRATOR (Saga Controller)» + линии от него к каждому сервису. Активные линии — сплошные с названием команды. Узлы сервисов — аналогично хореографии.
13. Добавить кнопку «Сбросить» под обеими диаграммами.
14. Добавить блок сравнения двух подходов: два блока рядом (хореография и оркестрация) с перечислением плюсов и минусов каждого.

## Чеклист

- [ ] Тип `FlowStep` объявлен как объединение 5 строковых литералов
- [ ] Интерфейсы `ServiceNode`, `ChoreographyStep`, `OrchestrationStep` объявлены
- [ ] `SERVICES_LAYOUT` содержит 5 узлов с координатами и цветами
- [ ] `CHOREOGRAPHY_STEPS` — 4 шага с правильной цепочкой событий
- [ ] `ORCHESTRATION_STEPS` — 4 шага с командами и ответами
- [ ] `runChoreography` использует `await new Promise(r => setTimeout(r, delay))` для анимации
- [ ] `runOrchestration` генерирует 2 строки лога на каждый шаг (команда + ответ)
- [ ] Кнопки заблокированы (`disabled`) пока идёт любая анимация
- [ ] SVG хореографии: активные линии сплошные, неактивные пунктирные
- [ ] Название события отображается на активной линии
- [ ] SVG оркестрации: центральный ORCHESTRATOR + линии к сервисам с командами
- [ ] Узлы: активный = заливка цветом сервиса + белый текст, неактивный = белый фон + цветной текст
- [ ] Кнопка «Сбросить» возвращает всё в начальное состояние
- [ ] Блок сравнения показывает плюсы и минусы обоих подходов

## Как проверить себя

1. Нажмите «Запустить» под «Хореографией» — анимация идёт ~2.4 секунды: узлы последовательно окрашиваются, лог заполняется строками вида `[Payment Service] Получил OrderPlaced → обрабатывает → публикует PaymentProcessed`.
2. Нажмите «Запустить» под «Оркестрацией» — в логе чередуются команды оркестратора и ответы сервисов. Последняя строка — «Saga завершена успешно».
3. Во время анимации обе кнопки неактивны. После завершения хореографии можно запустить оркестрацию.
4. Нажмите «Сбросить» — все узлы становятся белыми, логи очищаются, шаги сбрасываются в −1.
5. Убедитесь, что в SVG хореографии 4 линии между сервисами, а в SVG оркестрации 4 линии от центрального ORCHESTRATOR к сервисам.
6. Проверьте блок сравнения: у хореографии указаны «Нет единой точки отказа» и «Сложно отследить поток»; у оркестрации «Прозрачный поток управления» и «Оркестратор — узкое место».
