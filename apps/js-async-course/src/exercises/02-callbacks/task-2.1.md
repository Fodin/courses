# Задание 2.1: Callback Hell Визуализатор

## Цель

Построить интерактивный визуализатор pipeline из 5 последовательных асинхронных операций, реализованных через вложенные error-first колбэки. Показать "пирамиду" вложенности, порядок выполнения на timeline и наглядно продемонстрировать, что происходит при ошибке на любом из шагов.

## Требования

1. **Pipeline из 5 шагов** с вложенными колбэками в стиле error-first `(err, result)`:
   - `getUser(userId, cb)` — загрузка профиля пользователя
   - `getPosts(user, cb)` — получение постов
   - `getComments(posts, cb)` — загрузка комментариев
   - `filterSpam(comments, cb)` — фильтрация спама
   - `sendReport(filtered, cb)` — отправка отчёта
   - Каждый шаг симулирует задержку через `setTimeout`

2. **Визуальная пирамида** — каждый шаг отображается с отступом пропорционально глубине вложенности; у каждого шага свой цвет; активный шаг подсвечивается (glow-эффект)

3. **Статусы шагов**: `idle` (ожидание), `running` (выполняется), `done` (успешно), `error` (ошибка)

4. **Timeline** справа: лог событий с временными метками (`+Xms`), отображающий порядок выполнения

5. **Переключатель ошибки**: кнопки "OK", "#1"–"#5" позволяют задать, на каком шаге произойдёт сбой; при ошибке последующие шаги не запускаются

6. **Предупреждение про `if(err)`**: при возникновении ошибки появляется объяснение, что без `return` после проверки `err` код продолжил бы выполнение с `undefined`

7. **Кнопки**: "Запустить" (запускает pipeline с текущими настройками), "Сброс" (очищает состояние)

## Чеклист

- [ ] Компонент называется `Task2_1` и экспортируется по умолчанию
- [ ] `useLanguage` импортирован, `t('task.2.1')` используется в заголовке
- [ ] Реализованы именно вложенные колбэки — не промисы, не async/await
- [ ] Error-first сигнатура: `(err, result)` — первый аргумент всегда ошибка
- [ ] Каждый шаг имеет собственный цвет, отступ увеличивается с каждым уровнем
- [ ] При ошибке на шаге N шаги N+1..5 остаются в статусе `idle`
- [ ] Timeline показывает события в хронологическом порядке с `+Xms` метками
- [ ] Кнопки переключения ошибки корректно меняют поведение pipeline
- [ ] Нет TypeScript-ошибок типа `any`

## Как проверить себя

1. Нажмите "Запустить" с настройкой "OK" — все 5 шагов последовательно перейдут в `done`
2. Убедитесь, что каждый следующий шаг стартует только после завершения предыдущего
3. Выберите "#3", нажмите "Запустить" — шаги 1 и 2 должны пройти, шаг 3 перейти в `error`, шаги 4–5 остаться `idle`
4. Проверьте timeline — события должны появляться с нарастающими временными метками
5. Убедитесь, что пирамида наглядна: каждый следующий блок сдвинут правее предыдущего
