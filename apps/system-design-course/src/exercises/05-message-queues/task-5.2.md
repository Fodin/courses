# Задание 5.2: Визуализатор очереди сообщений

## Цель

Построить интерактивный визуализатор, который демонстрирует работу очереди сообщений: producer и consumer rates, глубину очереди, backpressure, DLQ и режимы доставки.

## Требования

1. Реализуйте настройку параметров через кнопки/слайдеры:
   - **Producer rate** — сколько сообщений в секунду генерируется (1, 5, 10, 20)
   - **Consumer rate** — сколько сообщений в секунду обрабатывается (1, 5, 10, 20)
   - **Consumer count** — количество потребителей (1, 2, 3, 5)
   - **Error rate** — процент ошибок обработки (0%, 10%, 30%, 50%)
2. Визуализируйте состояние системы:
   - Глубина очереди (прогресс-бар с числом сообщений)
   - Количество обработанных сообщений
   - Количество сообщений в DLQ (при ошибках — после 3 retry)
   - Статус: нормальный / backpressure / перегрузка
3. Реализуйте переключение режимов доставки:
   - **At-most-once** — сообщение может потеряться при ошибке
   - **At-least-once** — сообщение retry при ошибке (может дублироваться)
4. Автоматическая симуляция через setInterval (кнопки Start/Stop/Reset)
5. Покажите лог последних событий (produced, consumed, error, DLQ)

## Чеклист

- [ ] Настраиваемый producer rate (кнопки)
- [ ] Настраиваемый consumer rate и count
- [ ] Настраиваемый error rate
- [ ] Визуализация глубины очереди (прогресс-бар + число)
- [ ] Счётчик обработанных сообщений
- [ ] DLQ при ошибках (после 3 retry)
- [ ] Переключение at-most-once / at-least-once
- [ ] Индикатор backpressure при переполнении
- [ ] Кнопки Start / Stop / Reset
- [ ] Лог последних событий

## Как проверить себя

1. Producer rate > consumer rate * count — очередь растёт, backpressure
2. Producer rate < consumer rate * count — очередь пустеет
3. Error rate > 0 с at-least-once — сообщения retry, часть уходит в DLQ
4. Error rate > 0 с at-most-once — сообщения теряются (нет DLQ)
5. Reset сбрасывает все счётчики и очередь
