# Задание 3.5 — Общий types.ts для двух модулей со взаимными типами (среднее)

## Цель

Научиться распознавать симметричную типовую связь (оба модуля ссылаются друг
на друга в собственных интерфейсах) и решать её единым приёмом — общим файлом
типов — вместо двух точечных `import type` в разные стороны.

## Что дано

- `a.ts` (редактируется) — `interface A { partner: B }`, импортирует `B` из
  `b.ts` обычным импортом.
- `b.ts` (редактируется) — `interface B { partner: A }`, импортирует `A` из
  `a.ts` обычным импортом.
- `types.ts` (редактируется) — пустая заготовка с `TODO`.

Оба модуля зависят друг от друга только ради чужого типа — идеальный кандидат
на общий файл типов.

## Требования

1. Перенесите оба интерфейса (`A` и `B`) в `types.ts`.
2. В `a.ts` подключите `A` и `B` из `./types` через `import type`.
3. В `b.ts` подключите `A` и `B` из `./types` через `import type`.
4. `a.ts` и `b.ts` не должны импортировать друг друга напрямую.
5. Нажмите «Проверить».

## Чеклист

- [ ] `types.ts` содержит оба интерфейса — `A` и `B`
- [ ] `a.ts` подключает типы из `types.ts` через `import type`
- [ ] `b.ts` подключает типы из `types.ts` через `import type`
- [ ] Ни одного рантайм-цикла в графе не осталось
- [ ] Пройти квиз уровня ≥ 80%

## Как проверить себя

Если между `a.ts` и `b.ts` нет ни одного прямого импорта (только оба тянут
типы из `types.ts`), а функции `describeA`/`describeB` продолжают собираться —
рефакторинг сделан верно.
