# Задание 1.1: Ловушки мутаций

## Цель

Наглядно показать разницу между прямой мутацией объекта и созданием иммутабельной копии.
Понять, почему мутация опасна для разделяемых объектов и как React реагирует на изменения ссылок.

## Требования

1. Объявите объект `user` типа `{ name: string; age: number; address: { city: string } }`
   с начальными значениями `{ name: 'Alice', age: 30, address: { city: 'Moscow' } }`.
2. Отобразите текущий объект как карточку с тремя полями.
3. Реализуйте кнопку "Мутировать напрямую" — изменяет `user.age = 31` без создания копии.
4. Реализуйте кнопку "Создать копию" — создаёт новый объект через spread (`{ ...user, age: user.age + 1 }`).
5. После каждого действия выводите:
   - Значения оригинала (до и после действия)
   - Значения изменённого объекта
   - Результат `original === copy` (referential equality)
   - Список изменившихся полей
6. Для мутации — предупреждение красным "Оригинал испорчен".
7. Для копии — сообщение зелёным "Оригинал цел".
8. Кнопка "Сбросить" возвращает начальное состояние.

## Чеклист

- [ ] Объект `user` имеет вложенное поле `address`
- [ ] Кнопка мутации изменяет поле напрямую через присвоение
- [ ] Кнопка копии использует spread оператор
- [ ] После мутации `original === copy` возвращает `true`
- [ ] После копии `original === copy` возвращает `false`
- [ ] Показаны изменившиеся поля
- [ ] Предупреждение/успех визуально отличаются цветом
- [ ] Сброс восстанавливает начальное состояние

## Как проверить себя

Нажмите "Мутировать напрямую" — вы должны увидеть что `original === copy: true`,
то есть это один и тот же объект, оригинал испорчен.

Нажмите "Сбросить", затем "Создать копию" — вы должны увидеть `original === copy: false`,
оригинал с `age: 30` остался нетронутым, в копии `age: 31`.

Подсказка: при мутации React не видит изменения, так как ссылка та же —
поэтому вам понадобится принудительно вызвать ре-рендер (например, `setUser({ ...mutated })`).
