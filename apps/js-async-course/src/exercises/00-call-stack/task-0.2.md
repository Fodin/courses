# Задание 0.2: Блокировка главного потока

## Цель

Наглядно продемонстрировать, что происходит с браузером во время тяжёлых вычислений в главном потоке — и как можно их разбить на чанки, чтобы UI оставался отзывчивым. Компонент должен дать студенту прочувствовать разницу на практике.

## Требования

1. **Режим "Синхронная блокировка"** — запускает `fibonacci(42)` синхронно:
   - Анимированный спиннер (вращающиеся символы) должен **замерзать** во время вычисления
   - Кнопка "Кликни меня" с счётчиком — в режиме блокировки на клики не реагирует
   - После завершения показывается результат и время блокировки в миллисекундах
   - Перед запуском показывается подсказка о том, что нужно сначала покликать

2. **Режим "Чанкинг через setTimeout"** — тот же fibonacci, но итеративно с паузами:
   - Вычисление разбито на чанки по ~5000 шагов
   - Между чанками вызывается `setTimeout(fn, 0)` для уступки управления Event Loop
   - Спиннер продолжает анимироваться (UI не заморожен)
   - Кнопка "Кликни меня" реагирует на клики во время вычисления
   - Показывается прогресс: `Вычислено до fib(N) из fib(500000)...`

3. **Переключение режимов** через вкладки (tabs):
   - При переключении состояние сбрасывается (результат, счётчик кликов, прогресс)
   - Кнопка запуска меняет текст и цвет в зависимости от режима

4. **Показатели** — после завершения отображаются:
   - Результат вычисления (или сообщение о размере числа)
   - Время выполнения в миллисекундах
   - Пояснение: было ли блокирование или нет

5. **Код** — оба варианта алгоритма показываются в компоненте с подсветкой через `<pre>`:
   - Синхронная рекурсия с комментарием `// ~3.5 млрд операций`
   - Итеративный чанкинг с `setTimeout` и комментарием `// yield!`

6. **Кнопка "Сброс"** — очищает все состояния, возвращает к начальному виду

## Чеклист

- [ ] Компонент называется `Task0_2` и экспортируется по умолчанию
- [ ] `useLanguage` импортирован и `t('task.0.2')` используется в заголовке
- [ ] Спиннер анимируется через `setInterval` и останавливается при блокировке
- [ ] `fibSlow(42)` вызывается синхронно и реально блокирует поток (не через `async`)
- [ ] Чанковый алгоритм использует `setTimeout(fn, 0)` для уступки управления
- [ ] Счётчик кликов обновляется при нажатии во время чанкового режима
- [ ] Время блокировки измеряется через `performance.now()`
- [ ] Кнопка "Запустить" блокируется (disabled) во время выполнения
- [ ] Нет TypeScript-ошибок типа `any`

## Как проверить себя

1. Откройте компонент, режим "Синхронная блокировка"
2. Нажмите кнопку "Кликни меня" несколько раз — счётчик растёт
3. Нажмите "Запустить fibonacci(42)"
4. **Немедленно** кликните на "Кликни меня" несколько раз
5. Убедитесь: спиннер замер, клики не зарегистрированы до завершения вычисления
6. Переключитесь на вкладку "Чанкинг через setTimeout"
7. Нажмите "Запустить fibonacci(500000)"
8. Активно кликайте "Кликни меня" — счётчик должен расти во время вычисления
9. Спиннер продолжает анимироваться — UI отзывчив
