# Задание 10.2: Vault / External Secret Managers — интеграция и динамические секреты

## Цель

Создать интерактивную визуализацию процесса аутентификации через JWT/OIDC в HashiCorp Vault и получения секретов. Показать разницу между статическими и динамическими секретами, а также сравнить подходы к интеграции с AWS Secrets Manager.

## Требования

1. Реализовать **пошаговую анимацию** JWT/OIDC flow: (1) GitLab генерирует JWT → (2) джоб отправляет JWT в Vault → (3) Vault проверяет подпись через GitLab OIDC → (4) Vault проверяет политику → (5) Vault выдаёт временный токен → (6) джоб читает секрет. Каждый шаг активируется кнопкой "Следующий шаг".
2. Реализовать **переключатель** "Статический секрет / Динамический секрет". Для статического: показать YAML с `VAULT_TOKEN` в переменных GitLab и объяснить проблему долгоживущего токена. Для динамического: показать YAML с `id_tokens` и TTL.
3. Показывать **Timeline жизни секрета**: для статического — бесконечная полоса (красная), для динамического — ограниченная TTL полоса (зелёная) с отметкой "автоматически отозван".
4. Реализовать **выбор secrets engine**: `KV` (ключ-значение), `AWS` (временные IAM credentials), `Database` (временные DB пользователи). Для каждого показывать пример команды vault и что возвращается.
5. Показывать **YAML-конфиг** для GitLab CI с `id_tokens` блоком, который обновляется при изменении параметров.

## Чеклист

- [ ] Пошаговая анимация 6 шагов JWT flow с кнопкой "Следующий шаг"
- [ ] Визуальные блоки для каждого участника: GitLab, Runner, Vault, GitLab OIDC
- [ ] Переключатель статический / динамический секрет
- [ ] Timeline с визуальным отображением жизни секрета (конечный vs бесконечный)
- [ ] Три кнопки выбора secrets engine с описанием
- [ ] Пример vault-команды для получения секрета из выбранного engine
- [ ] YAML-блок с id_tokens конфигурацией
- [ ] Индикатор текущего шага (1/6, 2/6, ...)

## Как проверить себя

1. Пройди все 6 шагов анимации — каждый шаг должен выделять активного участника
2. Переключись на "Статический" — должен появиться YAML с VAULT_TOKEN и предупреждение об опасности
3. Переключись на "Динамический" — YAML должен содержать `id_tokens:` блок, timeline должен быть конечным
4. Выбери secrets engine `AWS` — пример должен показывать `vault write aws/creds/...` и возвращаемые `access_key`/`secret_key`
5. Выбери `Database` — пример должен показывать создание временного пользователя PostgreSQL

## Подсказки

- Используй `useState` для: `step` (0-6), `secretType` ('static'|'dynamic'), `engine` ('kv'|'aws'|'database')
- Шаги анимации: массив объектов `{ actor, description, highlight }`. При переходе к шагу N — выделяй `highlight` блок
- Timeline: `div` с фиксированной шириной 100%, внутри — цветная полоса. Для динамического — полоса 60% ширины с иконкой "✓ отозван"
- Участники flow: GitLab UI (синий), Runner (серый), Vault (зелёный), GitLab OIDC endpoint (фиолетовый)
