# Задание 3.2: Key Chaos

## Цель

Воспроизвести и исправить классический баг "протекания" state при использовании index как key. Список задач содержит `<input>` внутри каждого элемента. При удалении элемента из середины значения input'ов "съезжают". Студент находит причину на уровне reconciliation и исправляет её правильными keys.

## Требования

1. Реализовать список из 5 задач, где каждая задача содержит:
   - Название задачи (`span` или `p`)
   - Поле `<input>` с `placeholder="Заметки..."`
   - Кнопку "Удалить" для удаления этой задачи
2. **Намеренно** использовать `index` как key (или вообще без key — получишь warning, но баг тот же).
3. Добавить кнопку "Добавить задачу в начало" — она вставляет новую задачу перед всеми остальными.
4. Добавить панель объяснения бага: что произошло и почему.
5. После воспроизведения бага — исправить: заменить `key={index}` на `key={task.id}`, где `id` — стабильный уникальный идентификатор.
6. Показать рядом две версии (с багом и без) для наглядного сравнения.

## Чеклист

- [ ] Список задач с input внутри каждого элемента
- [ ] Версия "с багом" использует index как key
- [ ] Версия "без бага" использует стабильный id как key
- [ ] Обе версии показаны одновременно (side by side или с переключателем)
- [ ] Кнопка "Удалить" корректно удаляет задачу
- [ ] Кнопка "Добавить в начало" вставляет в позицию 0
- [ ] В версии с багом input values "съезжают" при удалении/вставке
- [ ] В версии без бага input values остаются у правильных задач

## Как проверить себя

1. В версии "с багом" введи в input первых трёх задач: "note-A", "note-B", "note-C"
2. Удали первую задачу
3. Наблюдай: "note-A" появилось у второй задачи, "note-B" — у третьей. Это баг.
4. Добавь задачу кнопкой "Добавить в начало" — input'ы снова "съедут"
5. Повтори шаги 1-4 в версии "без бага" — input'ы всегда остаются у правильных задач
6. Объясни себе: почему React решил, что input с "note-A" принадлежит второй задаче?
