# Задание 13.3: Performance Audit (Capstone)

## Задание

Перед вами дашборд аналитики с реальными проблемами производительности. Компонент уже
написан, но работает плохо: лишние ре-рендеры, устаревшие паттерны, неправильные ключи.
Ваша задача — провести полный performance audit, найти ВСЕ пять проблем и исправить каждую.

---

## Цель

Применить все знания курса: effect chains, React.memo, state colocation, key, useSyncExternalStore.
Это финальное задание курса — синтез всех изученных паттернов.

---

## Проблемы для поиска и исправления

### Проблема 1: Effect Chain для derived data
В компоненте есть цепочка эффектов: `rawData` → `useEffect` → `setFilteredData` →
`useEffect` → `setSortedData`. Каждый эффект вызывает дополнительный рендер.

**Как исправить:** заменить на `useMemo` — вычислять `filteredData` и `sortedData`
прямо во время рендера, без эффектов и без дополнительных state.

### Проблема 2: Inline objects ломают React.memo
`DataTable` обёрнут в `React.memo`, но всё равно ре-рендерится. Причина:
родитель передаёт `columns={[...]}` и `style={{ ... }}` — новые объекты каждый рендер.

**Как исправить:** вынести `columns` и `style` за пределы компонента (константы).

### Проблема 3: State слишком высоко
`selectedRowId` хранится в корне дашборда, хотя используется только в `RowDetailPanel`.
При выборе строки ре-рендерится весь дашборд включая `MetricCards` и `DataTable`.

**Как исправить:** State Colocation — переместить `selectedRowId` в `RowDetailPanel`
(или создать `SelectionSection`, который объединяет таблицу и панель деталей).

### Проблема 4: Нет key при рендере списка
`MetricCards` рендерит список метрик без `key`. React использует индекс по умолчанию,
что приводит к неправильному reconciliation при изменении порядка метрик.

**Как исправить:** добавить `key={metric.id}` — стабильный уникальный идентификатор.

### Проблема 5: Подписка через useEffect вместо useSyncExternalStore
`LiveStatusIndicator` подписывается на внешний store (статус соединения) через `useEffect`.
В Concurrent Mode это создаёт tearing — компонент может показывать устаревший статус.

**Как исправить:** использовать `useSyncExternalStore` с правильными `subscribe` и `getSnapshot`.

## Подсказки

- Effect chain признак: `useEffect` с `setState` внутри, где этот state мог быть useMemo
- React.memo не работает: добавьте console.log в компонент — если он логирует при неизменных props,
  ищите inline объекты в вызывающем коде
- useSyncExternalStore: первый аргумент — subscribe(callback), второй — getSnapshot() → значение
- Для симуляции внешнего store: создайте объект с `subscribe`, `getSnapshot`, `setState` методами
- Проверяйте render counters: увеличение без причины = найдена проблема
