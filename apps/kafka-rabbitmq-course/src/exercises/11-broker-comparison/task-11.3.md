# Задание 11.3: Decision Tree — выбор брокера

## Цель

Реализовать интерактивное дерево решений для выбора брокера сообщений. Студент построит пошаговый wizard с вопросами "Да/Нет", который в зависимости от ответов ведёт к одному из 6 брокерных рекомендаций. Задание развивает навык проектирования state-машин и понимание архитектурных trade-offs.

## Требования

1. Определить интерфейс `TreeNode` с полями: `id: string`, `question?: string`, `yes?: string`, `no?: string` (ID следующих узлов), `result?: string` (название брокера, если терминальный), `broker?: string`, `color?: string`, `explanation?: string`, `useCases?: string[]`.
2. Заполнить объект `TREE_NODES: Record<string, TreeNode>` с не менее чем 10 узлами:
   - Стартовый `root` — вопрос про гарантированную доставку
   - Вопрос про replay/повторное чтение
   - Вопрос про throughput > 500K msg/s
   - Вопрос про tiered storage / geo-replication
   - Вопрос про операционную сложность
   - Вопрос про сложную маршрутизацию / DLQ / RPC
   - Вопрос про наличие Redis в стеке
   - Вопрос про критичность latency < 1ms
   - 6 терминальных узлов с результатами: Kafka, Pulsar, Kafka (small), NATS JetStream, RabbitMQ, Redis Streams, NATS Core
3. Каждый терминальный узел должен содержать: `result` (название), `color`, `explanation` (почему этот выбор, 2-3 предложения), `useCases` (массив из 3-5 примеров).
4. Реализовать состояния: `path: string[]` (история пройденных узлов, начинается с `['root']`), `answers: Record<string, boolean>` (ответы на каждый вопрос).
5. Реализовать функцию `answer(yes: boolean)`: добавляет в `path` следующий узел, записывает ответ в `answers`.
6. Реализовать функцию `back()`: удаляет последний узел из `path`, удаляет ответ для предпоследнего узла.
7. Реализовать функцию `reset()`: сбрасывает `path` к `['root']`, очищает `answers`.
8. Отрисовать "хлебные крошки" (breadcrumbs): путь пройденных шагов с ответами (Да/Нет зелёным/красным). Текущий шаг — белым.
9. Отрисовать текущий узел:
   - Если вопрос: шаг N из ~5, текст вопроса крупно, кнопки "Да" (зелёная) и "Нет" (красная).
   - Если результат: заголовок "Рекомендация", название брокера цветом, объяснение, список use cases.
10. Кнопки навигации: "Назад" (если `path.length > 1`) и "Начать заново" (если `path.length > 1`).
11. Внизу — статичная сетка всех брокеров с кратким описанием (5 карточек).

## Чеклист

- [ ] Интерфейс `TreeNode` определён со всеми опциональными полями
- [ ] `TREE_NODES` содержит не менее 10 узлов (4+ вопроса + 6 результатов)
- [ ] Каждый результат-узел имеет explanation и useCases
- [ ] `path` начинается с `['root']`, корректно пополняется при ответах
- [ ] `answers` записывает true/false для каждого пройденного вопроса
- [ ] Кнопки "Да" (зелёная) и "Нет" (красная) отображаются для вопросов
- [ ] При нажатии "Да"/"Нет" переход к следующему узлу
- [ ] Breadcrumbs показывают пройденный путь с ответами
- [ ] Терминальный узел: показывает рекомендацию с explanation и use cases
- [ ] Кнопка "Назад" корректно возвращает к предыдущему вопросу
- [ ] "Начать заново" сбрасывает к первому вопросу
- [ ] Сетка 5 брокеров снизу отображается всегда
- [ ] Рамка текущего узла: цветная для результата, серая для вопроса

## Как проверить себя

1. При открытии виден вопрос "Нужна ли гарантированная доставка?". Нажмите "Нет" — должен появиться результат NATS Core.
2. Нажмите "Начать заново". Нажмите "Да" → "Да" (replay) → "Да" (высокий throughput) → "Да" (tiered storage) — результат должен быть Apache Pulsar.
3. Нажмите "Назад" — вернётесь на вопрос про tiered storage, ответ Да ещё виден в breadcrumbs.
4. Нажмите "Нет" — результат Apache Kafka.
5. Пройдите путь: Да → Да → Нет → Нет (нет Kafka/Redis опыта) → Да (простой деплой) — результат NATS JetStream.
6. Пройдите путь: Да → Нет (не нужен replay) → Да (сложная маршрутизация) — результат RabbitMQ.
7. Убедитесь, что во всех результатах есть объяснение и как минимум 3 use case.
