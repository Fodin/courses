# Задание 12.2: postMessage и Structured Clone

## Цель

Визуально продемонстрировать, какие типы данных можно передавать через `postMessage`, а какие вызовут `DataCloneError`. Показать, что алгоритм Structured Clone создаёт глубокую копию — изменения в Worker не затрагивают оригинал в главном потоке.

## Требования

1. **Интерактивная таблица типов данных:** кнопки для выбора типа — Object, Array, Date, Map, Error, Function, DOM Node. Кнопки цветно маркированы: ✓ (зелёный) — клонируется, ✗ (красный) — DataCloneError.

2. **Для поддерживаемых типов (Object, Array, Date, Map, Error):**
   - Создать реальный Worker через Blob URL
   - Отправить значение через `postMessage`
   - Worker изменяет данные (например, меняет поле `name`)
   - Отобразить в логе: что отправили, что Worker получил, что оригинал НЕ изменился
   - Явно показать принцип deep clone через лог

3. **Для неподдерживаемых типов (Function, DOM):**
   - НЕ создавать Worker
   - Отобразить в логе: "DataCloneError: <Тип> не может быть клонирован"
   - Пояснение почему это происходит

4. **Лог** с цветным выводом: синий = отправка, зелёный = получение, жёлтый = информация, красный = ошибка

5. **Информационный блок** под таблицей — объяснение для выбранного типа

## Как проверить себя

1. Выберите "Object" и нажмите "Отправить в Worker"
2. Лог должен показать: отправили `{name: "Alice", ...}`, Worker изменил поле, оригинал остался `{name: "Alice", ...}`
3. Выберите "Date" — лог должен показать ISO-строку переданного Date
4. Выберите "Function" и нажмите "Отправить"
5. Должен появиться красный лог: DataCloneError (Worker не создаётся)
6. Выберите "DOM Node" — аналогично
