# Задание 1.1: Симулятор Event Loop

## Цель

Построить пошаговый визуализатор, который показывает, как задачи перемещаются между четырьмя зонами: Call Stack, Web APIs, Microtask Queue и Macrotask Queue — на конкретном примере кода.

## Требования

1. **Четыре визуальные области** — Call Stack, Web APIs, Microtask Queue (Promise), Macrotask Queue (setTimeout) — каждая своим цветом
2. **Пример кода** — отображается слева со строками, текущий шаг не обязательно подсвечен построчно (достаточно описания)
3. **Шаговая анимация** — кнопка "Шаг вперёд" двигает симуляцию вперёд; в каждой области показываются актуальные "карточки" задач
4. **Описание шага** — под областями выводится текстовое пояснение того, что происходит на текущем шаге
5. **Вывод консоли** — отдельный блок показывает, что уже напечатано в консоль
6. **Кнопка Сброс** — возвращает к начальному состоянию
7. **Итоговое объяснение** — на последнем шаге выводится итог: почему именно такой порядок (1 → 4 → 3 → 2)

## Чеклист

- [ ] Компонент называется `Task1_1` и экспортируется по умолчанию
- [ ] `useLanguage` импортирован, `t('task.1.1')` используется в заголовке
- [ ] Четыре визуальные зоны отображаются одновременно
- [ ] На каждом шаге в нужных зонах появляются / исчезают карточки задач
- [ ] Блок "Вывод в консоль" обновляется по мере выполнения шагов
- [ ] Пояснение шага меняется при каждом нажатии "Шаг вперёд"
- [ ] Кнопка "Шаг вперёд" заблокирована на последнем шаге
- [ ] Кнопка "Сброс" возвращает к шагу 0
- [ ] Нет TypeScript-ошибок типа `any`

## Как проверить себя

1. Откройте компонент — должны быть видны четыре пустые зоны и исходный код
2. Нажмите "Шаг вперёд" — в Call Stack должна появиться карточка `log('1')`, в выводе — `1`
3. Нажимайте до конца — порядок вывода должен быть `1 → 4 → 3 → 2`
4. Убедитесь, что `Promise` (микротаска) выводится РАНЬШЕ `setTimeout` (макротаска)
5. На последнем шаге все очереди должны быть пусты
6. Нажмите "Сброс" — всё вернётся в начало
