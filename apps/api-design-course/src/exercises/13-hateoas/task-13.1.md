# Задание 13.1: Навигатор по гипермедиа

## Цель

Реализовать интерактивный навигатор, который ходит по API **только через ссылки `_links`**, не зная URL заранее. Студент стартует с точки входа и кликает по доступным переходам — как клиент HATEOAS, ведомый сервером.

## Требования

1. Заранее заданный «мок-API»: набор ресурсов-состояний, у каждого данные + `_links` (карта переходов `rel → { href, method }`)
2. Старт с точки входа (например, заказ в состоянии `pending`); показать текущий ресурс как форматированный JSON
3. Под ресурсом — кнопки по числу доступных `_links` (кроме `self`): подпись кнопки = `rel` + method + href
4. Клик по ссылке выполняет «переход»: меняет текущий ресурс на тот, куда ведёт `rel`, и перерисовывает новый набор ссылок
5. Хлебные крошки / лог переходов: какие `rel` были пройдены (`pay → ship → ...`)
6. Кнопка «Сбросить» возвращает к точке входа
7. Подсветить `self` отдельно (это не действие, а адрес самого ресурса)

## Чеклист

- [ ] Текущий ресурс показан как JSON с блоком `_links`
- [ ] Кнопки переходов строятся из `_links` (не захардкожены вручную)
- [ ] Клик меняет состояние ресурса и набор доступных ссылок
- [ ] `self` отделён от действий
- [ ] Лог пройденных переходов (`rel`)
- [ ] Кнопка сброса к точке входа
- [ ] Терминальное состояние (например, `cancelled`) не имеет действий, кроме `self`

## Данные для мок-API (эталон)

```
pending  → данные { status: "pending" }, _links: self, pay, cancel
paid     → данные { status: "paid" },    _links: self, ship, refund
shipped  → данные { status: "shipped" }, _links: self, track, return
cancelled→ данные { status: "cancelled"}, _links: self
```

Переходы: `pay`: pending→paid, `cancel`: pending→cancelled, `ship`: paid→shipped, `refund`: paid→cancelled.

## Как проверить себя

1. Старт — `pending`, видны кнопки `pay` и `cancel`.
2. Нажми `pay` — ресурс стал `paid`, кнопки сменились на `ship` и `refund`.
3. Нажми `ship` — `shipped`, кнопки `track`/`return`.
4. Сбрось и нажми `cancel` — `cancelled`, действий нет, только `self`.

## Подсказки

- Состояние: `currentKey` (ключ текущего ресурса) и `history` (массив пройденных `rel`).
- Мок-API — объект `{ [key]: { data, links: { rel: { href, method, to } } } }`, где `to` — ключ следующего ресурса.
- Кнопки: `Object.entries(resource.links).filter(([rel]) => rel !== 'self')`.
- Переход: `setCurrentKey(link.to)` + дописать `rel` в history.
