# Задание 9.2: flushSync Demo

## Цель

Понять, когда автоматический батчинг мешает и как `flushSync` позволяет принудительно "сбросить" обновления состояния синхронно. Классический пример — автоскролл чата: без `flushSync` DOM обновляется после скролла и мы не попадаем в конец списка.

## Требования

1. Реализовать компонент `FlushSyncDemo` с двумя чатами рядом (side-by-side): "Без flushSync" и "С flushSync"
2. Каждый чат содержит:
   - Список сообщений (`div` с фиксированной высотой и `overflow-y: auto`)
   - `ref` на контейнер сообщений
   - Общее поле ввода и кнопку "Отправить" (для каждого чата отдельно)
3. **Левый чат (без `flushSync`)**:
   - При отправке: `setMessages(prev => [...prev, newMessage])`, затем `ref.current.scrollTop = ref.current.scrollHeight`
   - Скролл вызывается ДО того как React применил новое состояние — в DOM ещё нет нового сообщения, высота не изменилась, скролл не работает точно
4. **Правый чат (с `flushSync`)**:
   - Импорт: `import { flushSync } from 'react-dom'`
   - При отправке: `flushSync(() => { setMessages(prev => [...prev, newMessage]) })`, затем `ref.current.scrollTop = ref.current.scrollHeight`
   - `flushSync` синхронно применяет обновление — DOM уже содержит новое сообщение, `scrollHeight` корректный
5. Добавить в каждый чат счётчик "Рендеров: N" (через `useRef`) и статус "Последний скролл: точный / неточный" (через замер `scrollTop === scrollHeight - clientHeight`)
6. Начальный список содержит не менее 5 сообщений, чтобы область прокрутки была активной с самого начала

## Чеклист

- [ ] `flushSync` импортируется из `'react-dom'`, не из `'react'`
- [ ] Левый чат: `setMessages` вызывается без `flushSync`, скролл после
- [ ] Правый чат: `setMessages` обёрнут в `flushSync(...)`, скролл после
- [ ] Оба контейнера имеют фиксированную высоту и `overflow-y: auto`
- [ ] `ref` привязан к контейнеру сообщений (не к странице)
- [ ] Счётчик рендеров отображается в каждом чате
- [ ] Визуально видно: правый чат всегда прокручивается до конца, левый — нет при большом кол-ве сообщений
- [ ] Нет `useEffect` для скролла — скролл вызывается напрямую в обработчике события

## Как проверить себя

1. Добавьте 10+ сообщений в левый чат — время от времени последнее сообщение будет "не доскроллено"
2. Добавьте те же 10+ сообщений в правый чат — всегда в конце
3. Добавьте очень длинное сообщение в левый чат — разница в скролле станет наиболее заметной
4. Откройте DevTools → Console и добавьте лог в обработчик: выведите `scrollTop` и `scrollHeight` до и после скролла — в левом чате `scrollHeight` ещё не обновлён в момент вызова
5. Убедитесь, что счётчик рендеров одинаковый в обоих чатах — `flushSync` не создаёт лишних рендеров, он только меняет момент применения
