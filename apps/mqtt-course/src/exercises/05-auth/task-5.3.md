# Задание 5.3: Плагины аутентификации

## Цель

Познакомиться с доступными механизмами аутентификации для Mosquitto: от встроенного Dynamic Security Plugin до сторонних решений. Научиться выбирать подходящий механизм для OpenWRT.

## Требования

1. Изучите все 4 варианта плагинов в компоненте
2. Найдите, какой плагин имеет «Полную» поддержку OpenWRT — должно быть 2 варианта
3. Просмотрите пример конфигурации для каждого плагина
4. Определите: какой плагин выбрать для OpenWRT с 50 устройствами?
5. Определите: какой плагин выбрать если устройства нужно добавлять без перезапуска?

## Чеклист

- [ ] Понял разницу между `password_file` и `Dynamic Security Plugin`
- [ ] Знаю команду инициализации Dynamic Security: `mosquitto_ctrl dynsec init`
- [ ] Понял, почему `mosquitto-go-auth` проблематичен на OpenWRT (musl libc)
- [ ] Знаю концепцию JWT аутентификации в MQTT (пароль = JWT токен)
- [ ] Могу выбрать механизм аутентификации под конкретные требования

## Как проверить себя

Выберите правильный механизм для каждого сценария:

| Сценарий | Механизм |
|---|---|
| OpenWRT роутер, 10 датчиков, статичная конфигурация | ? |
| OpenWRT роутер, 100 датчиков, добавление без перезапуска | ? |
| Сервер с PostgreSQL, тысячи пользователей | ? |
| Микросервисная архитектура с OAuth2/JWT | ? |

Ответы:
- Password File + ACL (простота, нет зависимостей)
- Dynamic Security Plugin (динамическое управление, встроен)
- mosquitto-go-auth с postgres бэкендом
- mosquitto-go-auth с jwt бэкендом или custom HTTP API

Объясните: почему при использовании Dynamic Security Plugin нужен административный пользователь и почему его пароль особенно важно защитить?

Ответ: администратор dynamic security может создавать/удалять пользователей через MQTT топики `$CONTROL/dynamic-security/v1`. Компрометация этого аккаунта даёт полный контроль над аутентификацией брокера.
