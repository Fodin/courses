# Задание 7.2: Build a Mini Store

## Задание

Реализуйте минимальный state manager с нуля: `createStore(initialState)` → `{ getState, setState, subscribe }`. Затем постройте на нём хук `useStore(store, selector?)`. Протестируйте на приложении-счётчике с двумя независимыми подписчиками.

## Цель

Понять, как устроены Zustand, Jotai и другие state-менеджеры под капотом — все они реализуют тот же контракт `subscribe / getSnapshot`. После этого задания API `useSyncExternalStore` станет очевидным, а не магическим.

## Требования

1. Реализовать функцию `createStore<T>(initialState: T): Store<T>`, где `Store<T>` — тип с методами:
   - `getState(): T` — возвращает текущее состояние
   - `setState(next: T | ((prev: T) => T)): void` — обновляет state и уведомляет подписчиков
   - `subscribe(listener: () => void): () => void` — регистрирует listener, возвращает unsubscribe
2. `setState` должен использовать `Object.is` для проверки равенства — если state не изменился, listeners не уведомляются
3. Реализовать хук `useStore<T, S>(store: Store<T>, selector?: (state: T) => S): T | S`, который использует `useSyncExternalStore` внутри
4. Создать глобальный store с состоянием `{ count: number }` и начальным значением `{ count: 0 }`
5. Реализовать два независимых компонента-подписчика:
   - `Counter` — показывает `count` и кнопку "Increment"
   - `DoubleCounter` — показывает `count * 2`, кнопку не имеет
6. Оба компонента должны обновляться синхронно при нажатии кнопки в `Counter`
7. Добавить счётчики рендеров в оба компонента, чтобы убедиться: каждый рендерится ровно один раз при обновлении

## Чеклист

- [ ] `createStore` возвращает объект с `getState`, `setState`, `subscribe`
- [ ] `setState` принимает как новое значение, так и функцию-обновитель `(prev) => next`
- [ ] `setState` с тем же значением (`Object.is`) не уведомляет listeners
- [ ] `subscribe` возвращает функцию отписки, удаляющую listener из множества
- [ ] `useStore` построен на `useSyncExternalStore`, а не на `useEffect + useState`
- [ ] `Counter` и `DoubleCounter` рендерятся независимо от других компонентов
- [ ] При клике "Increment" оба компонента обновляются одновременно (без tearing)
- [ ] Счётчик рендеров показывает 1 ре-рендер при каждом клике

## Как проверить себя

1. Запустите компонент и несколько раз нажмите "Increment"
2. После каждого клика `Counter` должен показывать N, `DoubleCounter` — N*2
3. Счётчик рендеров каждого компонента увеличивается на 1 при каждом клике (не на 2!)
4. Попробуйте сделать несколько `setState` подряд в одном обработчике — убедитесь, что listeners вызываются для каждого изменения
5. Вызовите `setState` с тем же значением — счётчик рендеров не должен увеличиваться
