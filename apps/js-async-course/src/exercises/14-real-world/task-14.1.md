# Задание 14.1: Загрузчик файлов

## Цель

Реализовать комплексный компонент загрузки файлов, объединяющий четыре концепции: `asyncPool` для ограниченной конкурентности, `AbortController` для отмены, retry с exponential backoff при ошибках, и анимированный UI с прогресс-барами.

## Требования

1. **Добавление файлов**: кнопка "Добавить файлы" генерирует 5–10 симулированных файлов разного размера (от 1 до 10 MB). Файлы добавляются в список — допускается добавлять несколько раз.

2. **Параллельная загрузка с лимитом**: слайдер "Конкурентность" (N = 1..5) определяет сколько файлов загружается одновременно. Реализовать через `asyncPool(N, files, uploadTask)`.

3. **Карточка файла**: каждый файл отображается как карточка с именем, размером, прогресс-баром (0–100%), и цветным статусом.

4. **Статусы файла**: `pending` → `uploading` → `completed`. При сетевой ошибке: `uploading` → `retrying` → (успех) `completed` или (исчерпаны попытки) `failed`. При ручной отмене: `cancelled`.

5. **Индивидуальная отмена**: кнопка "Отменить" на каждой карточке в статусе `uploading` или `retrying` отменяет только этот файл через его `AbortController`.

6. **Отмена всех**: кнопка "Отменить все" останавливает все активные загрузки одновременно.

7. **Retry с backoff**: при ошибке загрузки — автоматический повтор до 3 раз с задержками 500ms, 1000ms, 2000ms. В статусе `retrying` показывать номер попытки.

8. **Общий прогресс**: строка "X из N файлов загружено" над списком.

## Чеклист

- [ ] Компонент называется `Task14_1` и экспортируется по умолчанию
- [ ] `useLanguage` импортирован, `t('task.14.1')` используется в заголовке
- [ ] `asyncPool(N, files, fn)` ограничивает конкурентность — при N=1 файлы идут строго по одному
- [ ] Каждый файл имеет собственный `AbortController`, не общий
- [ ] Кнопка "Отменить" на карточке отменяет только этот файл
- [ ] Кнопка "Отменить все" отменяет все активные загрузки
- [ ] Retry меняет статус на `retrying` (не `uploading`) и показывает номер попытки
- [ ] Exponential backoff: задержки 500ms, 1000ms, 2000ms между попытками
- [ ] `AbortError` при отмене не считается ошибкой — статус `cancelled`, не `failed`
- [ ] Прогресс-бар отображает число 0–100 в зависимости от прогресса загрузки
- [ ] Нет TypeScript-ошибок `any`

## Как проверить себя

1. Добавьте файлы, установите конкурентность = 1, нажмите "Начать загрузку" — файлы должны загружаться строго по одному
2. Установите конкурентность = 3 — три файла в статусе `uploading` одновременно
3. Во время загрузки нажмите "Отменить" на одном файле — только он перейдёт в `cancelled`
4. Нажмите "Отменить все" — все файлы в `uploading`/`retrying` перейдут в `cancelled`
5. После завершения у некоторых файлов будет статус `retrying` — это означает что retry сработал
6. Строка прогресса корректно считает только `completed` файлы
