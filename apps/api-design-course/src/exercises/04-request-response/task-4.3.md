# Задание 4.3 — Эталонный Request/Response для ресурса

## Цель

Создать полный набор правильных request/response-пар для стандартных CRUD-операций. Закрепить навык проектирования тел запросов и ответов с учётом HTTP-заголовков, статус-кодов и конвенций.

## Требования

1. Компонент покрывает пять операций: список, получение одного, создание, частичное обновление, удаление.
2. Для каждой операции показаны: HTTP-метод, полный URL, заголовки запроса, тело запроса (если есть).
3. Переключатель «Запрос / Ответ» показывает заголовки и тело ответа с правильным статус-кодом.
4. Для каждой операции — блок «Ключевые решения» с обоснованием выбора метода, статуса и структуры.
5. Ресурс для примеров — «товар» (product) с полями: id, name, price, category, inStock.

## Чеклист

- [ ] Все 5 операций: GET (список), GET (один), POST, PATCH, DELETE
- [ ] Для каждой: метод, URL, заголовки, тело запроса
- [ ] Для каждой: статус ответа, заголовки ответа, тело ответа
- [ ] Переключатель «Запрос/Ответ»
- [ ] Пагинация в GET-коллекции (meta)
- [ ] POST возвращает 201 + Location
- [ ] PATCH использует application/merge-patch+json
- [ ] DELETE возвращает 204 без тела
- [ ] Блок с обоснованием решений для каждой операции

## Как проверить себя

Закройте компонент. Спроектируйте с нуля request/response для ресурса «заказ» (order) — все 5 операций. Сравните с эталоном. Обратите внимание на: заголовки, статус-коды, наличие/отсутствие тела, поля meta в коллекции.
