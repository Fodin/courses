# Задание 1.3: Service Discovery — реестр сервисов

## Цель

Создать интерактивный реестр сервисов с динамической регистрацией/дерегистрацией инстансов,
health-проверками и балансировщиком нагрузки по алгоритму Round-Robin.

## Требования

1. Service Registry: сгруппированный список инстансов по имени сервиса (`user-service`, `order-service`, `payment-service`)
2. Каждый инстанс показывает: IP:Port, статус (healthy / unhealthy / unknown), время ответа, счётчик запросов
3. Статус инстанса визуализируется цветным индикатором (зелёный / красный / жёлтый)
4. Выпадающий список для выбора шаблона сервиса при регистрации
5. Кнопка `+ Регистрация инстанса` — добавляет новый инстанс выбранного типа с уникальными IP и портом
6. Кнопка `×` на каждом инстансе — дерегистрирует его из реестра
7. Кнопка `Health Check` — переводит все инстансы в `unknown`, затем обновляет статусы:
   - Healthy инстансы: 85% шанс остаться healthy, 15% перейти в unhealthy
   - Unhealthy инстансы: 30% шанс восстановиться, 70% остаться unhealthy
8. Блок Load Balancer: выбор сервиса + кнопка `Маршрутизировать запрос`
9. Round-Robin балансировка: запросы распределяются по healthy инстансам по очереди
10. Лог маршрутизации: отображает `timestamp → host:port (responseTime ms)` или ошибку при отсутствии инстансов
11. Статистика в карточках: всего инстансов, Healthy, Unhealthy, всего запросов

## Чеклист

- [ ] Реестр сгруппирован по именам сервисов с отдельными секциями
- [ ] Инстанс без группы показывает сообщение `Нет инстансов`
- [ ] Кнопка `+ Регистрация инстанса` добавляет карточку с IP и портом
- [ ] Кнопка `×` удаляет инстанс из реестра
- [ ] `Health Check` показывает промежуточное состояние `unknown` (жёлтый)
- [ ] После проверки статусы обновляются случайным образом
- [ ] Healthy инстансы светятся зелёным индикатором (glow-эффект)
- [ ] Round-Robin последовательно обходит healthy инстансы одного сервиса
- [ ] При отсутствии healthy инстансов лог показывает ошибку `ERROR: Нет доступных инстансов`
- [ ] Счётчик запросов (`req`) растёт на карточке каждого целевого инстанса
- [ ] Статистические карточки обновляются при любом изменении реестра
- [ ] Компонент использует `useLanguage` и `t('task.1.3')` для заголовка

## Как проверить себя

1. Откройте задание в браузере — убедитесь, что начальные инстансы отображаются корректно
2. Выберите `user-service` в выпадающем списке и добавьте 2 новых инстанса
3. Нажмите `Health Check` — все должны на секунду стать жёлтыми, потом обновиться
4. В блоке Load Balancer выберите `user-service` и нажмите `Маршрутизировать запрос` 4 раза
5. Убедитесь, что запросы чередуются между healthy инстансами (Round-Robin)
6. Дерегистрируйте все инстансы `user-service`, нажмите `Маршрутизировать запрос`
7. Лог должен показать ошибку — нет доступных инстансов
8. Проверьте, что счётчики запросов на карточках инстансов увеличиваются
