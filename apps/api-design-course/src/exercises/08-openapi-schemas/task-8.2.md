# Задание 8.2: Рефакторинг спецификации

## Цель

Создать интерактивный инструмент для демонстрации рефакторинга OpenAPI-спецификации: найти дублирование, вынести повторяющиеся блоки в `components` и наглядно показать экономию строк.

## Требования

1. Показать статистику: количество строк "до" и "после" рефакторинга, экономию
2. Чеклист из 4 дублирующихся блоков, каждый кликабелен:
   - `Order schema` — повторяется в 2 endpoints
   - `Error schema` — повторяется в 4 местах
   - `401 Unauthorized response` — повторяется в 2 endpoints
   - `500 ServerError response` — повторяется в 2 endpoints
3. Для каждого пункта показывать сколько раз он дублируется (значок `×N`)
4. При отметке пункта показывать результирующий `$ref`
5. Переключатель "До" / "После" для просмотра YAML
6. После отметки всех пунктов — сообщение об успехе

## Что реализовать

- [ ] Константы `SPEC_BEFORE` и `SPEC_AFTER` с YAML-текстами
- [ ] Массив `DUPLICATES` с описанием каждого дублирующегося блока
- [ ] Состояние `refactored: string[]` — список отмеченных ID
- [ ] Состояние `view: 'before' | 'after'` для переключения YAML
- [ ] Функция `toggle(id)` — добавляет/убирает из списка отмеченных
- [ ] Вычисление `allDone` — все ли пункты отмечены

## Содержание SPEC_BEFORE

Спецификация с двумя endpoints (`GET /orders` и `GET /orders/{id}`), в которой:
- Схема заказа (`id`, `total`, `status`) описана дважды inline
- Схема ошибки (`code`, `message`) описана в каждом из ответов 401, 404, 500
- Ответы 401 и 500 описаны повторно в каждом endpoint

## Содержание SPEC_AFTER

Та же спецификация после рефакторинга:
- `Order` и `Error` вынесены в `components/schemas`
- `Unauthorized`, `NotFound`, `ServerError` вынесены в `components/responses`
- В paths используются `$ref` ссылки

## Как проверить себя

- Кнопка "После" показывает исправленную спецификацию с `$ref`
- При отметке каждого пункта появляется строка с результирующим `$ref`
- После отметки всех четырёх пунктов появляется сообщение об успехе
- Счётчик экономии показывает реальную разницу в строках
