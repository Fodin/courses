# Задание 7.1: Dead Letter Exchange — путь отклонённых сообщений

## Цель

Реализовать интерактивную визуализацию DLX flow, которая показывает, как сообщения попадают в Dead Letter Queue через три различных механизма: NACK, TTL и переполнение очереди.

## Требования

1. Реализовать функцию `publishMessage`, которая:
   - Создаёт сообщение с уникальным ID и временной меткой
   - Помещает его в `orders.queue` со статусом `queued`
   - Запускает анимацию перехода через статусы

2. Реализовать три пути в DLX:
   - **NACK**: статусы `queued` → `processing` → `rejected` → `dead-lettered`
   - **TTL Expired**: статусы `queued` → `processing` → `expired` → `dead-lettered`
   - **Max Length**: статусы `queued` → `processing` → `rejected` → `dead-lettered`

3. Отображать конфигурацию очереди:
   - `x-dead-letter-exchange`
   - `x-dead-letter-routing-key`
   - `x-message-ttl` (если выбран режим TTL)

4. Показывать маршрут каждого сообщения по клику на него.

5. Визуально разделить `orders.queue` и `orders.dead-letter` на два блока с счётчиками.

## Проверочный список

- [ ] Кнопка "Опубликовать" добавляет сообщение в визуализацию
- [ ] При выборе режима NACK сообщение проходит через `rejected` → `dead-lettered`
- [ ] При выборе режима TTL сообщение проходит через `expired` → `dead-lettered` после истечения TTL
- [ ] При выборе режима Max Length сообщение отклоняется из-за переполнения
- [ ] Клик на сообщение показывает детальный маршрут с именами exchange/queue
- [ ] Счётчики обеих очередей обновляются в реальном времени
- [ ] Кнопка "Очистить" сбрасывает состояние

## Как проверить себя

Нажми "Опубликовать" с режимом TTL и таймером 2 сек. Через 2 секунды сообщение должно:
1. Появиться в `orders.queue` со статусом QUEUED
2. Перейти в PROCESSING
3. Перейти в EXPIRED
4. Переместиться в `orders.dead-letter` со статусом DEAD LETTERED

Маршрут должен содержать строки с `x-message-ttl`, `x-dead-letter-exchange` и итоговым именем DLQ.
