# Язык, семантика и парадигмы

## Что такое язык программирования?

Язык программирования — это не просто набор ключевых слов. Это трёхслойная система:

```
Синтаксис → Семантика → Прагматика
```

**Синтаксис** — грамматика языка. Правила, по которым строятся корректные программы. Это как орфография: `if (x > 0)` — правильно, `if x > 0 then` — синтаксическая ошибка в JavaScript.

**Семантика** — смысл конструкций. Что *происходит*, когда выполняется код? `x++` синтаксически корректно, но семантика зависит от контекста: в C это неопределённое поведение в ряде случаев, в JavaScript — чётко определённая операция.

**Прагматика** — зачем язык устроен именно так? Почему в Python отступы обязательны? Потому что создатели хотели сделать читаемость частью синтаксиса, а не опцией.

```typescript
// Синтаксически корректно
const result = arr.map(x => x * 2)

// Семантически: создаёт НОВЫЙ массив, не мутирует arr
// Прагматика: функциональный стиль поощряет иммутабельность
```

## Декларативный vs Императивный стиль

Представьте, что вы даёте задание курьеру.

**Императивно** — пошаговые инструкции:
> Выйди из офиса, поверни налево, иди 200 метров, войди в третье здание, поднимись на второй этаж...

**Декларативно** — описание результата:
> Доставь посылку по адресу: ул. Ленина, 15, офис 201.

В коде это выглядит так:

```typescript
const numbers = [1, 2, 3, 4, 5, 6]

// Императивно: как делать
const evensImperative: number[] = []
for (let i = 0; i < numbers.length; i++) {
  if (numbers[i] % 2 === 0) {
    evensImperative.push(numbers[i])
  }
}

// Декларативно: что хотим получить
const evensDeclarative = numbers.filter(n => n % 2 === 0)
```

Декларативный стиль повсюду: SQL (`SELECT * FROM users WHERE age > 18`), HTML, CSS, React JSX, GraphQL. Вы описываете *что*, а не *как*.

## Мультипарадигменное программирование

JavaScript и TypeScript — мультипарадигменные языки. Они поддерживают:

- **ООП**: классы, наследование, инкапсуляция
- **Функциональное**: функции как значения, иммутабельность, композиция
- **Процедурное**: последовательные инструкции, циклы

```typescript
// ООП-стиль
class UserService {
  private users: User[] = []
  addUser(user: User) { this.users.push(user) }
}

// Функциональный стиль
const addUser = (users: User[], user: User): User[] => [...users, user]

// Оба подхода решают одну задачу по-разному
```

Мультипарадигменность — это не слабость, а суперсила. Вы выбираете инструмент под задачу, а не подгоняете задачу под инструмент.

## Почему это важно на практике?

Понимание парадигм помогает:
- Читать чужой код быстрее (узнавать паттерны)
- Принимать архитектурные решения осознанно
- Не писать ООП там, где достаточно пары функций
- Использовать функциональный стиль там, где нужна предсказуемость

## Первоклассные сущности (First-Class Citizens)

В JavaScript функции — первоклассные объекты. Это значит, что с ними можно делать всё то же, что с числами и строками: присваивать переменным, передавать аргументами, возвращать из других функций.

```typescript
// Функция как значение
const double = (x: number) => x * 2

// Функция как аргумент
const transform = (fn: (x: number) => number, values: number[]) =>
  values.map(fn)

// Функция как возвращаемое значение
const multiplier = (factor: number) => (x: number) => x * factor
const triple = multiplier(3)
```

Это фундаментальная особенность, которая делает возможным функциональное программирование в JS/TS.

## Итог

```
Синтаксис  — правила написания
Семантика  — правила выполнения
Прагматика — причины дизайна
```

Хороший разработчик думает на всех трёх уровнях. Синтаксис — это лишь поверхность.
