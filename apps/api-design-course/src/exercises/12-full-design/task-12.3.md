# Задание 12.3: Эталонный E-commerce API

## Цель

Изучить эталонный дизайн REST API для интернет-магазина — полный набор ресурсов, методов, статус-кодов, форматов запросов/ответов и сквозных аспектов. Понять, как применяются все темы курса вместе.

## Ресурсы для изучения

Изучи каждый ресурс и его эндпоинты:

1. **Products** (4 endpoint) — список, создание, детали, обновление
2. **Cart** (4 endpoint) — просмотр корзины, добавление/изменение/удаление позиций
3. **Orders** (4 endpoint) — создание, список, детали, отмена (action endpoint)
4. **Users** (3 endpoint) — регистрация, вход, профиль
5. **Reviews** (2 endpoint) — список отзывов с рейтингом, создание

## Чеклист

- [ ] Products: понять разницу между списком (краткая карточка) и детальным ответом
- [ ] Cart: почему POST /cart/items возвращает 409, если товара нет в наличии?
- [ ] Orders: разобраться, зачем в GET /orders/{id} есть поле `timeline`
- [ ] Orders: понять, почему отмена — это POST /orders/{id}/cancel, а не DELETE
- [ ] Users: почему POST /auth/login rate-limited по IP, а не по user ID?
- [ ] Reviews: что означает поле `verified` в отзыве и как оно проставляется?
- [ ] Сквозные аспекты: запомнить формат ошибок, версионирование, формат дат и денег

## Вопросы для самопроверки

1. Почему деньги хранятся как `{ "amount": 850.00, "currency": "RUB" }`, а не просто числом?
2. Что произойдёт, если клиент вызовет POST /orders/{id}/cancel для уже отменённого заказа?
3. Почему в списке отзывов `meta.distribution` показывает количество по каждому рейтингу?
4. Чем отличается ответ GET /products (список) от GET /products/{id} (детали)?
5. Почему публичные endpoint (GET /products) не требуют авторизации, а POST /reviews — требует?

## Как проверить себя

1. Изучи все 5 ресурсов последовательно, читая request и response для каждого endpoint
2. Ответь на все 5 вопросов самопроверки — запиши ответы
3. Попробуй воспроизвести структуру API по памяти: какие ресурсы? какие методы?
4. Обрати внимание на блок «Сквозные аспекты» — он применяется ко всему API
5. Сравни этот API с тем, что ты видел в задании 12.2 — найди конкретные отличия

## Подсказки

- `timeline` в заказе — паттерн State Machine History: вся история переходов статусов
- POST /orders/{id}/cancel — это action endpoint, не DELETE, потому что у отмены есть бизнес-логика (причина, возврат средств, обновление склада)
- `verified: true` в отзыве означает, что пользователь подтверждённо купил этот товар (проверяется через orderId)
- Структура `meta.distribution` нужна для рендеринга столбчатой диаграммы рейтингов без дополнительного запроса
