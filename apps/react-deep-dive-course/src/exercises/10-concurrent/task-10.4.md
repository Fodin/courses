# Задание 10.4: Concurrent Tree Walk

## Цель

Визуализировать разницу между sync и transition обновлениями через анимацию обхода fiber tree. Понять, как React обрабатывает обновления разного приоритета и почему transition обновления могут быть "прерваны".

## Задание

Создайте интерактивный визуализатор "Fiber Tree Walker". На экране — дерево из 15–20 узлов (3 уровня вложенности). Каждый узел — круг с именем компонента.

### Состояния узлов

- **Серый** (idle) — узел ещё не обработан
- **Жёлтый** (processing) — узел обрабатывается прямо сейчас  
- **Зелёный** (sync-done) — обработан как sync update
- **Синий** (transition-done) — обработан как transition update
- **Оранжевый** (interrupted) — transition был прерван sync update

### Кнопки управления

1. **"Sync Update"** — запускает "обход" дерева. Каждый узел подсвечивается жёлтым поочерёдно с задержкой 80ms (через setTimeout/useEffect chain), затем становится зелёным. Sync update нельзя прервать — обход всегда доходит до конца.

2. **"Transition Update"** — запускает медленный обход (150ms на узел), узлы становятся синими. Можно прервать нажатием "Sync Update" в середине — прерванные узлы становятся оранжевыми, и начинается быстрый sync обход.

3. **"Сбросить"** — все узлы возвращаются в серый.

### Лог событий

Справа от дерева — лог с записями:
- `[12:00:00.123] Sync update запущен`
- `[12:00:00.456] Transition прерван на узле App > Header > Nav`
- `[12:00:01.234] Sync завершён (5 узлов)`

### Дерево узлов

```
App
├── Header
│   ├── Logo
│   └── Nav
│       ├── NavItem1
│       └── NavItem2
├── Main
│   ├── Sidebar
│   │   ├── Widget1
│   │   └── Widget2
│   └── Content
│       ├── Card1
│       ├── Card2
│       └── Card3
└── Footer
    ├── Links
    └── Copy
```

## Требования

1. Структура дерева задана как массив объектов `{ id, name, parentId, depth }` — не React-компоненты, а данные
2. Рендер дерева — рекурсивная функция или `TreeNode` компонент
3. `nodeStates: Record<string, NodeState>` — состояние каждого узла
4. Sync обход — `useRef` для флага `isRunning`, цепочка setTimeout (не concurrent): каждый setTimeout устанавливает следующий узел в 'processing', через 80ms — в 'sync-done'
5. Transition обход — аналогично, но 150ms на узел, состояние 'transition-done'; при запуске Sync во время Transition — все оставшиеся 'idle' и текущий 'processing' помечаются 'interrupted', затем запускается Sync обход
6. Лог — массив строк в `useRef`, максимум 20 записей, отображается в реальном времени
7. Анимация плавная: CSS transition на background-color узлов

## Чеклист

- [ ] Дерево из 15+ узлов, 3 уровня вложенности
- [ ] 5 состояний узла с разными цветами (idle/processing/sync-done/transition-done/interrupted)
- [ ] Sync обход: 80ms на узел, идёт до конца, нельзя прервать кнопкой Sync (игнорирует новый клик пока идёт)
- [ ] Transition обход: 150ms на узел, прерывается при Sync
- [ ] При прерывании transition: обработанные узлы остаются синими, текущий/необработанные → оранжевые
- [ ] После прерывания — Sync обход начинается с начала (все узлы → idle → sync processing)
- [ ] Лог событий с временными метками
- [ ] Кнопка "Сбросить" работает в любой момент

## Как проверить себя

1. Нажмите "Transition Update" — наблюдайте медленный синий обход
2. В середине обхода нажмите "Sync Update" — синие остаются синими, незаконченные станут оранжевыми, затем запускается быстрый зелёный обход
3. Попробуйте нажать "Sync Update" дважды — второй клик должен игнорироваться (sync нельзя прервать)
4. Лог должен показать: "Transition прерван на узле X", "Sync update запущен"
5. "Сбросить" в любой момент должен остановить любой обход и вернуть все узлы в серый
