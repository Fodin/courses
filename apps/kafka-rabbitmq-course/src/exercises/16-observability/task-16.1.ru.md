# Задание 16.1: Consumer Lag дашборд

## Цель

Реализовать интерактивный дашборд для мониторинга **Consumer Lag** в реальном времени. Дашборд симулирует поступление сообщений и потребление, показывает lag по каждой партиции и consumer group с цветовой индикацией состояния.

## Требования

1. Объявить интерфейс `PartitionStats` с полями `partition: number`, `logEndOffset: number`, `committedOffset: number`, `lag: number`.
2. Объявить интерфейс `ConsumerGroup` с полями `id: string`, `topic: string`, `partitions: PartitionStats[]`.
3. Реализовать вспомогательную функцию `getLagColor(lag, threshold)`, возвращающую цвет `'#e53e3e'` (critical), `'#ed8936'` (growing) или `'#38a169'` (ok) в зависимости от значения lag.
4. Реализовать функцию `getLagLabel(lag, threshold)`, возвращающую строку `'CRITICAL'`, `'GROWING'` или `'OK'`.
5. Задать константу `THRESHOLDS = { yellow: 500, red: 2000 }` и начальные данные для двух consumer groups: `orders-consumer` (топик `orders`, 3 партиции с малым lag) и `analytics-consumer` (топик `events`, 3 партиции с разным lag, включая CRITICAL).
6. Объявить состояния компонента: `groups: ConsumerGroup[]` и `slowdown: boolean` (режим замедления consumer).
7. Реализовать `useEffect` с интервалом 1200ms, который симулирует рост log-end offset и изменение committed offset. В режиме `slowdown` скорость потребления резко снижается (consumer почти не продвигается).
8. Вычислять `totalLag` как сумму лагов всех партиций всех групп.
9. Отрисовать кнопку переключения режима slowdown с текстом "Consumer замедлен (симуляция инцидента)" / "Consumer работает нормально" и сводку суммарного lag.
10. Отрисовать легенду (OK / GROWING / CRITICAL) с цветовыми маркерами.
11. Для каждой consumer group отрисовать карточку с цветной рамкой (цвет зависит от суммарного lag группы), внутри — таблицу партиций с колонками: Partition, Log-End Offset, Committed Offset, визуальный прогресс-бар lag, статус.
12. Прогресс-бар должен плавно анимировать изменения через CSS transition.

## Чеклист

- [ ] Интерфейсы `PartitionStats` и `ConsumerGroup` объявлены
- [ ] `getLagColor` возвращает правильный цвет для каждого диапазона lag
- [ ] `getLagLabel` возвращает `'OK'`, `'GROWING'` или `'CRITICAL'`
- [ ] Константа `THRESHOLDS` и начальные данные двух групп объявлены
- [ ] `useEffect` симулирует рост LEO и изменение committed offset каждые 1200ms
- [ ] В режиме `slowdown` потребление резко замедляется, lag начинает расти
- [ ] Суммарный lag отображается и обновляется в реальном времени
- [ ] Кнопка переключает режим slowdown и меняет цвет/текст
- [ ] Легенда с тремя цветами отрисована
- [ ] Каждая группа показывает цветную рамку и badge со статусом
- [ ] Таблица партиций содержит все 4 колонки
- [ ] Прогресс-бар lag визуально отражает отставание и меняет цвет плавно
- [ ] Интервал очищается при `useEffect` cleanup (clearInterval)

## Как проверить себя

1. Откройте задание — оба consumer group показаны, `orders-consumer` зелёный (lag 2–5), `analytics-consumer` содержит красную партицию (lag ~2200).
2. Наблюдайте обновление каждые 1.2 секунды: числа меняются, прогресс-бары анимируются.
3. Нажмите кнопку "Consumer работает нормально" — она должна переключиться на "Consumer замедлен". Через несколько секунд lag начнёт расти, партиции станут оранжевыми, затем красными.
4. Суммарный lag должен стремительно расти при slowdown и отображаться красным при значении > 8000.
5. Нажмите кнопку снова — consumer "ускоряется", lag начинает сокращаться.
