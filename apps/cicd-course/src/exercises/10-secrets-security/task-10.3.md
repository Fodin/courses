# Задание 10.3: Защита пайплайна — Protected Branches, Environments и Approval Rules

## Цель

Создать интерактивный симулятор системы защиты деплоя. Пользователь настраивает слои защиты (protected branches, environment approvals, deployment rules) и видит, пройдёт ли деплой в разных сценариях.

## Требования

1. Реализовать **конфигуратор защиты** с тремя независимыми слоями:
   - Protected Branch: переключатель "включить защиту main" + выбор кто может мёрджить (Developers, Maintainers, Owners)
   - Environment Approvals: переключатель + ввод количества требуемых апрувов (1, 2, 3)
   - Self-approval: переключатель "запретить апрув своего деплоя"
2. Реализовать **симулятор сценариев** — три кнопки с разными ситуациями:
   - Сценарий A: Developer пушит в `feature/login`, запускает deploy-production
   - Сценарий B: Maintainer мёрджит MR в `main`, запускает deploy-production, один approver уже апрувил
   - Сценарий C: Developer пытается апрувить свой собственный деплой
3. Для каждого сценария показывать **пошаговый flow**: стрелки и блоки проверок, каждая проверка — зелёный "пройдено" или красный "заблокировано".
4. Отображать **итоговый вердикт** крупным блоком: "Деплой разрешён" (зелёный) или "Деплой заблокирован" (красный) с объяснением причины.
5. Показывать **YAML-конфиг** джоба deploy-production, который обновляется при изменении настроек (environment, when: manual, rules).

## Чеклист

- [ ] Три секции конфигуратора с переключателями и параметрами
- [ ] Три кнопки сценариев с описанием
- [ ] Пошаговый flow проверок (минимум 3 шага) с цветовой индикацией
- [ ] Крупный блок итогового вердикта (Разрешён / Заблокирован)
- [ ] Объяснение причины блокировки или разрешения
- [ ] YAML-блок, обновляющийся при изменении конфигурации
- [ ] Все три сценария дают разные результаты при разных конфигурациях

## Как проверить себя

1. Включи все три слоя защиты, выбери сценарий A — должна быть блокировка: feature-ветка не protected
2. С теми же настройками выбери сценарий B, апрувов = 2, уже апрувил 1 — должна быть блокировка: недостаточно апрувов
3. Выключи Environment Approvals, выбери сценарий B — должен быть разрешён (если maintainer имеет право)
4. Включи Self-approval запрет, выбери сценарий C — должна быть блокировка с объяснением
5. Проверь, что YAML обновляется при изменении количества апрувов (комментарий в YAML)

## Подсказки

- Используй `useState` для: `protectedBranch` (boolean), `mergeRole` ('developers'|'maintainers'|'owners'), `approvalsEnabled` (boolean), `requiredApprovals` (1|2|3), `selfApproval` (boolean), `scenario` (null|'A'|'B'|'C')
- Функция `checkScenario(config, scenario)` → `{ passed: boolean, steps: CheckStep[], reason: string }`
- Шаги проверки — массив объектов: `{ name: string, passed: boolean, detail: string }`
- Для сценария B учитывай: нужно `requiredApprovals` апрувов, получен 1 — если `requiredApprovals > 1` → блокировка
- YAML: при `approvalsEnabled: true` добавляй комментарий `# requires ${requiredApprovals} approval(s)` в environment секцию
