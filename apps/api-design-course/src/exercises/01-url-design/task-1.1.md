# Задание 1.1 — URL-конструктор

## Цель

Закрепить умение конструировать корректные REST endpoints: выбирать правильный HTTP-метод, формировать путь из ресурсов и идентификаторов, добавлять query params только там, где это нужно.

## Требования

1. Компонент отображает один из нескольких сценариев (например: «Получить все заказы пользователя с ID = 7»).
2. Пользователь выбирает HTTP-метод, добавляет сегменты пути кнопками (ресурсы и ID) и при необходимости вводит query params.
3. Компонент собирает и отображает получившийся URL в реальном времени.
4. Кнопка «Проверить» сравнивает собранный URL с эталоном и показывает результат.
5. Кнопка «Подсказка» объясняет принцип без раскрытия ответа.
6. Кнопка «Следующий» переключает на следующий сценарий.
7. Не менее 4 разных сценариев, покрывающих: коллекцию, один ресурс, вложенный ресурс, фильтрацию.

## Чеклист

- [ ] Выбор HTTP-метода (GET, POST, PUT, PATCH, DELETE)
- [ ] Добавление сегментов пути из готовых вариантов
- [ ] Ввод query params вручную
- [ ] Предпросмотр URL обновляется при каждом изменении
- [ ] Проверка показывает правильный ответ при ошибке
- [ ] Подсказка не раскрывает ответ сразу
- [ ] Минимум 4 сценария

## Как проверить себя

Соберите endpoint для каждого сценария без подсказок. Проверьте результат. Если ошибаетесь — прочитайте объяснение правильного варианта и разберите, где была логическая ошибка.
