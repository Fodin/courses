# Задание 11.3: requestIdleCallback — фоновая работа без блокировки

## Цель

Продемонстрировать разницу между синхронной обработкой большого массива и обработкой через `requestIdleCallback`. Пользователь видит, что синхронный подход замораживает анимацию, а rIC позволяет UI оставаться отзывчивым при том же объёме работы.

## Требования

1. **Задача** — обработка 10 000 элементов:
   - Для каждого: `Math.sqrt(i * 17 + Math.sin(i) * 100)`
   - Каждые 100 элементов — сортировка массива из 100 случайных чисел
   - Это создаёт ощутимую, но реалистичную нагрузку

2. **Индикатор анимации** — вращающийся спиннер через `requestAnimationFrame`:
   - Работает постоянно пока идёт обработка
   - При синхронном режиме должен замереть (это ожидаемо и является демонстрацией проблемы)
   - При rIC-режиме продолжает плавно вращаться

3. **Прогресс-бар** — отображает прогресс обработки (0–100%)

4. **Два режима запуска**:
   - "Синхронно" — весь цикл в одном вызове `setTimeout(() => {...}, 0)`
   - "Через rIC" — обработка чанками через `requestIdleCallback`

5. **Лог idle-периодов** (только для rIC-режима):
   - Показывает последние 10 idle-периодов
   - Для каждого: номер, `timeRemaining()` при старте, количество обработанных элементов
   - Полоска цвета: зелёная (>20ms), жёлтая (>5ms), красная (≤5ms)

6. **Результат** — после завершения показывает общее время и комментарий о поведении UI

## Чеклист

- [ ] Компонент называется `Task11_3` и экспортируется по умолчанию
- [ ] `useLanguage` импортирован, `t('task.11.3')` используется в заголовке
- [ ] Используется настоящий `requestIdleCallback`, не polyfill и не setTimeout
- [ ] Используется настоящий `requestAnimationFrame` для спиннера
- [ ] `cancelIdleCallback` и `cancelAnimationFrame` вызываются при сбросе и размонтировании
- [ ] Прогресс обновляется в реальном времени в rIC-режиме
- [ ] Лог idle-периодов отображает корректные значения `timeRemaining()`
- [ ] Кнопки заблокированы во время работы
- [ ] Опция `{ timeout: 2000 }` передаётся в `requestIdleCallback`
- [ ] Нет TypeScript-ошибок, нет `any`

## Как проверить себя

1. Нажмите "Синхронно" — спиннер должен замереть на время обработки, затем резко появиться результат
2. Нажмите "Сброс", затем "Через rIC" — спиннер продолжает вращаться, прогресс растёт постепенно
3. Наблюдайте лог: первые idle-периоды имеют больше времени (>30ms), потом меньше
4. Общее время в rIC-режиме больше, чем синхронно — это нормально
5. Попробуйте кликать на кнопки во время rIC-обработки — они реагируют
6. Во время синхронной обработки — клики не работают
