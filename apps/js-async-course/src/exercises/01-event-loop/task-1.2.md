# Задание 1.2: Микротаски vs Макротаски

## Цель

Создать интерактивный демонстратор, который наглядно показывает разницу в приоритетах между очередями микротасок и макротасок, включая опасный сценарий Microtask Starvation.

## Требования

1. **Три сценария** (переключаются вкладками):
   - Базовый: одна микротаска vs одна макротаска
   - Все микротаски до макротаски: три микротаски + одна макротаска
   - Microtask Starvation: бесконечная цепочка Promise блокирует макротаску

2. **Две очереди** — Microtask Queue (фиолетовая) и Macrotask Queue (янтарная) — с карточками задач для каждого сценария

3. **Пошаговое выполнение** — кнопка "Выполнить микротаску" / "Выполнить макротаску" в зависимости от того, что осталось

4. **Лог порядка** — список задач в порядке их выполнения с цветовой разметкой (фиолетовый для микро, янтарный для макро)

5. **Сценарий Starvation** — показывает визуально что макротаска заблокирована и никогда не получит управление

6. **Правило Event Loop** — постоянный информационный блок: "ВСЕ микротаски → ОДНА макротаска → repeat"

- [ ] `useLanguage` импортирован, `t('task.1.2')` используется в заголовке
- [ ] Три сценария переключаются без ошибок, состояние сбрасывается
- [ ] В базовом сценарии микротаска выполняется раньше макротаски
- [ ] Во втором сценарии все три микротаски выполняются до макротаски
- [ ] В сценарии Starvation макротаска визуально помечена как заблокированная
- [ ] Лог отображает правильный порядок с цветовой разметкой
- [ ] Кнопка "Сброс" работает для всех сценариев

## Как проверить себя

1. Откройте сценарий "Базовый приоритет"
2. Нажмите кнопку выполнения — должна выполниться микротаска (не макротаска!)
3. Нажмите ещё раз — выполнится макротаска
4. Переключитесь на "Все микротаски до одной макротаски"
5. Нажимайте — все три микротаски должны выполниться до появления макротаски
6. Переключитесь на "Microtask Starvation" и запустите — макротаска должна быть отмечена как заблокированная
