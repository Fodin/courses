# Задание 5.4: Стратегии cache key

## Цель

Создать конфигуратор `cache:key`, который наглядно показывает разные стратегии ключей кэша и симулирует поведение при переключении веток — cache hits и cache misses.

## Требования

1. Показать три стратегии cache key: статический, на основе переменной `$CI_COMMIT_REF_SLUG`, на основе `files: [package-lock.json]`
2. Для каждой стратегии — краткое описание и пример YAML
3. Добавить симулятор: "Смена ветки" и "Изменение package-lock.json"
4. Симулятор показывает: будет cache hit или cache miss для каждой стратегии
5. Добавить настройку `prefix` — поле ввода или выбор из вариантов (`v1`, `$CI_COMMIT_REF_SLUG`, пусто)
6. Финальный YAML конфиг обновляется при изменении любой настройки
7. Показать таблицу сравнения стратегий: автоинвалидация / изоляция веток / сложность

## Чеклист

- [ ] Три карточки стратегий с названием, описанием и YAML-примером
- [ ] Активная стратегия визуально выделена (border, background)
- [ ] Симулятор с двумя кнопками: "Сменить ветку" и "Обновить package-lock.json"
- [ ] Для каждой стратегии после симуляции — индикатор: Hit (зелёный) или Miss (красный)
- [ ] Поле ввода или выбор prefix
- [ ] Итоговый YAML обновляется в реальном времени
- [ ] Таблица сравнения трёх стратегий по ключевым характеристикам

## Как проверить себя

1. Выбери стратегию "Статический ключ", нажми "Сменить ветку" — должен быть Hit (ветка не влияет)
2. Выбери "По ветке ($CI_COMMIT_REF_SLUG)", нажми "Сменить ветку" — Miss (новый ключ)
3. Выбери "По lock-файлу", нажми "Обновить package-lock.json" — Miss (ключ изменился)
4. Нажми "Обновить package-lock.json" при статическом ключе — Hit (содержимое не влияет на ключ)
5. Введи prefix `v2` — убедись, что он появился в YAML

## Подсказки

- Состояние симулятора: `currentBranch: 'main'|'feature/auth'`, `lockfileChanged: boolean`
- `cacheKey` вычисляется в зависимости от стратегии и текущего состояния симулятора
- Для сравнения ключей: предыдущий ключ храни в `useState`, при смене сравниваешь — hit или miss
- Таблицу строй через HTML `<table>` с inline стилями — 4 строки (3 стратегии + заголовок) × 4 колонки
