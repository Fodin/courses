# Задание 13.1: Race Condition визуализатор

## Цель

Построить визуализатор, который демонстрирует разницу между небезопасным параллельным доступом к SharedArrayBuffer (race condition) и атомарным инкрементом через `Atomics.add`. Два настоящих Web Worker'а соревнуются за одну ячейку памяти.

## Требования

1. **SharedArrayBuffer с одной ячейкой** — `new SharedArrayBuffer(4)`, `Int32Array[0] = 0`.

2. **Два Web Worker'а** — каждый выполняет 50 итераций. Оба стартуют одновременно и получают один SAB.

3. **Режим "Без Atomics"** (race condition):
   - Каждый Worker: читает `arr[0]`, ждёт ~1мс, пишет `read + 1`
   - Итоговый результат меньше 100 — потоки перезаписывают друг друга
   - Worker'ы создаются через `new Blob([code])` + `URL.createObjectURL`

4. **Режим "С Atomics"** (безопасно):
   - Каждый Worker: `Atomics.add(arr, 0, 1)` — атомарный инкремент
   - Итоговый результат всегда = 100

5. **5 последовательных запусков** — таблица результатов показывает разброс (без Atomics) или стабильность (с Atomics).

6. **Лог** — каждый запуск логирует результат и пометку "RACE CONDITION!" если значение != 100.

7. **Переключатель** — вкладки "Без Atomics / С Atomics", при переключении результаты очищаются.

## Чеклист

- [ ] Компонент называется `Task13_1` и экспортируется по умолчанию
- [ ] `useLanguage` импортирован, `t('task.13.1')` используется в заголовке
- [ ] Использован настоящий `SharedArrayBuffer` (не симуляция)
- [ ] Worker'ы создаются через Blob + `URL.createObjectURL`
- [ ] В режиме "Без Atomics" хотя бы один из 5 запусков даёт результат != 100
- [ ] В режиме "С Atomics" все 5 запусков дают результат = 100
- [ ] Таблица с ячейками: номер запуска, итоговое значение, статус ✓/✗
- [ ] Лог с последовательными записями о каждом запуске
- [ ] Worker'ы корректно завершаются (`worker.terminate()`)
- [ ] Нет TypeScript-ошибок типа `any`

## Как проверить себя

1. Запустите в режиме "Без Atomics" — несколько из 5 результатов должны быть меньше 100
2. Переключитесь на "С Atomics" — все 5 результатов должны быть ровно 100
3. Откройте DevTools → Performance: убедитесь, что Worker'ы действительно запускаются в отдельных потоках
4. Повторите 3-4 раза в режиме "Без Atomics" — каждый раз разные результаты (недетерминизм)
