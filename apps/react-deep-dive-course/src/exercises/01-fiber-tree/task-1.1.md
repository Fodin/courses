# Задание 1.1: Fiber Node Explorer

## Цель

Визуализировать Fiber-дерево по JSON-описанию: показать узлы с именами и тип-тегами, связи child (вниз), sibling (вправо) и обозначить return-связи (пунктиром). Это поможет прочувствовать структуру child/sibling/return не абстрактно, а глазами.

## Требования

1. Принять на вход массив `FiberNodeDef[]` — описание дерева (name, tag, children).
2. Визуализировать дерево: каждый узел — карточка с именем и tag-бейджем (цвет зависит от типа: FC — синий, HostComponent — зелёный, Fragment — серый и т.д.).
3. Дочерние узлы отображать ниже родителя со сдвигом влево, братские — на одном уровне с разделителем `→ sibling`.
4. Показывать стрелку `return ↑` у каждого узла, указывающую имя родителя.
5. Добавить интерактивность: при клике на узел выделить его и показать панель с его полями (name, tag, child: имя | null, sibling: имя | null, return: имя | null).
6. Использовать только `useState` и `inline CSS` — без внешних библиотек.
7. Предусмотреть кнопку "Сбросить выделение".

## Чеклист

- [ ] Дерево визуализируется по JSON-описанию
- [ ] Карточки узлов имеют имя и tag-бейдж с цветом
- [ ] Дочерние узлы отступают вниз-вправо от родителя
- [ ] Братские узлы расположены на одном уровне
- [ ] Есть подпись `return ↑ ParentName` у каждого узла
- [ ] Клик на узел выделяет его и показывает поля fiber
- [ ] Панель деталей показывает child/sibling/return по именам
- [ ] Выделение можно сбросить

## Как проверить себя

1. Загрузи дерево: `App → [Header, Main → [Article, Aside], Footer]`
2. Убедись, что `Main` имеет `child: Article`, `sibling: Footer`, `return: App`
3. Кликни на `Article` — в панели должно быть `child: null`, `sibling: Aside`, `return: Main`
4. Кликни на `Header` — `child: null`, `sibling: Main`, `return: App`
5. Добавь Fragment-узел и убедись, что он получает серый бейдж
