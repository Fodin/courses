# Задание 2.2: Симулятор балансировки нагрузки

## Цель

Построить интерактивный симулятор, который наглядно показывает, как разные алгоритмы балансировки распределяют запросы между серверами с разной мощностью.

## Требования

1. Создайте пул из 4 серверов с разной мощностью (weight): например, 3, 1, 2, 1
2. Реализуйте три алгоритма балансировки с переключением между ними:
   - **Round Robin** — запросы по кругу, без учёта мощности
   - **Weighted Round Robin** — с учётом весов серверов
   - **Least Connections** — на сервер с минимальным числом активных соединений
3. Добавьте кнопку «Отправить N запросов» (пакетная отправка, например 10-50 запросов)
4. Визуализируйте для каждого сервера:
   - Прогресс-бар текущей нагрузки (% от capacity)
   - Счётчик обработанных запросов
   - Мощность (weight) сервера
5. Покажите итоговую статистику: стандартное отклонение нагрузки, самый загруженный/простаивающий сервер
6. Кнопка «Сброс» для начала нового эксперимента

## Чеклист

- [ ] 4 сервера с разными весами отображаются с прогресс-барами
- [ ] Реализованы 3 алгоритма (Round Robin, Weighted RR, Least Connections)
- [ ] Переключение алгоритмов обновляет стратегию (не сбрасывает счётчики)
- [ ] Пакетная отправка запросов работает корректно
- [ ] Видна разница в распределении между алгоритмами
- [ ] Weighted RR отправляет больше запросов на серверы с большим весом
- [ ] Least Connections учитывает текущую загрузку

## Как проверить себя

1. Сбросьте счётчики, выберите Round Robin, отправьте 40 запросов — каждый сервер должен получить по 10
2. Сбросьте, выберите Weighted RR — сервер с weight=3 должен получить ~43% запросов (3/7)
3. Сбросьте, выберите Least Connections, отправляйте запросы по одному — запрос всегда идёт на наименее загруженный сервер
4. Сравните стандартное отклонение нагрузки между алгоритмами при серверах разной мощности
