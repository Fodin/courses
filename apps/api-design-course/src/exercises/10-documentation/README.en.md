# Level 10: API Documentation

## Documentation as Part of DX

**Developer Experience (DX)** is how easy and enjoyable it is for a developer to work with your API. Good documentation is the main component of DX.

Bad documentation = developer goes to a competitor. Good documentation = developer becomes an evangelist for your product.

## What Good Documentation Should Contain

| Element | Why |
|---------|-----|
| Getting Started | First working request within 5 minutes |
| Authentication | How to obtain and use credentials |
| Reference | Complete reference for all endpoints |
| Code Examples | Copyable examples in multiple languages |
| Error Codes | What each error means and how to fix it |
| Rate Limits | Limits and response headers |
| Sandbox | Safe environment for testing |
| SDK | Official libraries |
| Changelog | History of changes and breaking changes |

## Main Tools

**Swagger UI** — interactive documentation generated from an OpenAPI specification. Try it out right in the browser. Ideal for internal teams and API experiments.

**Redoc** — beautiful three-column layout from OpenAPI. The best choice for a public developer portal when design and readability matter.

**Stoplight** — a complete platform: API design + documentation + mock server + linting. For enterprise and large teams.

## Gold Standards

- **Stripe** — the gold standard: examples in 8 languages, interactive explorer, test data
- **Twilio** — excellent quickstart, clear structure
- **GitHub** — complete reference, great GraphQL support
