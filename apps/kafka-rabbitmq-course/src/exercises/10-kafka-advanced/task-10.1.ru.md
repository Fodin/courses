# Задание 10.1: Kafka Streams — топология

## Цель

Реализовать интерактивный визуализатор топологии Kafka Streams. Студент поймёт, как строится пайплайн потоковой обработки из операторов Source → Filter → Map → GroupBy → Aggregate → Sink, что происходит с данными на каждом этапе и почему порядок операторов важен.

## Требования

1. Определить тип `NodeType` — union type из шести значений: `'source' | 'filter' | 'map' | 'groupby' | 'aggregate' | 'sink'`.
2. Определить интерфейс `TopologyNode` с полями: `id: string`, `type: NodeType`, `label: string`, `config: Record<string, string>`, `description: string`.
3. Определить интерфейс `Message` с полями: `key: string`, `value: string`, `passed: boolean`.
4. Создать массив `TOPOLOGY_NODES` из шести узлов топологии:
   - **Source** — читает события из топика `orders`, параметры: `bootstrap`, `auto.offset.reset`
   - **Filter** — пропускает заказы с суммой `amount > 100`, параметр `null.handling: skip`
   - **Map / Transform** — меняет ключ на `userId`, обогащает данными пользователя, указывает `schema.registry`
   - **GroupBy** — перераспределяет по `userId`, создаёт repartition-топик с 12 партициями
   - **Aggregate** — Tumbling window 1 час, state store RocksDB, changelog-топик для fault tolerance
   - **Sink** — записывает результат в топик `user-order-stats`, `acks: all`, `replication.factor: 3`
5. Создать словарь `NODE_COLORS` — уникальный цвет для каждого из шести типов узлов.
6. Создать массив `SAMPLE_MESSAGES` из 5 сообщений с полями `key`, `value`, `passed`. Три сообщения должны проходить фильтр (`passed: true`, `amount > 100`), два — нет.
7. Реализовать состояния: `selectedNode`, `step` (текущий шаг симуляции), `processedMessages`.
8. Реализовать функцию `simulateStep`: переходит к следующему узлу. При достижении узла `filter` — фильтрует `SAMPLE_MESSAGES` по `passed: true` и сохраняет в `processedMessages`. При шаге 0 (Source) — заполняет `processedMessages` всеми сообщениями.
9. Реализовать функцию `reset`: сбрасывает все состояния в начальные значения.
10. Отобразить список узлов топологии вертикально. Активные узлы (уже пройденные шаги) выделяются цветом из `NODE_COLORS`. Между узлами — вертикальный разделитель-стрелка.
11. При клике на узел — показывать панель деталей с полем `description` и всеми парами `config`.
12. После прохождения Filter — отображать список сообщений, прошедших фильтр.
13. Кнопки: "Следующий шаг (N/6)" и "Сброс".
14. Информационный блок внизу: объяснение как читать топологию, роль GroupBy repartition и необходимость state store для Aggregate.

## Чеклист

- [ ] Тип `NodeType` объявлен как union из 6 значений
- [ ] Интерфейс `TopologyNode` содержит все 5 полей
- [ ] Интерфейс `Message` содержит `key`, `value`, `passed`
- [ ] Массив `TOPOLOGY_NODES` содержит ровно 6 узлов в правильном порядке
- [ ] У каждого узла заполнены `config` и `description`
- [ ] `NODE_COLORS` содержит цвет для каждого из 6 типов
- [ ] `SAMPLE_MESSAGES` содержит 5 сообщений, из которых 3 проходят фильтр
- [ ] `simulateStep` корректно фильтрует сообщения на шаге Filter
- [ ] `reset` сбрасывает `step`, `processedMessages` и `selectedNode`
- [ ] Узлы отображаются вертикально с разделителями
- [ ] Активные узлы подсвечиваются цветом, неактивные — серым
- [ ] Клик по узлу раскрывает панель с `description` и `config`
- [ ] После шага Filter виден список прошедших сообщений с ключом и значением
- [ ] Кнопка "Следующий шаг" отключается при `step >= 6`

## Как проверить себя

1. Нажмите "Следующий шаг" один раз — узел Source должен стать активным (окрашенным). Сообщения в панели — все 5.
2. Нажмите ещё раз — активируется Filter. Список сообщений должен сократиться до 3 (только `amount > 100`).
3. Кликните на узел "Aggregate" — должна открыться панель с описанием про RocksDB и Tumbling window, а также конфигурацией `window.type`, `window.size`, `state.store`, `changelog.topic`.
4. Нажмите "Следующий шаг" до конца (6/6). Кнопка должна стать неактивной. Все узлы окрашены.
5. Нажмите "Сброс" — топология возвращается в начальное состояние: все узлы серые, сообщений нет, шаг 0/6.
