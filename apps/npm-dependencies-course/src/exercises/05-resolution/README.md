# Уровень 5: Алгоритм разрешения зависимостей

## Как npm строит дерево зависимостей

Когда вы запускаете `npm install`, npm не просто скачивает пакеты из `package.json`. Он выполняет полный алгоритм разрешения (resolution):

1. **Читает `package.json`** — собирает список прямых зависимостей с диапазонами версий
2. **Запрашивает реестр** — получает метаданные каждого пакета (список версий и их зависимости)
3. **Выбирает версию** — для каждой зависимости находит максимальную версию, удовлетворяющую диапазону (`max-satisfying`)
4. **Рекурсивно разворачивает** — для каждого выбранного пакета повторяет шаги 2–3 с его зависимостями
5. **Строит idealTree** — идеальное плоское дерево с учётом дедупликации
6. **Reify** — применяет изменения к реальному `node_modules`

## Max-satisfying: выбор версии

Для диапазона `^1.2.3` npm выбирает **наибольшую версию ≥ 1.2.3 и < 2.0.0**, доступную в реестре. Это называется `semver.maxSatisfying`.

```
Диапазон: ^1.2.3
Доступные версии: 1.2.3, 1.2.5, 1.3.0, 1.5.1, 2.0.0
Выбор: 1.5.1  ← максимальная в пределах мажора
```

## Транзитивные зависимости

Ваш проект зависит от A, A зависит от B, B зависит от C — C является транзитивной зависимостью вашего проекта. npm рекурсивно разрешает всё дерево.

## Дедупликация в idealTree

Перед записью в `node_modules` npm строит «идеальное дерево» (idealTree) и применяет дедупликацию: если несколько пакетов совместимы с одной версией — используется одна копия. При конфликте версий — вложенная установка (см. уровень 4).

## Роль Arborist

**Arborist** — внутренний модуль npm (с версии npm v7), отвечающий за управление деревом зависимостей. Он:

- строит idealTree (желаемое состояние)
- сравнивает с actualTree (текущий `node_modules`)
- выполняет reify: вносит минимально необходимые изменения

До Arborist npm перепересчитывал всё дерево целиком. Arborist делает это инкрементально.

## Детерминизм через lockfile

Без lockfile результат `npm install` может отличаться на разных машинах — реестр пополняется новыми версиями. С lockfile npm берёт точные версии из него и пропускает шаг max-satisfying.

```
С lockfile:   package-lock.json → точные версии → детерминированный результат
Без lockfile: реестр → max-satisfying → результат зависит от момента времени
```

## Две версии одного пакета

Два пакета могут требовать разные мажорные версии одной библиотеки — и обе сосуществуют в дереве. Node.js разрешает `require()` путём обхода директорий вверх, поэтому каждый пакет найдёт свою версию.

## Тизер: overrides

В npm v8.3+ поле `overrides` в `package.json` позволяет принудительно задать версию транзитивной зависимости для всего дерева. Это полезно для срочных патчей безопасности. Подробно — в уровне 9.

## ⚠️ Типичные ошибки

❌ Думать, что `npm install` всегда ставит одни и те же версии без lockfile  
✅ Всегда коммитить `package-lock.json` для воспроизводимых сборок

❌ Удалять `package-lock.json` при проблемах вместо диагностики  
✅ Использовать `npm ls` и `npm explain` для понимания дерева
