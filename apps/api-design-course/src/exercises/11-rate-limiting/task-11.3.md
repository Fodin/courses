# Задание 11.3: Проектирование Rate Limiting

## Цель

Реализовать интерактивный self-check по проектированию rate limiting для трёх реальных сценариев. Студент изучает сценарий, пишет своё решение, затем сравнивает с эталоном.

## Требования

1. Три карточки-сценария (кликабельные): публичный API с тарифами, внутренний API микросервисов, BFF для мобильного приложения
2. При выборе сценария — показать textarea для ответа студента с placeholder-подсказкой о том, что описать
3. Кнопка «Показать эталонное решение» открывает панель с четырьмя блоками:
   - **Алгоритм** (выделен заголовок с цветом)
   - **Лимиты** (список с bullet-points)
   - **HTTP-заголовки** (в тёмном блоке с моноспейсом)
   - **Ключ идентификации** + **Дополнительные механизмы**
4. Активная карточка выделена рамкой (#6366f1), у неактивных — #e2e8f0
5. Ответы студента сохраняются при переключении между сценариями

## Чеклист

- [ ] Три карточки сценариев с иконкой, названием, описанием
- [ ] Клик по карточке раскрывает textarea для ответа
- [ ] Textarea сохраняет текст при переключении сценариев
- [ ] Кнопка «Показать эталонное решение» раскрывает панель
- [ ] Панель эталона: алгоритм, лимиты, заголовки (моноспейс), ключ, дополнительно
- [ ] Состояние revealed сохраняется для каждого сценария отдельно

## Данные для сценариев

### Сценарий 1: Публичный API для разработчиков
Три тарифа: Free (100/час), Pro (10k/час), Enterprise (100k/час).
Алгоритм: Token Bucket. Ключ: API Key из Authorization: Bearer.

### Сценарий 2: Внутренний API между микросервисами
8 сервисов, 3 тяжёлых потребителя. Защита от каскадных отказов.
Алгоритм: Sliding Window Counter. Ключ: Service ID из X-Service-ID.

### Сценарий 3: BFF для мобильного приложения
2 млн пользователей. Разные лимиты для /auth и общего API.
Алгоритм: Sliding Window Log для /auth + Token Bucket для основного. Ключ: User ID / IP.

## Как проверить себя

1. Для каждого сценария — напиши своё решение (хотя бы 3-5 пунктов)
2. Нажми «Показать эталон» и сравни
3. Обрати внимание: алгоритм зависит от типа API, ключ — от модели авторизации
