# Задание 14.1: Конструктор API — Библиотека

## Цель

Пройти все 7 шагов пошагового мастера проектирования REST API для системы «Библиотека». На каждом шаге — проработать чеклист и сверить своё решение с эталоном.

## Требования

1. Шаг 1 — определить все 6 ресурсов системы (книги, авторы, читатели, бронирования, вложенные ресурсы)
2. Шаг 2 — спроектировать URL-структуру: правильный нейминг, иерархия, query-параметры
3. Шаг 3 — составить матрицу HTTP-методов для каждого ресурса (GET/POST/PUT/PATCH/DELETE)
4. Шаг 4 — определить статус-коды для всех операций, включая error-сценарии
5. Шаг 5 — спроектировать модели данных с правильными форматами (camelCase, ISO 8601, деньги)
6. Шаг 6 — добавить пагинацию, фильтрацию и сортировку для списочных эндпоинтов
7. Шаг 7 — пройти финальный чеклист из 10 пунктов и подвести итоги

## Чеклист

- [ ] Шаг 1: определены 4 корневых ресурса и 2 вложенных
- [ ] Шаг 2: URL используют нижний регистр, множественное число, нет глаголов
- [ ] Шаг 3: GET не изменяет данные, DELETE идемпотентен
- [ ] Шаг 4: ни один успешный ответ не возвращает 4xx/5xx
- [ ] Шаг 5: все даты в ISO 8601, ID — строки, цены с валютой
- [ ] Шаг 6: пагинация через page/limit с meta в ответе
- [ ] Шаг 7: финальный чеклист пройден, все 10 пунктов отмечены

## Как проверить себя

1. Нажми «Показать» на каждом шаге — сравни своё решение с эталонным
2. Если твой ответ отличается — разберись, почему эталон именно такой
3. На шаге 3 проверь: ни один GET-запрос не должен создавать или удалять данные
4. На шаге 4 найди хотя бы одну операцию с кодом 409 — почему именно 409, а не 400?
5. На шаге 7 убедись, что ты можешь обосновать каждый пункт финального чеклиста

## Подсказки

- Вложенный ресурс (books/{id}/copies) выбирай тогда, когда экземпляр без книги не имеет смысла
- 409 Conflict — для бизнес-конфликтов состояния (книга уже забронирована, нет экземпляров)
- Пагинация нужна даже для «маленьких» коллекций — библиотека может вырасти
