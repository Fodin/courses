# Задание 12.3 — Смешанные тип/значение зависимости в цикле пакетов (сложное)

## Цель

Разобраться, какая часть смешанного импорта (`{ значение, type Тип }`) реально нужна в рантайме, и разорвать цикл, не сломав легитимную рантайм-связь.

## Что дано

- `packages/b/src/index.ts` — пакет `@repo/b` (🔒 только чтение). Импортирует из `@repo/a` смешанный клоз `{ AHelper, type AShape }`: `AHelper()` реально вызывается в рантайме (`makeA`), `AShape` используется только как тип.
- `packages/a/src/index.ts` — пакет `@repo/a`. Импортирует из `@repo/b` смешанный клоз `{ BHelper, type BShape }`: `BShape` реально используется как тип (`describeShape`), а вот `BHelper` — импортирован, но нигде не вызывается. Это мёртвый рантайм-импорт, оставшийся после рефакторинга.

## Требования

1. Откройте `packages/a/src/index.ts` и найдите импорт `import { BHelper, type BShape } from '@repo/b'`.
2. Убедитесь, что `BHelper` в файле действительно нигде не используется.
3. Удалите неиспользуемое значение `BHelper` из импорта и оставьте чистый `import type { BShape } from '@repo/b'`.
4. НЕ трогайте `packages/b/src/index.ts` — связь `@repo/b → @repo/a` (вызов `AHelper()`) легитимна и должна остаться рантайм-импортом.
5. Нажмите «Проверить» — цикл `@repo/a ↔ @repo/b` должен исчезнуть, а `makeA` в `@repo/b` продолжает работать.

## Чеклист

- [ ] Импорт `@repo/b` в `packages/a/src/index.ts` целиком типовой (`import type`)
- [ ] Неиспользуемое значение `BHelper` удалено из `@repo/a`
- [ ] Связь `@repo/b → @repo/a` (`AHelper`) осталась рантайм-импортом
- [ ] В графе рантайм-импортов нет цикла
- [ ] Пройти квиз уровня ≥ 80%

## Как проверить себя

Смешанный импорт вида `{ foo, type Bar }` **не** считается типовым целиком — движок видит в нём рантайм-ребро, даже если `foo` нигде не используется. Прежде чем ставить `import type`, убедитесь, что в файле действительно не осталось ни одного вызова значения из соседнего пакета.
