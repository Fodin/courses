# Задание 7.3 — Do-нотация через генераторы

## Цель

Реализовать `Do`-хелпер для Either и использовать его для парсинга конфига. Показать, что Do-нотация — это синтаксический сахар над flatMap с идентичной семантикой.

## Требования

1. Реализуйте функцию `Do<L, R>(gen: () => Generator<Either<L, any>, R, any>): Either<L, R>`:
   - Создаёт итератор через `gen()`
   - При каждом `yield` проверяет: если `Left` — немедленно возвращает `Left` (short-circuit)
   - Если `Right` — передаёт распакованное значение обратно в генератор
   - Возвращаемое значение генератора оборачивает в `Right`
2. Реализуйте четыре валидатора, возвращающих `Either<string, T>`:
   - `parseHost(host: string)` — пустая строка или спецсимволы → `Left`
   - `parsePort(port: string)` — не число или вне 1-65535 → `Left`
   - `parseDbName(name: string)` — пустая строка или невалидный идентификатор → `Left`
   - `parseTimeout(timeout: string)` — не число, ≤ 0, или > 30000 → `Left`
3. Реализуйте `parseConfigFlatMap` — вложенные `eitherFlatMap` (4 уровня вложенности)
4. Реализуйте `parseConfigDo` — через `Do(function* () { ... })` с `yield` для каждого шага
5. Оба варианта должны принимать одни и те же данные и возвращать **идентичный** результат
6. Добавьте поля ввода для `host`, `port`, `dbName`, `timeout`
7. Кнопка "Выполнить" запускает оба варианта и показывает результаты рядом
8. Добавьте индикатор "Результаты идентичны" / "Результаты различаются"
9. При успехе (`Right`) показывайте строку подключения: `postgres://host:port/dbName?timeout=N`
10. Добавьте кнопку "Невалидные данные" с заведомо ошибочными значениями

## Чеклист

- [ ] `Do` корректно обрабатывает short-circuit при `Left`
- [ ] `Do` передаёт распакованное значение через `iterator.next(value)`
- [ ] `Do` оборачивает итоговый `return` в `Right`
- [ ] Все 4 валидатора реализованы с конкретными сообщениями ошибок
- [ ] `parseConfigFlatMap` использует вложенный `eitherFlatMap`
- [ ] `parseConfigDo` использует `Do` с `yield`
- [ ] Оба подхода возвращают идентичные результаты на одних данных
- [ ] Валидные данные → оба показывают `Right({...})`
- [ ] Ошибочные данные → оба показывают `Left("...")` с первой ошибкой
- [ ] Индикатор идентичности работает корректно

## Как проверить себя

1. Введите валидные данные (`localhost`, `5432`, `mydb`, `3000`) → оба Right, результаты идентичны
2. Введите пустой host → оба Left с сообщением про host
3. Введите port = 99999 → оба Left с сообщением про port
4. Введите все поля с ошибками → ошибка только первого поля (short-circuit!)
5. Нажмите "Невалидные данные" → убедитесь, что Do прерывается на первом Left

## Подсказки

- `Do` реализует ту же логику, что `flatMap`, но через итерацию генератора
- Ключевая строка: `result = iterator.next(either.value)` — именно так yield "возвращает" значение в генератор
- `yield` в генераторе — это синтаксический способ написать `flatMap(value =>`, а `return` — это `Right(finalValue)`
- Аналогия с async/await: `yield` в Do → `await`, `Left` → `throw`/`reject`
