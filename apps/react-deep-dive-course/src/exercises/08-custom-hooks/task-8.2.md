# Задание 8.2: usePrevious и useLatestCallback

## Задание

Два взаимосвязанных паттерна работы с `useRef`:

**(A)** Реализовать `usePrevious<T>(value: T): T | undefined` — хук, возвращающий значение из предыдущего рендера.

**(B)** Реализовать `useLatestCallback<T>(callback: T): T` — хук, возвращающий стабильную функцию, которая всегда вызывает актуальную версию колбэка (решение closure trap).

## Цель

Понять, когда `useRef` является правильным инструментом вместо `useState`, разобраться с timing-ом `useEffect` (после рендера), и научиться решать closure trap через "latest ref" паттерн.

## Требования

### Часть A: usePrevious

1. Реализовать `usePrevious<T>(value: T): T | undefined`
2. Использовать `useRef` без зависимостей (хук без deps array — обновляется после каждого рендера)
3. Вернуть `ref.current` до обновления эффекта
4. Демо: счётчик с кнопками +1 и -1, показывающий текущее и предыдущее значение
5. Показать объяснение timing-а: почему значение в ref — это значение из прошлого рендера

### Часть B: useLatestCallback

1. Реализовать `useLatestCallback<T extends Function>(callback: T): T`
2. Хранить callback в `useRef`, обновлять через `useEffect` без deps
3. Возвращать стабильную функцию через `useCallback((...args) => ref.current(...args), [])`
4. Демо: `setInterval`, который каждую секунду логирует актуальное значение счётчика
5. Показать closure trap без паттерна и корректную работу с ним

## Чеклист

- [ ] `usePrevious` использует `useRef`, а не `useState`
- [ ] `useEffect` в `usePrevious` вызывается без deps array (после каждого рендера)
- [ ] Демо A корректно показывает предыдущее значение (не текущее!)
- [ ] `useLatestCallback` хранит callback в ref и обновляет через useEffect
- [ ] Возвращаемая функция — стабильна (useCallback с [])
- [ ] Демо B показывает, что setInterval видит актуальное значение счётчика
- [ ] Рядом с демо B показан "сломанный" вариант с closure trap для сравнения

## Как проверить себя

**Часть A:**
1. Нажмите +1 несколько раз — "предыдущее" всегда должно отставать на 1
2. Сразу после mount — "предыдущее" должно быть `undefined`

**Часть B:**
1. Нажмите +1 три раза быстро, затем подождите — лог должен показать актуальный счётчик (не 0)
2. В "сломанном" варианте лог должен показывать 0 всегда (closure trap)
3. Убедитесь: setInterval не пересоздаётся при каждом нажатии (один экземпляр на весь lifecycle)
