# Задание 13.3: Компенсирующие действия

## Цель

Реализовать **симулятор компенсирующих действий** с подробным отображением бизнес-эффектов каждого шага. Компонент показывает не просто статусы, а конкретные изменения в системе: какие данные были затронуты при выполнении шага и что именно было отменено при компенсации. Студент должен понять разницу между технической компенсацией и бизнес-смыслом отката.

## Требования

1. Объявить тип `CompensationStatus`: `'idle' | 'done' | 'failed' | 'compensating' | 'compensated'`.
2. Объявить интерфейс `CompensationStep` с полями: `id: string`, `stepNumber: number`, `service: string`, `action: string`, `compensationAction: string`, `effect: string`, `compensationEffect: string`, `color: string`, `status: CompensationStatus`.
3. Объявить константу `COMP_STEPS` — массив из 4 шагов:
   - OrderService: действие "Создать заказ", эффект `'ORDER #1234 создан, статус: PENDING'`, компенсация "Отменить заказ", компенсирующий эффект `'ORDER #1234 отменён, статус: CANCELLED'`.
   - PaymentService: "Списать средства" / `'$99.99 списано с карты *1234'` / "Вернуть средства" / `'$99.99 возвращено на карту *1234'`.
   - InventoryService: "Зарезервировать товар" / `'SKU-555 зарезервирован (остаток: 9)'` / "Снять резервирование" / `'SKU-555 освобождён (остаток: 10)'`.
   - ShippingService: "Создать доставку" / `'Delivery #D789 создана в системе'` / "Отменить доставку" / `'Delivery #D789 отменена'`.
4. Реализовать состояния: `steps`, `failAtStep` (по умолчанию 2), `running`, `effects: string[]`, `phase`, `abortRef`.
5. Реализовать вспомогательные функции `getStepBg(status, color)` и `getStepBorderColor(status, color)` — возвращают цвет фона и рамки карточки шага в зависимости от статуса.
6. Реализовать функцию `runSimulation`:
   - Последовательно обходит шаги с задержкой `sleep(600)`.
   - При успешном шаге: статус → `'done'`, добавить в `effects` строку `[DONE] Шаг N: {effect}`.
   - При шаге с ошибкой (`i === failAtStep`): статус → `'failed'`, добавить `[FAILURE] Шаг N: {service} - ошибка выполнения`, запустить компенсацию.
   - Компенсация: добавить в `effects` строку `--- Начало компенсации (в обратном порядке) ---`, затем обойти успешные шаги в обратном порядке: статус `'compensating'` (700мс), затем `'compensated'`, добавить `[COMPENSATED] Шаг N: {compensationEffect}`.
   - В конце добавить `'--- Компенсация завершена. Данные восстановлены ---'`.
   - При `failAtStep === -1` — успешное завершение: `[SUCCESS] Все шаги выполнены успешно!`.
7. Реализовать `reset`.
8. Отрисовать вертикальный список шагов с нумерованными кружками и соединяющими линиями между ними:
   - Кружок с номером шага — цвет определяется `getStepBorderColor`.
   - Вертикальная линия между кружками — цвет: зелёный при `'done'`, красный при `'compensated'`, серый по умолчанию.
   - Карточка шага: шапка с именем сервиса и названием действия (меняется на `compensationAction` при откате), статус-бейдж, строка с эффектом в моноширинном шрифте.
9. Добавить кнопки выбора падающего шага ("Шаг 1", "Шаг 2", "Шаг 3", "Шаг 4", "Без ошибок"). Активная кнопка имеет красную рамку и красный текст (зелёный для "Без ошибок").
10. Добавить кнопку-тоггл "Симулировать" / "Сбросить" (`marginLeft: 'auto'`).
11. Отрисовать лог эффектов в тёмном блоке: строки `[FAILURE]` красным, `[COMPENSATED]` оранжевым, `[SUCCESS]` зелёным, `---` серым.
12. После завершения (`phase === 'done'`) показать итоговый блок: при успехе зелёный с текстом "Saga выполнена успешно. Все 4 шага зафиксированы.", при ошибке красный с текстом "Шаг N завершился ошибкой. Откатано M шаг(ов). Система консистентна."

## Чеклист

- [ ] Тип `CompensationStatus` объявлен с 5 значениями
- [ ] Интерфейс `CompensationStep` содержит `effect` и `compensationEffect`
- [ ] `COMP_STEPS` содержит 4 шага с реалистичными бизнес-эффектами
- [ ] `getStepBg` и `getStepBorderColor` возвращают разные значения для каждого статуса
- [ ] Вертикальная линия между кружками меняет цвет при `'compensated'`
- [ ] Карточка показывает `compensationAction` вместо `action` при откате
- [ ] Карточка показывает `compensationEffect` вместо `effect` при откате
- [ ] Строка эффекта в моноширинном шрифте
- [ ] Компенсация выполняется строго в обратном порядке завершённых шагов
- [ ] Кнопки выбора шага: активная — красная рамка, "Без ошибок" — зелёная
- [ ] Кнопки заблокированы (`disabled`) во время симуляции
- [ ] Лог эффектов разделяет строки по цвету (красный/оранжевый/зелёный/серый)
- [ ] Итоговый блок показывает количество откатанных шагов

## Как проверить себя

1. Откройте задание — 4 карточки шагов с серыми кружками-номерами.
2. Выберите "Шаг 3" (InventoryService) как точку ошибки и нажмите "Симулировать".
3. Шаги 1 и 2 последовательно переходят в `done` — их карточки показывают зелёную рамку и строку с эффектом (ORDER создан, деньги списаны).
4. Шаг 3 переходит в `failed` — карточка с красной рамкой и текстом ошибки.
5. В логе появляется `--- Начало компенсации (в обратном порядке) ---`.
6. Шаг 2 (PaymentService): сначала оранжевый статус "Откат...", затем серый "Откатано", строка с `compensationEffect` — деньги возвращены.
7. Шаг 1 (OrderService): аналогично, заказ отменён.
8. Вертикальные линии между откатанными шагами становятся красными.
9. Итоговый блок: "Шаг 3 завершился ошибкой. Откатано 2 шаг(ов). Система консистентна."
10. Выберите "Без ошибок" — все 4 шага проходят успешно, итог зелёный.
