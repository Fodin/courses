# Задание 4.2 — Асинхронный pipe

## Цель

Реализовать `asyncPipe` для цепочек async-функций и визуализировать выполнение API-пайплайна с анимированным таймлайном.

## Требования

1. Реализуйте `asyncPipe(...fns)`:
   - Принимает функции вида `(x) => Promise<y>`
   - Возвращает async-функцию: последовательно применяет каждую через `await`
   - При ошибке в любом шаге — пайплайн прерывается и ошибка пробрасывается

2. Создайте 4 шага симуляции API:
   - `fetchUser(id)` — задержка 500ms, возвращает `{id, name, email, role}`
   - `enrichProfile(user)` — задержка 300ms, добавляет `{avatar, bio}`
   - `validateAccess(profile)` — задержка 200ms, роль `guest` вызывает ошибку
   - `formatResponse(data)` — без задержки, форматирует для UI

3. Визуальный таймлайн:
   - Каждый шаг — строка с именем, шкалой длительности и статусом
   - Текущий выполняющийся шаг подсвечивается жёлтым
   - Завершённый шаг — зелёным с кратким preview результата
   - Шаг с ошибкой — красным

4. Управление:
   - Select для userId (минимум 3 варианта: admin, user, guest)
   - Select для точки принудительного отказа (без ошибок / ошибка в шаге N)
   - Кнопка "Запустить" — запускает пайплайн, блокируется во время выполнения

5. Отображение итога:
   - Успех: карточка с именем, ролью и bio
   - Ошибка: блок с сообщением об ошибке

## Чеклист

- [ ] `asyncPipe` реализован через `for...of` с `await` или через `.then`-chain
- [ ] Шаги выполняются строго последовательно, не параллельно
- [ ] Таймлайн обновляется в реальном времени (шаг за шагом)
- [ ] Ошибка в шаге прерывает пайплайн и показывает сообщение
- [ ] Повторный запуск сбрасывает все состояния шагов

## Как проверить себя

1. Запустите с userId=1 (admin), без ошибок — все шаги должны позеленеть последовательно
2. Запустите с userId=3 (guest) — `validateAccess` должен упасть с ошибкой о запрете доступа
3. Запустите с userId=99 — `fetchUser` должен упасть сразу
4. Включите "Ошибка в enrichProfile" — второй шаг упадёт даже для admin

**Подсказка:** Реализуйте `asyncPipe` через обычный `for...of` с `await` — это проще
отлаживать, чем `.reduce(promise.then(fn), ...)`. Важно: `for...of` выполняет шаги
строго последовательно в отличие от `Promise.all`.
