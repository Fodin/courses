# Статус-коды и обработка ошибок

## Зачем нужны правильные статус-коды?

HTTP-статус — это не просто число. Это сигнал всей цепочке: браузеру, CDN, мониторингу, клиентскому коду. Когда API возвращает 200 при ошибке — ломается мониторинг, ломается retry-логика, ломается опыт разработчика.

## Группы статус-кодов

| Группа | Смысл | Примеры |
|--------|-------|---------|
| **1xx** | Информационные | 100 Continue, 101 Switching Protocols |
| **2xx** | Успех | 200 OK, 201 Created, 204 No Content |
| **3xx** | Редиректы | 301 Moved Permanently, 304 Not Modified |
| **4xx** | Ошибки клиента | 400, 401, 403, 404, 409, 422, 429 |
| **5xx** | Ошибки сервера | 500, 502, 503, 504 |

## Самые важные коды для REST API

| Код | Имя | Когда |
|-----|-----|-------|
| **200** | OK | GET успешен, PUT/PATCH вернули обновлённый объект |
| **201** | Created | POST создал новый ресурс |
| **204** | No Content | DELETE, PUT/PATCH без тела в ответе |
| **400** | Bad Request | Сломанный JSON, неверный тип параметра |
| **401** | Unauthorized | Нет токена, токен невалиден |
| **403** | Forbidden | Токен есть, но нет прав |
| **404** | Not Found | Ресурс не существует |
| **409** | Conflict | Дублирование, конфликт версий |
| **422** | Unprocessable Entity | Ошибки валидации полей |
| **429** | Too Many Requests | Rate limit превышен |
| **500** | Internal Server Error | Баг в коде сервера |

## 200 vs 201 vs 204

- **200** — запрос выполнен, ответ содержит данные
- **201** — создан новый ресурс (POST), в заголовке `Location` — его URL
- **204** — успех, но тело ответа отсутствует (DELETE, некоторые PUT/PATCH)

## 400 vs 422

- **400** — запрос "сломан": невалидный JSON, неверный тип, отсутствует обязательный заголовок
- **422** — JSON правильный, но значения не проходят бизнес-валидацию (email неверного формата, пароль слишком короткий)

## 401 vs 403

- **401** — "кто ты?" — клиент не аутентифицирован, нет токена
- **403** — "ты известен, но тебе сюда нельзя" — нет прав для этого действия

## Структурированные ошибки (RFC 7807)

Стандарт Problem Details определяет единый формат для ошибок:

```json
{
  "type": "https://api.example.com/errors/validation-failed",
  "title": "Validation Failed",
  "status": 422,
  "detail": "One or more fields did not pass validation.",
  "instance": "/api/users",
  "errors": [
    { "field": "email", "message": "Must be a valid email address" }
  ]
}
```

Content-Type: `application/problem+json`
