# Задание 11.3: Selective Hydration

## Цель

Понять механику Selective Hydration: как React приоритизирует гидрацию компонентов на основе пользовательских взаимодействий, прерывая стандартный порядок (слева направо) в пользу того, с чем пользователь взаимодействует прямо сейчас.

## Задание

Реализуйте `SelectiveHydrationDemo` — страницу с 4 секциями в двух режимах гидрации: стандартная (последовательная) и приоритетная (по клику).

### Секции

```ts
const SECTIONS = [
  { id: 'header',   label: 'Header',   baseCost: 1200 },  // мс на гидрацию
  { id: 'sidebar',  label: 'Sidebar',  baseCost: 800  },
  { id: 'content',  label: 'Content',  baseCost: 2000 },
  { id: 'comments', label: 'Comments', baseCost: 1500 },
]
```

### Состояния секции

- `'static'` — серый фон, текст "Не гидрирован", некликабельный (pointer-events: none)
- `'hydrating'` — синий пульсирующий контур, текст "Гидрация...", анимация pulse
- `'hydrated'` — зелёный фон, текст "Интерактивный!", кнопка с `onClick`

### Шаг 1. Стандартная гидрация

Кнопка "Запустить стандартную гидрацию". Секции гидрируются последовательно в порядке Header → Sidebar → Content → Comments. Каждая занимает `baseCost` миллисекунд в состоянии `'hydrating'`.

### Шаг 2. Приоритетная гидрация (Selective)

Кнопка "Запустить selective hydration". Все секции в состоянии `'static'`, но на них можно кликнуть (несмотря на pointer-events: none — используйте overlay с onClick). Фоновая гидрация идёт в обычном порядке с задержками.

Если пользователь кликает на секцию в состоянии `'static'` или `'hydrating'`:
1. Если секция ещё не началась — она немедленно переходит в `'hydrating'` и гидрируется за `baseCost * 0.3` мс (ускоренно, т.к. приоритет!)
2. Если другая секция сейчас гидрируется (`'hydrating'`) — она "ставится на паузу" и возвращается в очередь
3. После приоритетной гидрации — продолжается нормальная очередь

### Шаг 3. Визуальные индикаторы

- `'static'` — серая карточка с текстом "Нажмите для приоритетной гидрации" (в selective режиме)
- `'hydrating'` — синяя пульсация + прогресс-бар внутри карточки (от 0 до 100% за baseCost мс)
- `'hydrated'` — зелёная карточка + время гидрации в мс + badge "Приоритетный" если был клик

### Шаг 4. Лог событий

Панель справа (или снизу) — лог с временными метками:
```
[0ms]    Гидрация Header начата (стандартная)
[800ms]  Клик на Comments → приоритет!
[800ms]  Header приостановлен
[800ms]  Гидрация Comments начата (приоритетная, 450ms)
[1250ms] Comments гидрирован ✓
[1250ms] Header возобновлён
```

### Шаг 5. Кнопка Reset

Сбросить все секции в `'static'`, очистить лог, остановить таймеры.

## Требования

1. 4 секции с состояниями `static` / `hydrating` / `hydrated`
2. Стандартная гидрация: последовательно, каждая за `baseCost` мс
3. Selective гидрация: клик приоритизирует секцию, прерывает текущую гидрацию
4. Прогресс-бар внутри `hydrating`-секции (CSS transition с анимацией)
5. Badge "Приоритетный" на секциях, гидрированных по клику
6. Лог событий с временными метками (относительно старта)
7. Корректная очистка таймеров (useRef для хранения timeout ID)
8. Кнопка Reset очищает всё
9. Секции в selective режиме показывают "Нажмите для приоритета" в состоянии `static`

## Чеклист

- [ ] Три состояния секции визуально различимы (серый / синий пульс / зелёный)
- [ ] Стандартная гидрация идёт строго последовательно
- [ ] Клик на `static`-секцию в selective режиме → приоритетная гидрация
- [ ] Прерванная секция возвращается в очередь и гидрируется после приоритетной
- [ ] Прогресс-бар корректно отображает прогресс за `baseCost` мс
- [ ] Badge "Приоритетный" только у секций, гидрированных кликом
- [ ] Лог содержит все события с корректными временными метками
- [ ] Reset полностью сбрасывает состояние
- [ ] Нет утечки таймеров (cleanup при размонтировании и при Reset)

## Как проверить себя

1. Запустите стандартную гидрацию: Header → Sidebar → Content → Comments в порядке очереди, без пропусков
2. Нажмите Reset, запустите selective гидрацию
3. Подождите, пока начнётся гидрация Header, затем кликните на Comments
4. Comments должен гидрироваться первым (быстро), Header — после
5. Проверьте, что badge "Приоритетный" есть у Comments и нет у Header
6. Проверьте лог: все события зафиксированы корректно
7. Нажмите Reset — всё сбрасывается, таймеры остановлены
