# Задание 4.3: Микротаски — визуализатор порядка выполнения

## Цель

Построить пошаговый визуализатор, наглядно показывающий, как Call Stack, Microtask Queue и Macrotask Queue взаимодействуют при выполнении кода с промисами и setTimeout. Второй режим — демонстрация "starvation": бесконечные рекурсивные промисы блокируют макротаски навсегда.

## Требования

1. **Режим "Пошаговое выполнение":**
   - Слева — code-сниппет с подсветкой текущей активной строки
   - Справа — три блока: Call Stack, Microtask Queue, Macrotask Queue
   - Снизу — поле вывода консоли (накопительное)
   - Кнопка "Шаг вперёд" переходит к следующему событию
   - Кнопка "Сброс" возвращает в начало
   - Описание текущего шага показывает, что происходит и почему

2. **Порядок шагов** должен демонстрировать вывод `A → E → B → C → D`:
   - `console.log('A')` — синхронно
   - `Promise.resolve().then(→'B').then(→'C')` — ставит микротаски
   - `setTimeout(→'D', 0)` — ставит в Macrotask Queue
   - `console.log('E')` — синхронно
   - Drain microtasks: `B`, потом `C`
   - Только потом макротаск: `D`

3. **Режим "Starvation":**
   - Показывает code-сниппет с рекурсивным `Promise.resolve().then(recursive)`
   - Кнопка запускает 3-секундную симуляцию
   - Счётчик микротасков растёт, счётчик макротасков почти не меняется
   - Объяснительный текст о том, почему макротаск никогда не выполняется

## Как проверить себя

1. Откройте компонент в режиме "Пошаговое выполнение"
2. Нажмите "Шаг вперёд" — появляется 'A' в консоли, Call Stack заполнен
3. Нажмите ещё раз — микротаск появляется в Microtask Queue
4. Продолжайте нажимать — убедитесь, что 'D' (setTimeout) появляется ПОСЛЕДНИМ
5. Итоговый вывод консоли: `A, E, B, C, D`
6. Перейдите во вкладку "Starvation", нажмите кнопку — счётчик микротасков должен расти, макротасков — оставаться минимальным
