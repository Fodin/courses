# Task 3.3 — ACK/NACK симулятор

## Цель

Создать интерактивный симулятор жизненного цикла сообщений в RabbitMQ с полноценным state machine. Пользователь отправляет сообщения и вручную управляет их подтверждением: ACK (успешная обработка), NACK+Requeue (повторная доставка), NACK+DLQ (в мёртвую очередь), Timeout (не ответил вовремя).

## Требования

1. Кнопка "Отправить сообщение" создаёт новое сообщение, которое проходит через состояния: `ready` → `delivering` → `delivered` → `processing`.
2. Настройка `prefetch` (1–5 через range input): если количество активных сообщений достигает prefetch, новые сообщения не отправляются — в лог пишется "BLOCKED".
3. Чекбокс "no-ack mode": при включении сообщения автоматически переходят в `acked` без ручного подтверждения.
4. Каждое сообщение в `delivered`/`processing`/`redelivering` состоянии показывает 4 кнопки действий: ACK, NACK+Requeue, NACK+DLQ, Timeout.
5. ACK: сообщение переходит в `acked`, пишется в лог, удаляется из очереди.
6. NACK+Requeue: `nacked` → `requeued` → `redelivering` → `processing` с увеличением attempt и флагом `redelivered=true`.
7. NACK+DLQ: `nacked` → `dead-lettered`, пишется в лог про dead-letter-exchange.
8. Timeout: `timeout` → `redelivering` → `processing` с новым delivery-tag.
9. Счётчик `delivery-tag` монотонно возрастает, новый тег присваивается при каждой (пере)доставке.
10. Статистика (Всего / ACK / DLQ / В работе) обновляется в реальном времени.
11. Лог событий в терминальном стиле (тёмный фон): каждая запись — время, тип события, детали. Последние 40 записей, новые сверху.
12. Кнопка "Очистить" сбрасывает все сообщения и лог, счётчики начинаются заново.

## Чеклист

- [ ] Отправка сообщения создаёт запись с уникальным id и delivery-tag
- [ ] Сообщение проходит анимированно через состояния (задержки ~500-600 мс)
- [ ] Prefetch-лимит блокирует отправку с записью в лог
- [ ] No-ack mode автоматически подтверждает сообщения
- [ ] Кнопки ACK / NACK+Requeue / NACK+DLQ / Timeout видны только для активных сообщений
- [ ] NACK+Requeue увеличивает attempt, выставляет redelivered=true, назначает новый delivery-tag
- [ ] NACK+DLQ переводит в dead-lettered без возврата в очередь
- [ ] Timeout переотправляет с новым delivery-tag и redelivered=true
- [ ] Статистика обновляется корректно после каждого действия
- [ ] Лог пишется для каждого события с временем
- [ ] Кнопка "Очистить" полностью сбрасывает состояние

## Как проверить себя

1. Отправьте 3 сообщения при prefetch=3, затем попробуйте отправить четвёртое — в лог должна появиться запись BLOCKED.
2. Нажмите NACK+Requeue на сообщении — оно должно пройти через `nacked` → `requeued` → `redelivering` → `processing` с пометкой "redelivered (попытка 2)".
3. Нажмите NACK+DLQ на другом сообщении — оно должно перейти в `dead-lettered` и остаться в этом состоянии.
4. Нажмите Timeout — сообщение должно получить новый delivery-tag и вернуться в обработку.
5. Включите no-ack mode и отправьте сообщение — оно должно автоматически подтвердиться без кнопок.
6. Проверьте счётчики Всего / ACK / DLQ / В работе — они должны отражать реальное состояние.
