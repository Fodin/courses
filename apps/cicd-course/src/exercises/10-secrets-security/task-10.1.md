# Задание 10.1: CI/CD Variables — типы, маскировка, область видимости

## Цель

Создать интерактивный конструктор CI/CD переменных. Пользователь настраивает параметры переменной (тип, masked, protected, scope), видит итоговый YAML и понимает, в каких условиях джоб получит доступ к переменной.

## Требования

1. Реализовать выбор **типа переменной**: `Variable` (строка) или `File` (путь к временному файлу). При выборе File показывать пояснение, что `$MY_VAR` будет содержать путь вроде `/tmp/gitlab-runner-file123`.
2. Реализовать переключатели **Masked** и **Protected** (чекбоксы или toggle-кнопки). При включении Masked показывать как значение будет выглядеть в логах (`[MASKED]`). При включении Protected — визуально показать, на каких ветках переменная доступна.
3. Показывать **предупреждение** когда одновременно выбраны: тип `Variable`, Masked включён, и введённое значение содержит пробел или перевод строки — "Masked не работает для этого значения".
4. Реализовать выбор **scope** через три кнопки: `Project`, `Group`, `Instance`. Показывать диаграмму вложенности уровней.
5. Реализовать **симулятор доступа**: показать два сценария — пайплайн на `main (protected)` и пайплайн на `feature/my-feature`. Подсветить, получит ли джоб переменную в каждом случае.
6. Отображать сгенерированный **пример использования в YAML** (не определение переменной, а как на неё ссылаться в скрипте).

## Чеклист

- [ ] Переключатель типа: Variable / File с описанием разницы
- [ ] Чекбоксы Masked и Protected
- [ ] Поле ввода значения переменной с валидацией для masked
- [ ] Предупреждение при несовместимых параметрах (masked + multiline/spaces)
- [ ] Три кнопки scope с визуальной иерархией уровней
- [ ] Симулятор: два сценария (protected branch / обычная ветка) с цветовой индикацией доступа
- [ ] Блок с примером YAML-использования переменной
- [ ] Пример лога джоба: со значением и с [MASKED]

## Как проверить себя

1. Выбери тип `File` — убедись, что пример использования показывает `kubectl --kubeconfig=$MY_VAR`, а не прямое значение
2. Включи `Masked`, введи значение с пробелом — должно появиться предупреждение о несовместимости
3. Включи `Protected`, выбери scope `Project` — в симуляторе `feature/my-feature` должна показывать "нет доступа"
4. Выключи `Protected` — оба сценария в симуляторе должны показывать доступ
5. Выбери scope `Group` — убедись, что диаграмма иерархии показывает group → project

## Подсказки

- Используй `useState` для: `varType` ('variable'|'file'), `masked` (boolean), `protected` (boolean), `scope` ('project'|'group'|'instance'), `value` (string)
- Для определения multiline/spaces в значении: `value.includes(' ') || value.includes('\n')`
- Симулятор: два объекта `{ branch: 'main', isProtected: true }` и `{ branch: 'feature/my-feature', isProtected: false }`
- Цвет доступа: зелёный (#E8F5E9 / #2E7D32) для "есть доступ", красный (#FFEBEE / #C62828) для "нет доступа"
