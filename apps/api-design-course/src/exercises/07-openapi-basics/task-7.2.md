# Задание 7.2: Конструктор OpenAPI-пути

## Цель

Реализовать пошаговый конструктор, который показывает, как строится описание одного
endpoint в OpenAPI. На каждом шаге YAML нарастает — пользователь видит процесс формирования
спецификации.

## Требования

1. Реализовать выбор из трёх сценариев: `GET /users`, `POST /users`, `GET /users/{id}`
2. Реализовать 4 шага: "Метод и путь", "Параметры", "Тело запроса", "Ответы"
3. На каждом шаге YAML-превью содержит все секции от шага 1 до текущего
4. При смене сценария шаги сбрасываются на первый
5. Кнопки "Назад" и "Далее" для навигации по шагам
6. Пройденные шаги отмечаются иначе (цвет, иконка)
7. Под YAML показывать контекстную подсказку для текущего шага

## Чеклист

- [ ] Три кнопки сценариев с методом и путём
- [ ] Четыре шага, переключаемых кнопками и кликом на шаг
- [ ] YAML нарастает по мере прохождения шагов
- [ ] Переключение сценария сбрасывает прогресс на шаг 1
- [ ] `GET /users/{id}` добавляет path-параметр `id`
- [ ] `POST /users` добавляет `requestBody`, но не path/query параметры
- [ ] `GET /users` добавляет query-параметр `limit`, но не requestBody
- [ ] В responses указаны коды 200/201, 400 и (для пути с {id}) 404
- [ ] Подсказка меняется в зависимости от текущего шага

## Как проверить себя

- Выберите сценарий `GET /users/{id}` и дойдите до шага "Параметры" — в YAML должен быть
  параметр `in: path` с `required: true`
- Выберите `POST /users`, перейдите на шаг "Тело запроса" — YAML должен содержать `requestBody`
  с `required: [name, email]`
- Переключитесь на другой сценарий — счётчик шагов сбросится на 1
- На шаге "Ответы" в сценарии `POST /users` должен быть код `"201"`, а не `"200"`
