# Задание 4.3: workflow:rules — управление пайплайном

## Цель

Создать симулятор дедупликации пайплайнов: показать проблему двойного запуска при branch + MR событиях и визуализировать как `workflow:rules` решает её.

## Требования

1. Переключатель режима: "Без workflow:rules" / "С workflow:rules"
2. Симулятор событий: кнопки "Push в ветку feature/auth" и "Открыть MR из feature/auth"
3. В режиме "без правил" — при обоих событиях создаются пайплайны (отображаем оба)
4. В режиме "с правилами" — при push с открытым MR branch-пайплайн блокируется
5. Лог событий — временная шкала действий и созданных пайплайнов
6. Счётчик потраченных runner-минут (у branch без MR — 5 мин, у MR — 5 мин, дубль = 10 мин)
7. Визуальная карточка пайплайна: тип (branch/mr), статус (создан/заблокирован), источник

## Сценарий симуляции

```
Шаг 1: git push feature/auth
  → Без правил: создаётся branch-пайплайн [push]
  → С правилами: создаётся branch-пайплайн [push] (MR ещё не открыт)

Шаг 2: Открыть MR из feature/auth в main
  → Без правил: создаётся МР-пайплайн [merge_request_event]
                branch-пайплайн уже работает → два пайплайна!
  → С правилами: создаётся МР-пайплайн [merge_request_event]
                branch-пайплайн блокируется workflow:rules
```

## Конфигурация workflow:rules для отображения

```yaml
# Режим "С workflow:rules"
workflow:
  rules:
    - if: $CI_MERGE_REQUEST_IID      # есть MR → MR-пайплайн
    - if: $CI_COMMIT_BRANCH && $CI_OPEN_MERGE_REQUESTS
      when: never                     # есть MR → блокируем branch
    - if: $CI_COMMIT_BRANCH           # нет MR → branch-пайплайн
```

## Чеклист

- [ ] Переключатель режима (без/с workflow:rules) с визуальным выделением активного
- [ ] Кнопка "Push в ветку" — добавляет событие в лог
- [ ] Кнопка "Открыть MR" — добавляет событие в лог
- [ ] Кнопка "Сбросить" — очищает лог и счётчики
- [ ] Карточки пайплайнов: тип, источник CI_PIPELINE_SOURCE, статус
- [ ] Блокированные пайплайны отображаются серым с причиной блокировки
- [ ] Счётчик суммарного времени (runner-минут)
- [ ] Блок с YAML конфигурацией workflow:rules (активируется в режиме "с правилами")

## Как проверить себя

- Режим "без правил": нажми "Push" → нажми "Открыть MR" → должно появиться 2 пайплайна, 10 мин
- Режим "с правилами": нажми "Push" (1 пайплайн, 5 мин) → нажми "Открыть MR" → branch блокируется, только MR-пайплайн
- Итого в режиме с правилами — 1 пайплайн вместо 2
- Сброс очищает всё до начального состояния
