# Задание 10.2: Конструктор стратегии версионирования

## Цель

Реализовать конструктор настройки стратегии версионирования и кеширования для каждого MFE с валидацией конфигурации и генерацией deployment manifest.

## Требования

1. Таблица MFE с колонками: MFE Name (редактируемое поле), Стратегия, URL Pattern, Cache TTL, Canary %, Rollback, удаление строки
2. Три стратегии версий:
   - `semver` → URL: `/mfe/{name}/1.0.0/remoteEntry.js`
   - `content-hash` → URL: `/mfe/{name}/abc1d2e3/remoteEntry.js`
   - `latest` → URL: `/mfe/{name}/latest/remoteEntry.js`
3. URL Pattern генерируется автоматически на основе имени и стратегии
4. Настройки: Cache TTL (no-cache / 1h / 1d / 1w / immutable), Canary % (слайдер 0–100), Rollback policy (auto-on-error / manual / disabled)
5. Кнопка "Добавить MFE" добавляет новую строку с дефолтными значениями
6. Вкладка "Deployment Manifest" показывает сгенерированный JSON
7. Валидация с предупреждениями о рисках:
   - Ошибка: Shell не может использовать стратегию "latest"
   - Ошибка: Canary > 0% с rollback policy "disabled"
   - Ошибка: Immutable cache со стратегией "latest"
   - Предупреждение: "Latest" стратегия с Cache TTL отличным от no-cache
   - Предупреждение: Canary = 100% (это уже не canary)
8. Справочный блок внизу с описанием каждой стратегии

## Чеклист

- [ ] Таблица с тремя начальными MFE (shell, catalog, cart)
- [ ] URL Pattern обновляется автоматически при смене имени или стратегии
- [ ] Слайдер canary с числовым индикатором процента
- [ ] Кнопка добавления и кнопки удаления каждой строки
- [ ] Две вкладки: "Настройка MFE" и "Deployment Manifest"
- [ ] JSON в манифесте обновляется в реальном времени при любом изменении
- [ ] Ошибки конфигурации отображаются с иконкой ⛔, предупреждения с ⚠️
- [ ] Строки с ошибками имеют отличный фон (#fff8f8)
- [ ] Манифест показывает счётчик ошибок конфигурации
- [ ] Справочный блок с тремя карточками стратегий
- [ ] Только inline-стили, никаких CSS-файлов

## Как проверить себя

1. Измените стратегию Shell на "latest" — должна появиться ошибка о недопустимости для shell
2. Установите Canary 25% и Rollback policy "disabled" — должна появиться ошибка о риске
3. Выберите Cache TTL "immutable" для MFE со стратегией "latest" — ошибка
4. Выберите Cache TTL "1d" для MFE со стратегией "latest" — предупреждение (не ошибка)
5. Добавьте новый MFE, укажите имя "payments" со стратегией "content-hash" — URL должен обновиться
6. Откройте вкладку Manifest — JSON должен содержать все 4 MFE со всеми настройками
7. Проверьте, что манифест обновляется в реальном времени при изменении canary-слайдера
