# Задание 7.1: Анатомия OpenAPI-документа

## Цель

Реализовать интерактивную карту структуры OpenAPI 3.x документа. Пользователь кликает
на секцию и видит подробное описание с примером YAML.

## Требования

1. Отрисовать все 5 секций OpenAPI: `openapi`, `info`, `servers`, `paths`, `components`
2. Для каждой секции показать иконку, название, краткое описание и метку обязательности
3. Активная секция подсвечивается цветом и левой рамкой
4. Клик на уже открытую секцию сворачивает детали (toggle)
5. При выборе секции показывать блок с подробным описанием и примером YAML
6. Пример YAML отображается в кодовом блоке с тёмным фоном и моноширинным шрифтом
7. Если ни одна секция не выбрана — показать placeholder с подсказкой

## Чеклист

- [ ] Все 5 секций отображаются
- [ ] `openapi`, `info`, `paths` помечены как обязательные (красный бейдж)
- [ ] `servers`, `components` помечены как опциональные (зелёный бейдж)
- [ ] Клик раскрывает детальное описание
- [ ] Повторный клик на ту же секцию — скрывает детали
- [ ] Кодовый блок с YAML примером (тёмный фон, `pre`, моноширинный шрифт)
- [ ] Placeholder когда ни одна секция не активна

## Как проверить себя

- Нажмите на `info` — должно появиться описание с примером YAML, включая поля title, version, contact
- Нажмите на `components` — в примере должны быть `schemas` и `responses` с `$ref`
- Нажмите ещё раз на `info` — детали должны скрыться
- Убедитесь, что `openapi`, `info`, `paths` имеют красный бейдж "обязательно"
