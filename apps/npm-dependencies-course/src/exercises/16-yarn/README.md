# Уровень 16: Yarn — classic, berry, Plug'n'Play

## Yarn Classic (v1)

Yarn появился в 2016 году как ответ на проблемы npm того времени: медленные установки, недетерминированность, отсутствие lockfile. Yarn Classic ввёл:

- `yarn.lock` — детерминированный lockfile с точными версиями
- Параллельные загрузки пакетов (в npm они были последовательными)
- Плоский `node_modules` (аналогично современному npm)
- Поле `resolutions` для принудительной замены версий транзитивных зависимостей

### Поле resolutions (Yarn Classic)

```json
{
  "resolutions": {
    "lodash": "4.17.21",
    "**/@types/react": "18.2.0"
  }
}
```

Синтаксис `**/@types/react` означает: заменить эту зависимость везде в дереве, независимо от глубины.

## Yarn Berry (v2+)

В 2020 году вышел Yarn Berry — полная переработка архитектуры. Главное нововведение — **Plug'n'Play (PnP)**.

### Plug'n'Play: нет node_modules

PnP заменяет `node_modules` двумя компонентами:

1. **`.pnp.cjs`** — файл-карта резолюции: для каждого пакета прописано, где найти его файлы и его зависимости
2. **`.yarn/cache/`** — зипы пакетов (`.zip`-архивы)

При запуске Node.js `.pnp.cjs` патчит `require()`, перехватывая резолюцию и направляя её к нужному `.zip`-файлу в кэше.

```
project/
  .pnp.cjs          ← карта резолюции (патч require)
  .yarn/
    cache/
      express-npm-4.18.2-abc123.zip
      debug-npm-4.3.4-def456.zip
  package.json
  yarn.lock
```

### Zero-installs

Поскольку `.yarn/cache/` содержит все пакеты в виде `.zip`-файлов, их можно **закоммитить в git**. Тогда после клонирования репозитория достаточно:

```bash
git clone ...
# пакеты уже в .yarn/cache/
# node_modules не нужен
```

Это особенно ценно для CI: нет фазы скачивания пакетов.

### Плюсы PnP

- Нет фантомных зависимостей (строгая изоляция как у pnpm)
- Быстрые установки: файлы не копируются, только читается `.pnp.cjs`
- Zero-installs: кэш в репозитории, мгновенный старт в CI

### Проблемы совместимости PnP

Некоторые инструменты напрямую обращаются к файловой системе в поисках `node_modules` — они не работают с PnP. Например, некоторые плагины Webpack или нативные аддоны.

Решение — опция `nodeLinker`:

```yaml
# .yarnrc.yml
nodeLinker: node-modules
```

Это заставляет Yarn Berry создавать обычный `node_modules` вместо PnP.

## yarn dlx

Аналог `npx` — запускает пакет без установки в проект:

```bash
yarn dlx create-react-app my-app
yarn dlx prettier --write .
```

## Отличия hoisting: Classic vs Berry PnP

| Поведение             | Yarn Classic       | Yarn Berry PnP   |
| --------------------- | ------------------ | ---------------- |
| node_modules          | Плоский (hoisting) | Нет              |
| Фантомные зависимости | Допускает          | Нет              |
| Совместимость         | Высокая            | Требует проверки |

## ⚠️ Частые ошибки

❌ Путать Yarn Classic и Yarn Berry — разные архитектуры, разные конфиги.

✅ Версия Yarn определяется в `package.json → packageManager` или `.yarnrc.yml`.

❌ Использовать PnP с инструментами, не поддерживающими его (без проверки).

✅ Проверить совместимость или использовать `nodeLinker: node-modules`.
