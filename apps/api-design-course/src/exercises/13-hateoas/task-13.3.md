# Задание 13.3: Проектирование HATEOAS API

## Цель

Реализовать интерактивный self-check по проектированию гипермедиа для трёх ресурсов с жизненным циклом. Студент продумывает состояния и переходы (`_links`), затем сравнивает с эталоном.

## Требования

1. Три карточки-сценария (кликабельные): платёж, статья в блоге (draft→published), заявка на отпуск (vacation request)
2. При выборе сценария — textarea для ответа студента с подсказкой: перечисли состояния и для каждого — какие `_links` (переходы) доступны
3. Кнопка «Показать эталон» раскрывает панель: таблица «состояние → доступные `rel`» + краткий комментарий о ключевом правиле сценария
4. Активная карточка выделена рамкой (#6366f1)
5. Ответы студента сохраняются при переключении сценариев; состояние «показан эталон» — отдельно для каждого

## Чеклист

- [ ] Три карточки сценариев с иконкой, названием, описанием
- [ ] Textarea ответа, сохраняется при переключении
- [ ] Кнопка «Показать эталон» (toggle для каждого сценария)
- [ ] Эталон: таблица «состояние → `rel`» + комментарий
- [ ] Состояние revealed хранится для каждого сценария отдельно

## Данные для сценариев (эталон)

### Сценарий 1: Платёж
- `created` → self, authorize, cancel
- `authorized` → self, capture, void
- `captured` → self, refund
- `refunded` → self
- Правило: после `captured` нельзя `void`, только `refund`; терминальные состояния несут только `self`.

### Сценарий 2: Статья в блоге
- `draft` → self, edit, publish, delete
- `published` → self, edit, unpublish, archive
- `archived` → self, restore
- Правило: `delete` доступен только в `draft`; опубликованную статью можно снять с публикации, но не удалить напрямую.

### Сценарий 3: Заявка на отпуск
- `submitted` → self, approve, reject, withdraw
- `approved` → self, cancel
- `rejected` → self, resubmit
- `cancelled` → self
- Правило: `approve`/`reject` доступны согласующему (роль), `withdraw`/`cancel` — заявителю; набор ссылок зависит и от состояния, и от роли.

## Как проверить себя

1. Для каждого сценария выпиши состояния и доступные переходы.
2. Нажми «Показать эталон» и сравни — особенно терминальные состояния (только `self`) и роль-зависимые переходы.
3. Обрати внимание: правильный дизайн делает невозможные переходы попросту отсутствующими в `_links`.

## Подсказки

- Состояние: `selected`, `answers` (сценарий→текст), `revealed` (сценарий→bool).
- Эталон удобно хранить массивом: `{ icon, title, description, states: [{ state, rels: [...] }], rule }`.
- Таблицу эталона рисуй из `states` — по строке на состояние.
