# Генерация кода и SDK

## Зачем генерировать код из спецификации

OpenAPI-спецификация — это не просто документация. Это **машиночитаемый контракт**, из которого можно автоматически получить:

- TypeScript-типы для всех моделей и эндпоинтов
- Готовые HTTP-клиенты с типобезопасными методами
- React Query / SWR хуки
- MSW-моки для тестирования без реального бэкенда

Без генерации frontend-разработчик вынужден вручную поддерживать типы в синхронизации с API. Стоит бэкенду изменить поле — и вы узнаёте об этом на продакшене.

## Основные инструменты для frontend

| Инструмент | Что генерирует | Runtime зависимость |
|---|---|---|
| **openapi-generator** | типы + клиенты + хуки (50+ языков) | Java / Docker |
| **openapi-typescript** | только TypeScript-типы | Node.js |
| **orval** | типы + React Query хуки + MSW-моки | Node.js |

## Contract-first подход

**Contract-first** означает, что спецификация пишется **до** реализации:

1. Продукт-менеджер и разработчики согласуют API-контракт в `openapi.yaml`
2. Frontend генерирует типы и начинает разработку с MSW-моками
3. Backend реализует API согласно контракту
4. При выпуске — реальный API уже соответствует типам на фронте

Альтернатива — **code-first**: сначала пишется код, потом из него генерируется спека (например, через аннотации). Подход рабочий, но даёт меньше контроля над дизайном API.

## Типичный workflow

```
openapi.yaml → npm run generate:api → src/api/schema.d.ts → компонент
```

Ключевое правило: `schema.d.ts` **никогда не редактируется вручную** — только регенерируется.
