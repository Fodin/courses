# Задание 13.2: Fan-out калькулятор

## Цель

Реализовать интерактивный калькулятор, который наглядно демонстрирует разницу между fan-out on write (push) и fan-out on read (pull). Визуализировать crossover point — момент, когда push становится дороже pull.

## Требования

1. **Входные параметры** (слайдеры):
   - Average followers — среднее число подписчиков (100 — 1 000 000)
   - Post rate — постов в секунду по всей системе (1 000 — 100 000)
   - Celebrity threshold — порог «селебрити» (1 000 — 100 000)
2. **Расчёт Push (fan-out on write)**:
   - Write ops/sec = post_rate × avg_followers
   - Read ops/sec = feed_reads_per_sec (константа, например 50 000)
   - Storage amplification = avg_followers × (размер postId)
3. **Расчёт Pull (fan-out on read)**:
   - Write ops/sec = post_rate (одна запись на пост)
   - Read ops/sec = feed_reads_per_sec × avg_following (300 подписок в среднем)
   - Storage = 1× (без дублирования)
4. **Crossover point** — при каком числе followers push-стоимость превышает pull-стоимость
5. **Визуализация** — таблица сравнения, цветовая индикация (зелёный = лучше, красный = хуже)
6. **Hybrid-расчёт** — сколько операций экономит hybrid при заданном celebrity threshold

## Чеклист

- [ ] Три слайдера управляют входными параметрами
- [ ] Таблица сравнения Push vs Pull с числовыми значениями
- [ ] Crossover point рассчитывается и отображается
- [ ] Hybrid-подход показывает экономию относительно чистого Push
- [ ] Цветовая индикация: какой подход выигрывает по каждой метрике
- [ ] Значения обновляются при изменении слайдеров в реальном времени

## Как проверить себя

1. Установите avg_followers = 500 — Push должен быть эффективнее (write дешёвый, read мгновенный)
2. Установите avg_followers = 1 000 000 — Pull должен быть эффективнее (push создаёт миллион записей)
3. Crossover point должен быть в районе 10 000 — 50 000 followers
4. Hybrid должен показывать экономию по сравнению с чистым Push
