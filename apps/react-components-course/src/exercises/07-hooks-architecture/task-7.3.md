# Задание 7.3: usePagination + useFilters + useSorting → useDataTable

## Цель

Реализовать три специализированных хука и скомпоновать их в `useDataTable`. Компонент таблицы получает готовые данные и управляющие функции — и занимается только рендерингом.

## Требования

1. Реализуйте `usePagination(totalItems: number, pageSize: number)`:
   - Хранит текущую страницу (начиная с 1)
   - Вычисляет `totalPages`, `offset` (для среза данных), флаги `hasPrev` / `hasNext`
   - Возвращает функции `goTo(page)`, `next()`, `prev()`
   - При изменении `totalItems` сбрасывает на первую страницу если текущая страница вышла за пределы

2. Реализуйте `useSorting<T>()`:
   - Хранит `field: keyof T | null` и `direction: 'asc' | 'desc'`
   - `toggleSort(field)`: если поле уже выбрано — меняет направление; иначе устанавливает поле с `'asc'`
   - Возвращает функцию `sort(items: T[]): T[]` для сортировки массива

3. Реализуйте `useFilters<F extends Record<string, unknown>>(initialFilters: F)`:
   - Хранит текущие значения фильтров
   - `setFilter(key, value)` — обновляет один фильтр
   - `resetFilters()` — сбрасывает все фильтры в `initialFilters`
   - Возвращает `values: F` и функции управления

4. Реализуйте `useDataTable<T>(data: T[], options)`:
   - Принимает исходные данные и опции: `pageSize`, `filterFn`
   - Внутри использует `useSorting`, `useFilters`, `usePagination`
   - Применяет фильтрацию → сортировку → пагинацию в правильном порядке
   - Возвращает: `pageData` (данные текущей страницы), `pagination`, `sorting`, `filters`, `totalCount`

5. Реализуйте демо-компонент `EmployeeTable` с таблицей сотрудников:
   - Данные: минимум 15 сотрудников с полями `id`, `name`, `department`, `salary`
   - Фильтр по отделу (select)
   - Сортировка по имени и зарплате (клик на заголовок столбца)
   - Пагинация по 5 записей

## Подсказки

- Порядок применения важен: фильтр → сортировка → пагинация. Пагинация должна считать `totalItems` от уже отфильтрованного массива
- Для сортировки строк используйте `a.localeCompare(b)`, для чисел — обычное вычитание
- `useMemo` для производных значений (filtered, sorted) — предотвращает лишние вычисления
- При изменении фильтров не забудьте сбросить пагинацию на первую страницу
- Иконки сортировки: `↑` для asc, `↓` для desc, `↕` для неактивного столбца

## Чеклист

- [ ] `usePagination` корректно вычисляет `totalPages` и `offset`
- [ ] `usePagination` сбрасывается на первую страницу при изменении `totalItems`
- [ ] `useSorting.toggleSort` переключает направление для текущего поля
- [ ] `useSorting.sort` возвращает отсортированный массив без мутации
- [ ] `useFilters.setFilter` обновляет один фильтр, остальные не трогает
- [ ] `useDataTable` применяет фильтр → сорт → пагинацию в правильном порядке
- [ ] `totalCount` отражает количество после фильтрации (до пагинации)
- [ ] Компонент `EmployeeTable` не содержит логики фильтрации/сортировки/пагинации
- [ ] При смене фильтра таблица сбрасывается на первую страницу

## Как проверить себя

Откройте таблицу с 15+ сотрудниками. Выберите фильтр по отделу — список сократится, пагинация пересчитается. Нажмите на заголовок "Зарплата" — список отсортируется по возрастанию, повторный клик — по убыванию. Перейдите на вторую страницу, затем измените фильтр — должны вернуться на первую страницу автоматически.
