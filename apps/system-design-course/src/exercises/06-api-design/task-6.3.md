# Задание 6.3: Проектирование REST API для блог-платформы

## Цель

Спроектировать полноценный REST API (Level 2) для блог-платформы: определить ресурсы, эндпоинты, HTTP-методы, пагинацию, фильтрацию и аутентификацию.

## Требования

1. Определите ресурсы блог-платформы:
   - **Users** — авторы и читатели
   - **Posts** — статьи блога
   - **Comments** — комментарии к статьям
   - **Tags** — теги для категоризации
2. Для каждого ресурса спроектируйте endpoints:
   - CRUD операции (GET, POST, PUT/PATCH, DELETE)
   - Вложенные ресурсы (GET /posts/:id/comments)
   - Фильтрация и поиск (GET /posts?tag=react&author=42)
3. Определите для каждого endpoint:
   - HTTP метод и URL
   - Тип пагинации (cursor или offset)
   - Требуется ли аутентификация
   - Описание и статус-коды
4. Интерактивная таблица с группировкой по ресурсам
5. Проверка полноты: все CRUD-операции покрыты, пагинация на списках

## Чеклист

- [ ] 4 ресурса: Users, Posts, Comments, Tags
- [ ] Для каждого ресурса: GET (list), GET (one), POST, PATCH, DELETE
- [ ] Вложенные ресурсы: /posts/:id/comments, /users/:id/posts
- [ ] Пагинация на всех списках (cursor для posts/comments, offset для tags)
- [ ] Фильтрация: по автору, тегу, дате
- [ ] Аутентификация: указано где нужна (POST, PATCH, DELETE), где нет (GET)
- [ ] Корректные HTTP-статус-коды (200, 201, 204, 400, 401, 404)

## Как проверить себя

1. Каждый ресурс имеет минимум 5 endpoints (list, get, create, update, delete)
2. URL содержат существительные, не глаголы (/posts, не /getPosts)
3. POST возвращает 201, DELETE — 204
4. Списки имеют пагинацию (cursor для публичных, offset для админки)
5. POST/PATCH/DELETE требуют аутентификацию, GET — нет (кроме приватных)
