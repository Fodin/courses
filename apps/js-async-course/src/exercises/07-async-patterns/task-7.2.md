# Задание 7.2: Async Pool

## Цель

Реализовать функцию `asyncPool(concurrency, tasks)`, которая выполняет задачи параллельно, но не более N одновременно. Визуализировать распределение задач по слотам и измерить ускорение относительно последовательного выполнения.

## Требования

1. **Функция `asyncPool(concurrency, tasks, onUpdate)`**:
   - `concurrency` — максимальное число одновременных задач
   - `tasks` — массив функций `() => Promise<unknown>`
   - `onUpdate(id, status, slot)` — коллбэк для обновления UI: какая задача запустилась/завершилась, в каком слоте

2. **Слайдер конкурентности N** от 1 до числа задач

3. **Визуализация слотов**: N горизонтальных строк, каждая — слот воркера. В каждом слоте показаны задачи, которые он выполнил (с длительностью)

4. **Карточки задач** — 12 задач разной длительности (300–1200ms). Цвет меняется: серый (очередь) → активный цвет слота (выполняется) → зелёный (готово)

5. **Статистика после завершения**: фактическое время, последовательное время (сумма всех), ускорение (ratio)

## Чеклист

- [ ] Компонент называется `Task7_2` и экспортируется по умолчанию
- [ ] `useLanguage` импортирован и `t('task.7.2')` используется в заголовке
- [ ] При N=1 задачи выполняются строго последовательно (только один слот активен)
- [ ] При N=12 все задачи запускаются почти одновременно
- [ ] Слоты корректно показывают, какой воркер взял какую задачу
- [ ] Фактическое время при N=1 ≈ сумма всех длительностей
- [ ] Нет TypeScript-ошибок типа `any`

## Как проверить себя

1. Установите N=1, запустите — задачи должны идти одна за одной в первом слоте
2. Установите N=3, запустите — должно быть 3 активных слота, задачи подхватываются как освобождается слот
3. Сравните время при N=1 vs N=3 vs N=6 — ускорение должно расти
4. Убедитесь, что в любой момент не более N задач имеют статус "running"
