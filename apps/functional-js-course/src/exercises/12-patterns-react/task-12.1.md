# Задание 12.1. Иммутабельный стейт-менеджмент

## Цель

Построить Mini-Redux на FP-принципах: pure reducer с Immer produce и поддержкой Undo/Redo через стек иммутабельных состояний.

## Требования

1. Реализуй `reducer(state: State, action: Action): State` — pure функцию, использующую `produce` из Immer. Обработай три кейса: `ADD_TODO` (добавить с инкрементом nextId), `TOGGLE_TODO` (переключить done по id), `DELETE_TODO` (удалить по id).
2. Реализуй функцию `dispatch(action)` в хуке `useUndoableReducer`: при каждом действии текущий `present` уходит в конец `past`, вычисляется новый `present`, `future` очищается.
3. Реализуй `undo()`: если `past` непуст — последний элемент становится `present`, предыдущий `present` уходит в начало `future`.
4. Реализуй `redo()`: если `future` непусто — первый элемент становится `present`, предыдущий `present` уходит в конец `past`.
5. Убедись, что после нескольких `dispatch` + `undo` + `dispatch` — `future` очищается.

## Чеклист

- [ ] `reducer` использует `produce` из immer, не мутирует `state` напрямую
- [ ] `ADD_TODO` добавляет todo с корректным `nextId`, инкрементирует `nextId`
- [ ] `TOGGLE_TODO` переключает `done` только у нужного todo
- [ ] `DELETE_TODO` удаляет todo по id
- [ ] `dispatch` сохраняет `present` в `past`, очищает `future`
- [ ] `undo` восстанавливает предыдущее состояние, `redo` — возвращает вперёд
- [ ] Кнопки Undo/Redo отключены когда стек пуст

## Как проверить себя

1. Добавь несколько todos, нажми Undo несколько раз — список возвращается к предыдущим состояниям.
2. После Undo нажми Redo — список возвращается вперёд.
3. После Undo добавь новый todo — кнопка Redo становится неактивной (future очищен).
4. Toggle и Delete тоже поддерживают Undo/Redo.
5. При нажатии Undo когда `past` пуст — ничего не происходит.
