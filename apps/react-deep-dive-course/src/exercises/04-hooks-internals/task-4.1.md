# Задание 4.1: Hooks Linked List

## Цель

Визуализировать структуру хуков как связный список (linked list) и увидеть, что происходит при нарушении порядка хуков.

## Задание

Реализуй компонент, который:

1. Содержит три хука: `useState`, `useEffect`, `useMemo`
2. Отображает рядом с компонентом интерактивную схему linked list — каждый хук как бокс с полями `memoizedState` и стрелкой `next`
3. Показывает текущее значение `memoizedState` для каждого хука в реальном времени (счётчик, массив deps, результат useMemo)
4. Добавляет кнопку "Toggle conditional hook" — при активации показывает предупреждение о том, что условный хук сломает список, и объясняет почему

## Требования

1. Компонент `HooksLinkedListDemo` содержит:
   - `useState(0)` — числовой счётчик
   - `useEffect` с зависимостью от счётчика — логирует изменения
   - `useMemo` — вычисляет `count * count`
2. Визуальная схема: три бокса, соединённые стрелками `next →`, последний показывает `next: null`
3. В каждом боксе отображается:
   - Название хука (useState, useEffect, useMemo)
   - Поле `memoizedState` с реальным значением
   - Поле `next` — стрелка к следующему или "null"
4. Кнопка "+1" увеличивает счётчик — схема обновляется в реальном времени
5. Блок "Что будет при условном хуке": показывает ❌ код с условным хуком и объяснение, почему это ломает список

## Чеклист

- [ ] Три хука в компоненте (useState, useEffect, useMemo)
- [ ] Три визуальных бокса с полями memoizedState и next
- [ ] memoizedState для useState показывает текущее число
- [ ] memoizedState для useEffect показывает deps array `[count]`
- [ ] memoizedState для useMemo показывает `count * count`
- [ ] Кнопка "+1" обновляет счётчик и схему
- [ ] Стрелки `next →` между боксами, последний `next: null`
- [ ] Блок с объяснением проблемы условных хуков

## Как проверить себя

1. Нажми "+1" несколько раз — значения в боксах должны обновляться синхронно
2. Убедись, что `useMemo` показывает квадрат текущего count
3. Прочитай объяснение условного хука и мысленно проследи, как смещается список
