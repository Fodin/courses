# Задание 2.2: Priority Queue — Планировщик задач

## Цель

Реализовать компонент-планировщик задач с четырьмя уровнями приоритета, аналогичными Scheduler в React: Sync (мгновенно), UserBlocking (250ms), Normal (5000ms), Idle (никогда не просрочится). Визуализировать очередь и порядок обработки задач.

## Задание

Создай компонент `Task2_2`, который:

1. Позволяет добавлять задачи с выбором приоритета (4 кнопки: Sync / UserBlocking / Normal / Idle)
2. Показывает текущую очередь задач, отсортированную по приоритету (Sync первые, Idle последние)
3. Обрабатывает задачи в правильном порядке:
   - **Sync** — мгновенно при добавлении (пока список не пуст)
   - **UserBlocking** — через 250ms после добавления в очередь
   - **Normal** — через 5000ms
   - **Idle** — только если очередь пуста от более срочных
4. Ведёт лог обработанных задач

## Требования

1. Тип задачи:
   ```ts
   type Priority = 'Sync' | 'UserBlocking' | 'Normal' | 'Idle'

   type Task = {
     id: string
     label: string
     priority: Priority
     createdAt: number
     expirationTime: number  // createdAt + timeout[priority]
   }
   ```
2. Таймауты приоритетов:
   ```ts
   const TIMEOUTS: Record<Priority, number> = {
     Sync: -1,           // немедленно
     UserBlocking: 250,
     Normal: 5000,
     Idle: Infinity,
   }
   ```
3. Очередь должна быть отсортирована по `expirationTime` (min-heap семантика — ближайший дедлайн первым)
4. Sync-задачи обрабатываются мгновенно и не появляются в очереди
5. Для остальных — через `setTimeout` с нужной задержкой обрабатывается самая приоритетная просроченная задача из очереди
6. Каждая задача в очереди показывает: имя, приоритет, время до дедлайна (или "просрочена")
7. Лог: последние 10 записей с временной меткой

## Цветовая схема приоритетов

| Приоритет | Цвет |
|---|---|
| Sync | Красный `#ef4444` |
| UserBlocking | Оранжевый `#f97316` |
| Normal | Синий `#3b82f6` |
| Idle | Серый `#6b7280` |

## Чеклист

- [ ] Четыре кнопки добавляют задачи с разным приоритетом
- [ ] Sync-задача обрабатывается мгновенно (не попадает в очередь)
- [ ] Очередь отсортирована по expirationTime
- [ ] Цвет задачи соответствует приоритету
- [ ] Задача показывает время до дедлайна (обновляется)
- [ ] Лог ведётся с временными метками
- [ ] При обработке задача исчезает из очереди и появляется в логе

## Как проверить себя

1. Добавь по одной задаче каждого приоритета
2. Sync обрабатывается мгновенно → в очереди 3 задачи
3. Очередь: UserBlocking вверху, Normal в середине, Idle внизу
4. Через 250ms — UserBlocking обрабатывается автоматически
5. Добавь ещё одну Sync во время ожидания → она сразу в логе
6. Порядок в логе: Sync1, Sync2, UserBlocking1, Normal1 (через 5s), ...
