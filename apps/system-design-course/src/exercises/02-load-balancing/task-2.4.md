# Задание 2.4: Проектирование многоуровневой балансировки

## Цель

Спроектировать архитектуру балансировки для системы с тремя типами трафика: WebSocket-соединения, REST API и статические файлы. Для каждого типа выбрать уровень балансировщика, алгоритм и тип health check.

## Требования

1. Система обрабатывает три типа трафика:
   - **WebSocket** — долгоживущие соединения (чат, уведомления в реальном времени)
   - **REST API** — короткие HTTP-запросы (CRUD операции, поиск)
   - **Static Files** — изображения, CSS, JS, видео (кэшируемый контент)
2. Для каждого типа трафика определите:
   - **Уровень балансировщика**: L4 или L7
   - **Алгоритм балансировки**: Round Robin, Weighted RR, Least Connections, IP Hash, Consistent Hashing
   - **Тип health check**: Active, Passive, оба
3. Обоснуйте каждое решение — почему именно этот алгоритм для этого трафика
4. Реализуйте как интерактивную таблицу с выбором параметров и проверкой ответов

## Чеклист

- [ ] Для WebSocket выбран подход, обеспечивающий sticky-поведение (IP Hash / Consistent Hashing)
- [ ] Для REST API выбран алгоритм, учитывающий текущую нагрузку (Least Connections)
- [ ] Для Static Files учтена возможность кэширования (CDN / Consistent Hashing)
- [ ] Для каждого типа трафика указан уровень LB (L4/L7)
- [ ] Health checks настроены с учётом специфики каждого типа трафика
- [ ] Обоснования логичны и учитывают характеристики трафика

## Как проверить себя

1. Откройте задание и выберите параметры для каждого типа трафика
2. Проверьте ответы — для каждого решения должно быть объяснение
3. Подумайте: что произойдёт, если один из серверов WebSocket упадёт?
4. Подумайте: почему для статики Consistent Hashing может быть лучше Round Robin?
5. Проверьте: достаточно ли только passive health checks для WebSocket-серверов?
