# Задание 1.1: Структура .gitlab-ci.yml

## Цель

Научиться собирать валидный `.gitlab-ci.yml` из отдельных блоков, понять назначение каждого ключевого слова и закрепить правила YAML-синтаксиса.

---

## Что нужно сделать

Создай компонент `Task1_1`, который реализует интерактивный конструктор `.gitlab-ci.yml`. Пользователь собирает конфиг из блоков, а компонент показывает результат и ошибки.

### Требования

1. Определи TypeScript-интерфейс `YamlBlock` с полями:
   - `id` — уникальный идентификатор блока
   - `label` — название блока (например, `'stages'`, `'image'`, `'script'`)
   - `content` — YAML-содержимое блока (строка)
   - `required` — обязателен ли блок (`boolean`)
   - `description` — краткое описание для подсказки

2. Реализуй набор из 6 блоков для конструктора:
   - `stages` — объявление стадий
   - `image` — Docker-образ
   - `job-name` — имя job'а
   - `stage` — принадлежность к стадии
   - `script` — список команд
   - `after_script` — постскрипт

3. Реализуй состояние `selectedBlocks` — массив id выбранных блоков

4. Отобрази два раздела:
   - **"Доступные блоки"** — карточки с блоками, которые можно добавить
   - **"Твой конфиг"** — выбранные блоки в виде YAML

5. Реализуй валидацию при нажатии кнопки "Проверить":
   - Есть ли хотя бы один job с именем
   - Есть ли ключевое слово `script` внутри job'а
   - Если указан `stage` — есть ли соответствующая запись в `stages`

6. Покажи результат валидации: зелёный блок "Конфиг валиден" или красный список ошибок

---

## Ожидаемый результат

- Список блоков, кликом добавляемых в конфиг
- Предпросмотр собранного YAML в реальном времени
- Кнопка "Проверить" с результатом валидации
- Кнопка "Сбросить" для очистки

## Как проверить себя

1. Нажми на блок `script` — он появился в "Твоём конфиге"?
2. Нажми "Проверить" без блока `job-name` — видишь ошибку об отсутствии имени job'а?
3. Добавь все обязательные блоки и нажми "Проверить" — видишь зелёное "Конфиг валиден"?
4. Нажми "Сбросить" — конфиг очистился?
