# Задание 1.1: REST vs gRPC — симулятор

## Цель

Создать интерактивный симулятор, наглядно демонстрирующий разницу между протоколами REST и gRPC:
форматы сообщений, накладные расходы на заголовки и кодирование, задержки при передаче данных.

## Требования

1. Переключатель протокола: кнопки `REST` и `gRPC` — только один активен в каждый момент
2. Диаграмма взаимодействия: два блока (`Order Service` и `User Service`) с анимированной стрелкой между ними, отражающей текущую фазу запроса
3. Отображение статуса запроса: индикатор с фазами `idle → requesting → processing → responding → done`
4. Статистика протокола: карточки с полями Протокол, Transport, Encoding, Latency
5. Визуализация payload: два прогресс-бара — полезная нагрузка и overhead (заголовки, метаданные)
6. Кнопка запуска симуляции — показывает реальные тела запроса и ответа в блоке вывода
7. Лог запроса и ответа: отдельные блоки с цветовой маркировкой направления (request — жёлтый, response — зелёный)
8. При переключении протокола лог и фаза сбрасываются

## Чеклист

- [ ] Кнопки REST / gRPC переключают активный протокол с визуальной подсветкой
- [ ] Диаграмма с двумя сервисами и анимированной стрелкой отображается корректно
- [ ] Стрелка меняет направление (`→→→` при запросе, `←←←` при ответе)
- [ ] Индикатор фазы меняет цвет и текст на каждом шаге
- [ ] Карточки статистики показывают разные значения для REST и gRPC
- [ ] Прогресс-бары отображают разный размер payload для каждого протокола
- [ ] Кнопка запуска симулирует полный цикл запрос → обработка → ответ
- [ ] В логе показывается тело реального HTTP/gRPC сообщения в `<pre>` блоке
- [ ] Компонент использует `useLanguage` и `t('task.1.1')` для заголовка

## Как проверить себя

1. Откройте задание в браузере
2. Нажмите кнопку `REST` — убедитесь, что статистика показывает JSON, HTTP/1.1, latency 45ms
3. Нажмите `Отправить REST запрос` — проследите смену фаз и появление лога
4. Переключитесь на `gRPC` — статистика должна изменить Transport на HTTP/2, Encoding на Protobuf
5. Запустите симуляцию gRPC — убедитесь, что latency в 3-4 раза меньше и payload компактнее
6. Прогресс-бары у gRPC должны быть заметно короче (меньше overhead)
7. Повторный запуск очищает предыдущий лог
