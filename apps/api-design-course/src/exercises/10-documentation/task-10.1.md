# Задание 10.1: Анатомия хорошей документации

## Цель

Изучить 12 ключевых критериев качественной API-документации и научиться отличать хорошую реализацию от плохой.

## Требования

1. Отобразить интерактивный чеклист из 12 критериев хорошей документации
2. Каждый критерий должен быть отмечаемым (checkbox) — при отметке текст зачёркивается
3. Прогресс-бар отображает процент выполненных критериев (X / 12, %)
4. При достижении 100% показать поздравительное сообщение
5. Реализовать фильтрацию по категориям (Структура, Безопасность, Reference, Примеры, Ошибки, Ограничения, Версионирование, SDK, Инструменты)
6. При клике на критерий — раскрывать детали: почему важен, пример плохой реализации (красный), пример хорошей (зелёный)
7. Каждый критерий должен иметь маркер важности: Критично / Важно / Полезно
8. Можно открыть только один критерий одновременно (аккордеон)

## Критерии чеклиста

- Getting Started / Быстрый старт
- Аутентификация и авторизация
- Полный справочник endpoints
- Примеры запросов (cURL + SDK)
- Примеры ответов с реальными данными
- Справочник кодов ошибок
- Rate limits и квоты
- Пагинация и фильтрация
- Changelog и история версий
- SDK и библиотеки
- Песочница / тестовая среда
- Интерактивная песочница (Try it out)

## Чеклист

- [ ] Чеклист из 12 критериев с возможностью отмечать
- [ ] Прогресс-бар с процентом и счётчиком
- [ ] Поздравление при 100%
- [ ] Фильтрация по категориям
- [ ] Аккордеон с деталями при клике
- [ ] Маркеры важности (Критично / Важно / Полезно)
- [ ] Примеры плохой и хорошей реализации для каждого критерия

## Как проверить себя

Откройте компонент в браузере:
1. Убедитесь, что прогресс-бар растёт при отметке чекбоксов
2. Кликните на критерий — должны появиться детали с примерами кода
3. Попробуйте фильтр по категории "Безопасность" — должны остаться только критерии этой категории
4. Отметьте все 12 критериев — должно появиться поздравление
