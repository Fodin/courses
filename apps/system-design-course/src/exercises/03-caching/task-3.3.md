# Задание 3.3: Калькулятор кэш-стратегии

## Цель

Создать интерактивный калькулятор, который на основе параметров нагрузки рекомендует оптимальный паттерн кэширования с развёрнутым объяснением.

## Требования

1. Реализуйте ввод параметров через слайдеры:
   - **Read/Write ratio** — соотношение чтений к записям (от «100% чтение» до «100% запись»)
   - **Stale tolerance** — допустимая устаревшесть данных (от «0 сек — данные всегда свежие» до «1 час — можно терпеть»)
   - **Traffic volume** — интенсивность трафика (от «низкий» до «очень высокий»)
2. На основе комбинации параметров выдавайте рекомендацию:
   - Рекомендуемый паттерн (Cache-Aside, Read-Through, Write-Through, Write-Behind или комбинация)
   - Рекомендуемый TTL
   - Нужна ли защита от stampede
   - Нужен ли cache warming
3. Для каждой рекомендации покажите объяснение: **почему** этот паттерн подходит для данных параметров
4. Покажите индикатор уверенности рекомендации (не все комбинации однозначны)

## Чеклист

- [ ] Три слайдера с визуальными метками работают
- [ ] При изменении параметров рекомендация обновляется мгновенно
- [ ] Рекомендация включает: паттерн, TTL, stampede protection, warming
- [ ] Есть развёрнутое объяснение, почему подходит этот паттерн
- [ ] Крайние значения дают логичные результаты (100% чтение → Cache-Aside, 0 stale tolerance → Write-Through)
- [ ] Высокий трафик + 0 tolerance → рекомендация включает stampede protection

## Как проверить себя

1. Читающая нагрузка (90% read), высокая stale tolerance → Cache-Aside с большим TTL
2. Пишущая нагрузка (80% write), 0 stale tolerance → Write-Through
3. Пишущая нагрузка (80% write), высокая stale tolerance → Write-Behind
4. Высокий трафик, любые параметры → рекомендация должна включать stampede protection
5. Любая нагрузка, низкая stale tolerance → короткий TTL
