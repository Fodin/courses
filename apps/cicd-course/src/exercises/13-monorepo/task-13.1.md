# Задание 13.1: rules:changes — умный запуск джобов в монорепо

## Цель

Создать интерактивный симулятор правил `rules:changes` для монорепо. Пользователь выбирает, какие файлы изменились в коммите, и видит — какие джобы запустятся, а какие будут пропущены.

## Требования

1. Отобразить структуру монорепо: три сервиса (`auth`, `payments`, `notifications`) и один общий пакет (`packages/shared-utils`)
2. Реализовать переключатели (чекбоксы или кнопки) для "изменения" файлов: по одной кнопке на сервис и на shared-utils
3. Для каждого сервиса задать список зависимостей (auth зависит от shared-utils, payments — нет, notifications — да)
4. Отображать список джобов и их статус: `will run` (зелёный) или `skipped` (серый)
5. Показывать результирующий `.gitlab-ci.yml` фрагмент с `rules:changes` для всех трёх сервисов
6. При включении shared-utils — все зависящие от него сервисы тоже должны переключиться в статус `will run`
7. Добавить счётчик: "Запустится X из Y джобов"

## Чеклист

- [ ] Визуализация структуры монорепо (три сервиса + shared-utils)
- [ ] Чекбоксы или кнопки для выбора изменённых путей
- [ ] Логика зависимостей: shared-utils → запускает auth и notifications
- [ ] Статус каждого джоба: `will run` / `skipped`
- [ ] YAML-блок с rules:changes для всех сервисов
- [ ] Счётчик запущенных джобов
- [ ] Визуальное выделение сервисов, запускающихся из-за зависимости (не напрямую)

## Как проверить себя

1. Отметь только "auth изменён" — должны запуститься джобы auth, payments и notifications — нет
2. Отметь только "shared-utils изменён" — должны запуститься auth и notifications (они зависят от shared-utils), payments — нет
3. Отметь все — все джобы запускаются, счётчик показывает 3 из 3
4. Сними все отметки — счётчик 0 из 3, все джобы skipped
5. Проверь, что YAML правильно отражает зависимости в rules:changes

## Подсказки

- Хранить состояние в объекте `{ auth: boolean, payments: boolean, notifications: boolean, sharedUtils: boolean }`
- Функция `willRun(service)` проверяет: `changed[service] || (dependsOnShared[service] && changed.sharedUtils)`
- Для визуального выделения "запущен через зависимость" используй другой цвет, например оранжевый вместо зелёного
- YAML генерируй через функцию, которая принимает имя сервиса и массив путей в `changes`
