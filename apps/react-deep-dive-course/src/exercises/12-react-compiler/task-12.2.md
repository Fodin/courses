# Задание 12.2: Rules of React

## Задание

Перед вами четыре компонента. Некоторые из них нарушают Rules of React — и именно поэтому
React Compiler не сможет их оптимизировать. Определите нарушителей, объясните почему, и исправьте.

## Цель

Научиться выявлять нарушения Rules of React: мутации, нестабильный вывод, чтение мутируемых
глобалов. Понять, что именно делает компонент "непригодным" для автоматической мемоизации.

## Требования

1. Реализуйте четыре компонента (каждый — отдельная карточка):

   **Компонент A — `MutatingList`**: принимает `items: string[]`, делает `items.push('extra')` в
   рендере, отображает список

   **Компонент Б — `TimestampKey`**: принимает `events: string[]`, рендерит список, где ключ
   каждого элемента = `Date.now()` (новый каждый рендер)

   **Компонент В — `RefReader`**: принимает `counterRef: React.RefObject<number>`, отображает
   `counterRef.current` как часть UI (читает ref.current в рендере)

   **Компонент Г — `PureTransform`**: принимает `values: number[]`, отображает их сумму, максимум
   и минимум — чисто, без мутаций

2. Для каждого компонента:
   - Кнопка "Принудительный рендер" (setState с тем же значением) — чтобы видеть эффект
   - Счётчик рендеров
   - Метка: "Compiler: оптимизирует / НЕ оптимизирует"

3. Панель диагностики под каждым компонентом:
   - Красная: "Нарушение: <описание>" — если компонент нарушает rules
   - Зелёная: "Чистый компонент — компилятор оптимизирует" — если всё в порядке

4. Интерактивная секция "Исправленные версии":
   - Кнопки "Показать исправление" для каждого нарушителя
   - При нажатии показывается исправленный код (в виде code block) и краткое объяснение

## Чеклист

- [ ] Компонент А: мутация `items.push` в рендере — отображается как нарушение
- [ ] Компонент Б: `Date.now()` как ключ — отображается как нарушение
- [ ] Компонент В: `ref.current` в рендере — отображается как нарушение
- [ ] Компонент Г: чистый — отображается как "компилятор оптимизирует"
- [ ] Каждый компонент имеет счётчик рендеров и кнопку принудительного рендера
- [ ] Для каждого нарушителя показывается исправленная версия (по кнопке)
- [ ] Компонент А исправляется через `[...items]` перед мутацией
- [ ] Компонент Б исправляется через стабильный ключ (индекс или id)
- [ ] Компонент В исправляется через `useState` вместо чтения ref.current

## Как проверить себя

- Компонент А: при каждом рендере список растёт (bugs!), т.к. `push` мутирует пришедший массив
- Компонент Б: при каждом рендере все элементы пересоздаются (новые ключи) — видно по счётчику DOM
- Компонент В: при изменении ref.current через внешний таймер — UI не обновляется
- Компонент Г: при принудительном рендере с теми же данными — сумма/макс/мин стабильны
- Нажмите "Показать исправление" для каждого нарушителя и убедитесь, что вы понимаете суть
