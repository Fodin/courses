# Задание 12.3. RemoteData и Match

## Цель

Реализовать ADT `RemoteData` для моделирования состояния загрузки данных и компонент `Match` для exhaustive pattern matching.

## Требования

1. Тип `RemoteData<E, A>` уже определён. Реализуй четыре конструктора: `notAsked()`, `loading()`, `failure(error)`, `success(data)`.
2. Реализуй `mapRD<E, A, B>(rd, f)`: применяет `f` только к `Success`, все остальные состояния возвращает без изменений (каст типа через `as`).
3. Реализуй `getOrElse<E, A>(rd, fallback)`: возвращает `rd.data` если `Success`, иначе `fallback`.
4. Реализуй компонент `Match<E, A>`: принимает `data` и четыре обработчика. Внутри — `switch` по `data.tag` с вызовом соответствующего обработчика. Все 4 кейса обязательны.
5. Подключи компонент к кнопкам-сценариям: "Загрузить" переходит в Loading → через 1.5s в Success, "Симулировать ошибку" → Loading → Failure, "Не загружено" → NotAsked.

## Чеклист

- [ ] Конструкторы `failure(e)` и `success(a)` сохраняют данные в поле `error`/`data`
- [ ] `mapRD` применяет функцию только к `Success`, Loading и Failure проходят без изменений
- [ ] `getOrElse` возвращает `fallback` для NotAsked, Loading, Failure
- [ ] `Match` обрабатывает все 4 состояния
- [ ] Кнопка "Загрузить": сначала показывает спиннер, через 1.5s — список пользователей
- [ ] Кнопка "Симулировать ошибку": сначала спиннер, через 1.5s — сообщение об ошибке
- [ ] Кнопка "Не загружено": сразу показывает плашку "Нажмите загрузить"
- [ ] Бейдж с текущим `tag` обновляется при смене состояния

## Как проверить себя

1. При старте — Match отображает "Нажмите загрузить" (NotAsked).
2. "Загрузить" → появляется спиннер → через 1.5s список из 3 пользователей.
3. `mapRD(rdState, users => users.length)` → при Success возвращает `Success(3)`, при Loading — `Loading`.
4. `getOrElse(mapped, 0)` → при Success возвращает `3`, при остальных — `0`.
5. Счётчик пользователей (бейдж) появляется только в состоянии Success.
6. "Симулировать ошибку" → спиннер → красная плашка с текстом ошибки.
