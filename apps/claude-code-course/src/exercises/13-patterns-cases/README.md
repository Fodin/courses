# Уровень 13: Архитектурные паттерны и кейсы

## Кейс 1: Миграция legacy-кодбейза

Представьте: вам достался проект на Express.js с 200 файлами, нулевой документацией и тестами "потом напишем". Задача -- мигрировать на NestJS. Без агента это месяцы ручной работы. С агентом -- стратегия:

```mermaid
flowchart LR
    A["Разведка<br/>plan mode"] --> B["CLAUDE.md<br/>legacy → target"]
    B --> C["Skills для<br/>трансформаций"]
    C --> D["Пошаговая миграция<br/>+ тесты"]
```

**Шаг 1: Разведка.** Запускаем агент в plan mode -- он анализирует структуру, зависимости, паттерны. Не меняет ни строки.

**Шаг 2: CLAUDE.md.** Описываем текущую и целевую архитектуру. Агент знает, откуда и куда мигрируем.

**Шаг 3: Skills.** Создаём навыки для типовых трансформаций: `/extract-service`, `/convert-route-to-controller`, `/add-dto-validation`.

**Шаг 4: Тесты как safety net.** Перед каждой трансформацией -- тест, после -- проверка. Агент не переходит к следующему шагу, пока тесты не зелёные.

## Кейс 2: Greenfield-проект с нуля

Новый проект -- шанс заложить agent-friendly архитектуру с первого дня:

```bash
# 1. Начинаем с CLAUDE.md
claude "Создай CLAUDE.md для нового проекта:
       NestJS + React + PostgreSQL + Prisma"

# 2. Генерация структуры
claude "/init" # Создаёт скелет проекта

# 3. Итеративная разработка
claude "Добавь модуль авторизации с JWT"
# Агент знает стек и конвенции из CLAUDE.md
```

Agent-friendly архитектура: чёткое разделение модулей, понятные имена, тесты с первого коммита, CLAUDE.md актуален на каждом этапе.

## Кейс 3: Мультирепо микросервисы

Проблема: агент видит только один репозиторий, а ваша система -- 12 микросервисов в разных репо.

Решения:
- **MCP-сервер** для кросс-репо поиска кода и документации
- **Общие .claude/rules/** -- одинаковые стандарты во всех репо
- **CLAUDE.md** с описанием всех сервисов и их взаимодействия
- **Субагенты** для координации изменений в разных репо

```markdown
<!-- CLAUDE.md в каждом репо -->
## Микросервисная архитектура
- user-service (порт 3001) -- авторизация и профили
- order-service (порт 3002) -- заказы, зависит от user-service
- payment-service (порт 3003) -- платежи, зависит от order-service
- notification-service (порт 3004) -- уведомления, подписан на события
```

## Кейс 4: CI/CD пайплайн с агентами

Агент в CI/CD запускается через Agent SDK с флагом `-p` (non-interactive):

```bash
# В CI/CD пайплайне
claude -p "Проверь PR #${PR_NUMBER}: code review по стандартам проекта"
claude -p "Сгенерируй changelog на основе коммитов с последнего релиза"
```

Ключевые применения: автоматический code review, генерация changelog, проверка соответствия стандартам, обновление документации.

⚠️ Обязательно: strict sandbox, минимальные permissions, мониторинг стоимости.

## Антипаттерны

| Антипаттерн | Проблема | Решение |
|-------------|----------|---------|
| "Агент сделает всё сам" | Нет контроля, ошибки накапливаются | Plan → review → execute |
| Слишком длинный CLAUDE.md | Тратит контекст, снижает точность | Rules + skills + короткий CLAUDE.md |
| Нет тестов | Агент ломает и не замечает | Тесты до начала работы агента |
| Игнорирование контекстного бюджета | Агент "забывает" начало разговора | Compact, короткие сессии, субагенты |

## Чеклист: готов ли проект

- [ ] CLAUDE.md описывает стек, архитектуру и конвенции
- [ ] `.claude/settings.json` с allow/deny настроен
- [ ] Есть тесты (хотя бы smoke)
- [ ] Skills для повторяющихся задач
- [ ] Sandbox включён (filesystem + network)
- [ ] `.gitignore` включает `.claude/settings.local.json`

## ⚠️ Частые ошибки новичков

### 🐛 1. Миграция без тестов

```bash
# ❌ "Агент, перепиши всё на NestJS"
# Через 2 часа: 50 файлов изменены, ничего не работает, непонятно где сломалось
```

```bash
# ✅ Пошагово с тестами
# 1. Написать тесты для текущего поведения
# 2. Мигрировать один модуль
# 3. Убедиться, что тесты зелёные
# 4. Повторить
```

### 🐛 2. CLAUDE.md не обновляется

Проект эволюционирует, а CLAUDE.md описывает архитектуру полугодовой давности. Агент генерирует код по устаревшим паттернам.

### 🐛 3. Агенту дают слишком большую задачу

"Перепиши весь проект" -- контекст переполняется, агент теряет нить. Разбивайте на маленькие задачи, используйте субагентов.
