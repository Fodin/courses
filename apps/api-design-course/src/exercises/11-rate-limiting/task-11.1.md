# Задание 11.1: Симулятор Token Bucket

## Цель

Реализовать интерактивный симулятор алгоритма Token Bucket, который наглядно показывает, как работает rate limiting: наполнение ведра токенами, расход при запросах и HTTP-заголовки ответа.

## Требования

1. Отображать ведро с визуальным индикатором уровня токенов (высота заполнения пропорциональна количеству токенов)
2. Цвет ведра меняется в зависимости от заполненности: зелёный (>50%), жёлтый (20-50%), красный (<20%)
3. Кнопка «Отправить запрос» — активна при наличии токенов, деактивирована при пустом ведре
4. Токены автоматически пополняются с заданной скоростью (используй `setInterval`)
5. Настраиваемые параметры через слайдеры: `capacity` (3–20) и `refillRate` (1–5 токенов/сек)
6. При успешном запросе показать заголовки: `X-RateLimit-Limit`, `X-RateLimit-Remaining`, `X-RateLimit-Reset`
7. При 429 дополнительно показать заголовок `Retry-After`
8. Вести лог последних 10 запросов с временем, статусом (200/429) и remaining

## Чеклист

- [ ] Ведро визуализировано (высота пропорциональна tokens/capacity)
- [ ] Цвет меняется: зелёный / жёлтый / красный
- [ ] Токены пополняются автоматически (useEffect + setInterval)
- [ ] Слайдер capacity обновляет состояние и ведро
- [ ] Слайдер refillRate влияет на скорость пополнения
- [ ] Заголовки X-RateLimit-* отображаются после каждого запроса
- [ ] При 429 виден Retry-After
- [ ] Лог запросов (последние 10) с цветовой индикацией

## Как проверить себя

1. Установи capacity=5, refillRate=1. Нажми кнопку 5 раз подряд — всё 200 OK.
2. 6-й запрос — 429, виден Retry-After.
3. Через секунду — снова 1 токен, запрос проходит.
4. Увеличь refillRate=5 — ведро пополняется намного быстрее.

## Подсказки

- Используй `useRef` для хранения `tokensRef` — это позволяет читать актуальное значение внутри `setInterval` без проблем с замыканием
- `lastRefillRef` хранит время последнего пополнения для точного расчёта
- Формула времени до следующего токена: `1 / refillRate - elapsed`
