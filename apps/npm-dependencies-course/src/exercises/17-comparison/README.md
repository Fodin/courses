# Уровень 17: npm vs pnpm vs Yarn — сравнение

## Три менеджера — три философии

- **npm** — стандарт «из коробки», идёт с Node.js, максимальная совместимость
- **pnpm** — strict-first: экономия диска, строгая изоляция через hard links
- **Yarn** — два поколения: Classic (скорость в 2016) и Berry (zero-installs, PnP)

## Скорость установки

| Менеджер       | Первая установка | Повторная (cache)         |
| -------------- | ---------------- | ------------------------- |
| npm            | Базовая          | Быстрее (cache)           |
| pnpm           | Быстрее npm      | Очень быстро (hard links) |
| Yarn Classic   | Быстрее npm      | Быстрее (offline mirror)  |
| Yarn Berry PnP | Быстро           | Очень быстро (zip)        |

## Использование диска

| Менеджер       | Подход                             | Эффект                            |
| -------------- | ---------------------------------- | --------------------------------- |
| npm            | Копии файлов в каждый node_modules | Дублирование: N проектов × размер |
| pnpm           | Hard links из глобального store    | Один экземпляр для всех проектов  |
| Yarn Classic   | Копии (как npm) + offline mirror   | Дублирование + кэш                |
| Yarn Berry PnP | Zip-архивы в .yarn/cache/          | Нет дублирования, минимум файлов  |

## Фантомные зависимости

| Менеджер       | Допускает phantom deps?              |
| -------------- | ------------------------------------ |
| npm            | Да (плоский node_modules)            |
| Yarn Classic   | Да (плоский node_modules)            |
| Yarn Berry PnP | Нет (строгая карта резолюции)        |
| pnpm           | Нет (симлинки только на прямые deps) |

## Файлы блокировки

| Менеджер | Lockfile          |
| -------- | ----------------- |
| npm      | package-lock.json |
| pnpm     | pnpm-lock.yaml    |
| Yarn     | yarn.lock         |

## Форсирование версий транзитивных зависимостей

| Менеджер | Поле             | Пример                                                  |
| -------- | ---------------- | ------------------------------------------------------- |
| npm      | `overrides`      | `"overrides": { "lodash": "4.17.21" }`                  |
| pnpm     | `pnpm.overrides` | `"pnpm": { "overrides": { "express>debug": "4.3.4" } }` |
| Yarn     | `resolutions`    | `"resolutions": { "**/lodash": "4.17.21" }`             |

## Поддержка монорепо / workspaces

Все три поддерживают workspaces. pnpm считается лучшим для монорепо за счёт строгой изоляции и экономии диска при большом числе пакетов.

## Рекомендации по выбору

- **npm** → максимальная совместимость, легаси-проекты, минимум настройки
- **pnpm** → монорепо, много проектов на одной машине, экономия диска, строгость
- **Yarn Berry** → zero-installs в CI, полный контроль над граф зависимостей, корпоративные проекты

## ⚠️ Частые ошибки

❌ Смешивать lockfile разных менеджеров в одном репозитории.

✅ Договоритесь о едином менеджере и зафиксируйте его в `packageManager` в package.json.
