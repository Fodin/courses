# Задание 9.3: Паттерн интерпретатора (Free-like)

## Цель

Реализовать DSL для key-value хранилища в виде типа данных (AST) и два независимых интерпретатора для одной и той же программы. Это демонстрирует принцип: описание программы отделено от её выполнения.

## Требования

1. Объявите тип операции:
   ```ts
   type StoreOp<A> =
     | { tag: 'Get';    key: string; next: (value: string | null) => A }
     | { tag: 'Set';    key: string; value: string; next: A }
     | { tag: 'Delete'; key: string; next: A }
     | { tag: 'Return'; value: A }
   ```

2. Реализуйте интерпретатор `runInMemory`:
   - Принимает `StoreOp<A>` и начальный `Map<string, string>`
   - Рекурсивно выполняет операции на копии Map
   - Возвращает `{ result: A; store: Map<string, string> }`
   - `Get` читает из Map, передаёт значение в `next`
   - `Set` добавляет в Map, продолжает с `next`
   - `Delete` удаляет из Map, продолжает с `next`

3. Реализуйте интерпретатор `runAsLog`:
   - Принимает `StoreOp<A>` и массив строк
   - НЕ выполняет операции реально — только собирает лог
   - Возвращает `string[]` с записями вида `"GET key"`, `"SET key = value"`, `"DELETE key"`
   - Для `Get` передаёт `null` в `next` (значение неизвестно без выполнения)

4. Создайте интерфейс:
   - Кнопки добавления шагов ("Get", "Set", "Delete") с полями ввода ключа/значения
   - Список построенных шагов с возможностью удаления
   - Переключатель между интерпретаторами
   - **In-Memory**: таблица с итоговым состоянием Map + финальный результат
   - **Log**: список операций как текст
   - Предустановленный пример программы для демонстрации

## Checklist

- [ ] Тип `StoreOp<A>` объявлен корректно с четырьмя вариантами
- [ ] `runInMemory` рекурсивен и создаёт копию Map на каждом шаге (иммутабельно)
- [ ] `runInMemory` корректно обрабатывает `Get` (значение может отсутствовать → `null`)
- [ ] `runAsLog` не мутирует никакого хранилища
- [ ] `runAsLog` для `Get` передаёт `null` в `next` (не пытается читать реальное значение)
- [ ] Одна и та же программа выдаёт разные результаты в разных интерпретаторах
- [ ] Список шагов обновляет программу динамически
- [ ] Пустая программа не вызывает ошибок

## Как проверить себя

Программа: `SET user = Alice` → `SET role = admin` → `GET user` → `DELETE role`:

**In-Memory:**
- Хранилище: `{ user: "Alice" }` (role удалён)
- Финальный результат: `done`

**Log:**
```
1. SET user = Alice
2. SET role = admin
3. GET user
4. DELETE role
```

Добавьте шаг `GET role` после `DELETE role`:
- In-Memory: `GET role` вернёт `null` (уже удалён)
- Log: просто добавится строка `GET role`

Ключевой вопрос: почему In-Memory и Log дают разные "ответы" на `GET` после `DELETE`? Потому что Log не знает состояния — он только записывает намерения.
