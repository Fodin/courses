# Rate Limiting и Throttling

## Зачем нужен rate limiting

Rate limiting ограничивает число запросов, которые клиент может сделать за единицу времени. Три главных причины:

- **Защита от злоупотреблений** — DDoS, брутфорс, скрейпинг
- **Fairness** — один клиент не монополизирует ресурс
- **Экономика** — бесплатный тариф не должен потреблять как платный

## Основные алгоритмы

### Token Bucket (самый популярный)

Ведро с токенами. Каждый запрос расходует токен. Токены пополняются с фиксированной скоростью. Допускает кратковременные всплески (burst) до размера ведра.

```
capacity = 10, refillRate = 2/сек
10 запросов подряд → OK (израсходовали всё ведро)
11-й запрос → 429 (ведро пусто)
через 0.5с → +1 токен → можно снова
```

### Sliding Window Counter

Делит время на окна, считает запросы с перекрытием. Точнее fixed window, нет спайка на границе периода.

## HTTP-заголовки

```http
X-RateLimit-Limit: 1000        # максимум запросов в окне
X-RateLimit-Remaining: 946     # осталось в текущем окне
X-RateLimit-Reset: 1735689600  # Unix timestamp сброса

# При 429:
HTTP/1.1 429 Too Many Requests
Retry-After: 30                # подождите 30 секунд
```

## Стратегия клиента

При получении 429 клиент должен использовать **exponential backoff с jitter**:

```
delay = min(maxDelay, baseDelay × 2^attempt) × random(0.5, 1.0)
```

Jitter предотвращает thundering herd — ситуацию, когда все клиенты атакуют одновременно после ожидания.
